# Q16 Topic Exchange 通配符规则

Topic Exchange 的 Routing Key 必须是用点号 `.` 分隔的字符串（如 `order.payment.success`），Binding Key 支持两个通配符：`*` 匹配**恰好一个单词**（不能跨点），`#` 匹配**零个或多个单词**（可以跨点）。特殊情况下，Binding Key 为 `#` 时等价于 Fanout（全收），不含通配符时等价于 Direct。这是 RabbitMQ 实际项目中最常用的 Exchange 类型。

上图分三个区域展示 Topic Exchange 的通配符规则：蓝色区域说明 `*` 只匹配恰好一个单词、不能跨点；橙色区域说明 `#` 匹配零到多个单词、可以跨点；底部绿色区域揭示两个特殊等价关系——`#` 退化为 Fanout、无通配符退化为 Direct。下面用代码实现这套通配符路由。

## 订单事件通配符路由实现

### Layer 1 — 配置层：声明不同通配符的 Binding

```java
@Configuration
public class OrderTopicConfig {
    public static final String EXCHANGE = "exchange.order.topic";

    @Bean
    public TopicExchange orderTopicExchange() {
        return new TopicExchange(EXCHANGE, true, false);
    }

    // Queue A: 收所有 order 相关消息（# 匹配零或多段）
    @Bean
    public Queue allOrderQueue() {
        return new Queue("queue.order.all", true);
    }

    @Bean
    public Binding allOrderBinding(Queue allOrderQueue, TopicExchange ex) {
        // order.# → 匹配 order / order.payment / order.payment.success 全部
        return BindingBuilder.bind(allOrderQueue).to(ex).with("order.#");
    }

    // Queue B: 只收 order 下的支付成功事件（* 匹配恰好一段）
    @Bean
    public Queue paymentSuccessQueue() {
        return new Queue("queue.order.payment.success", true);
    }

    @Bean
    public Binding paymentSuccessBinding(Queue paymentSuccessQueue, TopicExchange ex) {
        // order.*.success → 匹配 order.payment.success、order.refund.success
        // 但不匹配 order.success（少了中间段）
        return BindingBuilder.bind(paymentSuccessQueue).to(ex).with("order.*.success");
    }

    // Queue C: 精确匹配（无通配符 → 等价 Direct）
    @Bean
    public Queue exactPaymentQueue() {
        return new Queue("queue.order.payment.exact", true);
    }

    @Bean
    public Binding exactPaymentBinding(Queue exactPaymentQueue, TopicExchange ex) {
        // order.payment → 只匹配 routing key 恰好为 "order.payment" 的消息
        // 不匹配 order.payment.success（多了一段）
        return BindingBuilder.bind(exactPaymentQueue).to(ex).with("order.payment");
    }
}
```

关键点：同一个 Exchange 上可以挂多种 binding——`order.#` 用 `#` 全收、`order.*.success` 用 `*` 匹配中间段、`order.payment` 不含通配符做精确匹配。一条消息可以同时命中多个队列。

### Layer 2 — 生产者：用点号拼接多维度 routing key

```java
@Service
public class OrderTopicProducer {
    @Autowired
    private RabbitTemplate rabbitTemplate;

    public void sendPaymentSuccess(String orderId) {
        // routing key = "order.payment.success"
        // → 命中 queue.order.all（# 吃掉 payment.success）
        // → 命中 queue.order.payment.success（* 匹配 payment）
        // → 不命中 queue.order.payment.exact（精确匹配需要恰好 "order.payment"）
        rabbitTemplate.convertAndSend(
                OrderTopicConfig.EXCHANGE,
                "order.payment.success",          // ← 三段式 routing key
                new OrderEvent(orderId, "PAID"));
    }

    public void sendRefundSuccess(String orderId) {
        // routing key = "order.refund.success"
        // → 命中 queue.order.all（# 吃掉 refund.success）
        // → 命中 queue.order.payment.success（* 匹配 refund）← 注意！
        // → 不命中 queue.order.payment.exact
        rabbitTemplate.convertAndSend(
                OrderTopicConfig.EXCHANGE,
                "order.refund.success",           // ← * 不关心具体值，refund 也能匹配
                new OrderEvent(orderId, "REFUNDED"));
    }

    public void sendPlainOrder(String orderId) {
        // routing key = "order"（只有一段）
        // → 命中 queue.order.all（# 匹配零段）
        // → 不命中 queue.order.payment.success（* 需要三段，只有一段不匹配）
        // → 不命中 queue.order.payment.exact（需要恰好 "order.payment"）
        rabbitTemplate.convertAndSend(
                OrderTopicConfig.EXCHANGE,
                "order",                          // ← 只有前缀，# 匹配空
                new OrderEvent(orderId, "CREATED"));
    }
}
```

关键点：`order.refund.success` 也会命中 `order.*.success`，因为 `*` 匹配的是「任意一个单词」，不限于 `payment`。如果想只收支付成功的消息，应该用精确 routing key 或在消费者里做二次过滤。

### Layer 3 — 消费者：按队列维度独立处理

```java
@Component
public class OrderTopicConsumer {

    // 全量订单事件 → 审计日志
    @RabbitListener(queues = "queue.order.all")
    public void handleAll(OrderEvent event) {
        auditLog.record(event);  // 所有 order.* 消息都会进来
    }

    // 支付/退款成功 → 触发后续流程
    @RabbitListener(queues = "queue.order.payment.success")
    public void handlePaymentSuccess(OrderEvent event) {
        if ("PAID".equals(event.getStatus())) {
            inventoryService.deduct(event.getOrderId());
        } else if ("REFUNDED".equals(event.getStatus())) {
            inventoryService.restore(event.getOrderId());
        }
        // 注意：* 不区分 payment 和 refund，需要消费者自行判断
    }

    // 精确匹配 order.payment → 发优惠券
    @RabbitListener(queues = "queue.order.payment.exact")
    public void handleExactPayment(OrderEvent event) {
        couponService.sendCoupon(event.getOrderId());
    }
}
```

关键点：`queue.order.payment.success` 的名字虽然含 `payment`，但实际 `*` 也会匹配 `refund`，所以消费者内部需要根据 `event.getStatus()` 做二次判断。这正是 Topic Exchange 灵活性的代价——通配符匹配是结构性的，不关心语义。

## `*` vs `#` 通配符对比

| 维度 | `*`（星号） | `#`（井号） |
|---|---|---|
| 匹配范围 | 恰好一个单词 | 零个或多个单词 |
| 能否跨点 | 不能（只匹配两个点之间的内容） | 能（吃掉多个点分隔的段） |
| 能否匹配空 | 不能（必须有对应段） | 能（零段也匹配） |
| 贪婪程度 | 精确（一对一） | 贪婪（一对多） |
| `order.*.success` 匹配 `order.payment.success` | ✓ | — |
| `order.*.success` 匹配 `order.success` | ✗（少一段） | — |
| `order.#` 匹配 `order` | ✗（# 不在这里） | ✓（零段） |
| `order.#` 匹配 `order.a.b.c` | ✗ | ✓（多段） |
| 退化等价 | 无特殊退化 | `#` 单独使用 = Fanout |
| 典型用途 | 匹配固定段数的 routing key | 匹配前缀 + 任意后缀 |

> 记忆技巧：`*` 像填空题的一个空格（必须填一个词），`#` 像通配符 `.*`（可以什么都不填，也可以填很多）。

## 一句话总结

**一句话总结：`*` 是「必须填一个词的填空题」，`#` 是「随便你填几个词的开放题」——Topic Exchange 用这两个通配符在精确路由（Direct）和全量广播（Fanout）之间自由滑动，所以它是实际项目里用得最多的 Exchange 类型。**
