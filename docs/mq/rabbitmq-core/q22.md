# Q22 Virtual Host 作用

Virtual Host（vhost）是 RabbitMQ 的**逻辑隔离单元**，每个 vhost 拥有独立的 Exchange、Queue、Binding 和权限配置。它的核心作用是资源隔离（不同业务/租户互不影响）、权限控制（每个 vhost 独立用户权限）、环境隔离（dev/test/prod 共用同一集群）。vhost 是轻量级的逻辑概念，不像虚拟机有资源开销，可以创建很多个。

上图展示了同一个 RabbitMQ Broker 内的三个 vhost（`/order`、`/log`、`/dev`），它们各自拥有独立的 Exchange、Queue、Binding 和用户权限，通过虚线分隔实现完全隔离。底部三个色块总结了 vhost 的三大核心作用，黑条列出了多 vhost 的典型场景。下面用代码实现多 vhost 的创建和使用。

## 多 vhost 的配置与使用

### Layer 1 — 创建 vhost 并配置权限（运维层）

```bash
# 1. 创建 vhost
rabbitmqctl add_vhost /order
rabbitmqctl add_vhost /log
rabbitmqctl add_vhost /dev

# 2. 创建用户
rabbitmqctl add_user order-user order-pass
rabbitmqctl add_user log-user log-pass
rabbitmqctl add_user dev-user dev-pass

# 3. 为每个 vhost 设置独立权限
# 格式：set_permissions [-p vhost] user configure write read
rabbitmqctl set_permissions -p /order order-user ".*" ".*" ".*"
#                        ↑ 只有 order-user 能访问 /order

rabbitmqctl set_permissions -p /log log-user ".*" ".*" ".*"
#                        ↑ 只有 log-user 能访问 /log

rabbitmqctl set_permissions -p /dev dev-user ".*" ".*" ".*"
#                        ↑ 只有 dev-user 能访问 /dev

# 4. order-user 尝试访问 /log 会被拒绝（权限隔离）
```

关键点：`set_permissions -p /vhost user` 为指定 vhost 设置用户权限。order-user 只在 `/order` 有权限，访问 `/log` 会被 RabbitMQ 拒绝。这就是 vhost 级别的权限控制。

### Layer 2 — Spring AMQP 连接指定 vhost

```java
@Configuration
public class MultiVhostConfig {

    // 订单服务连接 /order vhost
    @Bean("orderConnectionFactory")
    public ConnectionFactory orderConnectionFactory() {
        CachingConnectionFactory factory = new CachingConnectionFactory();
        factory.setHost("rabbitmq.example.com");
        factory.setPort(5672);
        factory.setVirtualHost("/order");          // ← 指定 vhost
        factory.setUsername("order-user");          // ← 对应 vhost 的用户
        factory.setPassword("order-pass");
        return factory;
    }

    // 日志服务连接 /log vhost
    @Bean("logConnectionFactory")
    public ConnectionFactory logConnectionFactory() {
        CachingConnectionFactory factory = new CachingConnectionFactory();
        factory.setHost("rabbitmq.example.com");
        factory.setPort(5672);
        factory.setVirtualHost("/log");             // ← 不同的 vhost
        factory.setUsername("log-user");             // ← 不同的用户
        factory.setPassword("log-pass");
        return factory;
    }

    // 订单服务的 RabbitTemplate（用 /order vhost）
    @Bean("orderRabbitTemplate")
    public RabbitTemplate orderRabbitTemplate(
            @Qualifier("orderConnectionFactory") ConnectionFactory cf) {
        return new RabbitTemplate(cf);
    }

    // 日志服务的 RabbitTemplate（用 /log vhost）
    @Bean("logRabbitTemplate")
    public RabbitTemplate logRabbitTemplate(
            @Qualifier("logConnectionFactory") ConnectionFactory cf) {
        return new RabbitTemplate(cf);
    }
}
```

关键点：通过 `setVirtualHost("/order")` 指定连接的 vhost。不同服务用不同的 ConnectionFactory 连不同 vhost，各自有独立的用户和权限。两个服务连同一个 Broker 但互相完全隔离。

### Layer 3 — 使用不同 vhost 的服务

```java
@Service
public class OrderService {
    @Autowired
    @Qualifier("orderRabbitTemplate")
    private RabbitTemplate orderRabbitTemplate;

    public void createOrder(String orderId) {
        // 发到 /order vhost 的 exchange.order
        // /log vhost 的用户看不到这个 Exchange
        orderRabbitTemplate.convertAndSend(
                "exchange.order",
                "order.created",
                new OrderEvent(orderId));
    }
}

@Service
public class LogService {
    @Autowired
    @Qualifier("logRabbitTemplate")
    private RabbitTemplate logRabbitTemplate;

    public void sendLog(String level, String msg) {
        // 发到 /log vhost 的 exchange.log
        // /order vhost 的用户看不到这个 Exchange
        logRabbitTemplate.convertAndSend(
                "exchange.log",
                "",
                new LogEvent(level, msg));
    }
}
```

关键点：两个 Service 注入不同的 RabbitTemplate，分别连不同的 vhost。即使两个 vhost 里有同名的 Exchange 或 Queue，也不会冲突——vhost 是命名空间级别的隔离。

## vhost 对比其他隔离方案

| 维度 | vhost 隔离 | 多 Broker 实例 | 命名前缀约定 |
|---|---|---|---|
| 资源开销 | 极低（逻辑隔离） | 高（每个实例独立进程） | 零 |
| 隔离强度 | Exchange/Queue/权限 完全隔离 | 物理隔离（最强） | 弱（靠命名约定） |
| 权限控制 | 原生支持（每 vhost 独立用户） | 实例级控制 | 无 |
| 运维成本 | 低（一套 Broker 管理） | 高（多套 Broker 运维） | 低 |
| 适合场景 | 多租户/多业务/多环境 | 安全要求极高的场景 | 简单项目 |
| Queue 重名问题 | 不存在（不同 vhost 独立） | 不存在 | 靠前缀避免 |

> 面试要点：vhost 是轻量级的逻辑隔离，不是虚拟机。它的本质是「命名空间 + 权限边界」，让一个 Broker 实例服务多个业务/环境而互不干扰。

## 一句话总结

**一句话总结：vhost 是 RabbitMQ 的「逻辑楼层」——同一栋楼（Broker）里不同楼层（vhost）各有独立的信箱（Queue）、路由器（Exchange）和门禁（权限），租户之间互不可见，但共享同一栋楼的基础设施。**
