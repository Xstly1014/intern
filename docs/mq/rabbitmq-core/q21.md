# Q21 Connection vs Channel

Connection 是客户端和 Broker 之间的 **TCP 长连接**，Channel 是 Connection 内部的**虚拟连接**（轻量级通道），多个 Channel 复用同一条 TCP 连接。之所以要有 Channel，是因为频繁建立/断开 TCP 连接开销大（三次握手 + AMQP 握手），如果每个线程都建独立 TCP 连接 Broker 会扛不住。Channel 是多路复用的，创建/销毁成本远低于 TCP 连接，但注意 **Channel 不是线程安全的**，一个 Channel 不能被多线程共享。

## Connection 与 Channel 的代码实现

### Layer 1 — Before：手动管理 TCP 连接（错误示例）

```java
// ✗ 错误方式：每个线程都建独立 TCP 连接
public class BadProducer implements Runnable {
    private final String message;

    public BadProducer(String message) {
        this.message = message;
    }

    @Override
    public void run() {
        ConnectionFactory factory = new ConnectionFactory();
        factory.setHost("localhost");
        try {
            // 每个线程都建 TCP 连接 → 三次握手 + AMQP 握手
            Connection connection = factory.newConnection();  // ← 开销大！
            Channel channel = connection.createChannel();     // ← 创建 Channel 很轻量

            channel.basicPublish("exchange.order", "order.created", null,
                    message.getBytes());

            channel.close();
            connection.close();  // ← 每次都关 TCP 连接，下次又要重新握手
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
// 100 个线程并发 → 100 条 TCP 连接 → Broker 连接数爆炸
```

关键点：每调用一次 `factory.newConnection()` 就建立一条新的 TCP 连接，包含三次握手 + AMQP 协议握手，耗时约 3ms。100 个线程并发就是 100 条 TCP 连接，Broker 的文件描述符很快耗尽。

### Layer 2 — After：Connection 复用 + Channel 多路复用

```java
// ✓ 正确方式：一个 Connection + 多个 Channel
@Configuration
public class RabbitConnectionConfig {

    @Bean
    public ConnectionFactory connectionFactory() {
        CachingConnectionFactory factory = new CachingConnectionFactory();
        factory.setHost("localhost");
        factory.setPort(5672);
        factory.setUsername("guest");
        factory.setPassword("guest");
        factory.setVirtualHost("/");
        // CachingConnectionFactory 会缓存 Connection，默认创建一个 Connection
        // Channel 用完关闭时只是归还到缓存，不是真正关闭
        return factory;
    }

    @Bean
    public RabbitTemplate rabbitTemplate(ConnectionFactory connectionFactory) {
        RabbitTemplate template = new RabbitTemplate(connectionFactory);
        // RabbitTemplate 内部自动管理 Channel：
        // - 每次调用 convertAndSend 时从 Connection 获取一个 Channel
        // - 发送完毕后自动关闭 Channel（归还到缓存池）
        // - 开发者不需要手动管理 Channel 生命周期
        return template;
    }
}
```

关键点：Spring AMQP 的 `CachingConnectionFactory` 自动管理 Connection 缓存和 Channel 池。开发者只需用 `RabbitTemplate`，Channel 的获取和归还全自动。

### Layer 3 — 手动 Channel 管理（需要精细控制时）

```java
@Service
public class ManualChannelService {
    @Autowired
    private ConnectionFactory connectionFactory;

    public void publishBatch(List<String> messages) {
        // 从缓存池获取 Connection（不是新建 TCP）
        Connection connection = connectionFactory.createConnection();
        Channel channel = null;
        try {
            // 创建 Channel 是轻量级操作（无网络握手，只是虚拟通道 ID 分配）
            channel = connection.createChannel();

            // 批量发送：同一个 Channel 复用，减少 Channel 创建次数
            for (String msg : messages) {
                channel.basicPublish(
                        "exchange.order",
                        "order.created",
                        null,
                        msg.getBytes());
            }

            // Channel 不是线程安全的！
            // ✗ 不能将 channel 存到成员变量让多线程共享
            // ✓ 每个方法调用内部创建和关闭 Channel

        } catch (Exception e) {
            throw new RuntimeException("批量发送失败", e);
        } finally {
            if (channel != null && channel.isOpen()) {
                try {
                    channel.close();  // 归还到 CachingConnectionFactory 的缓存池
                } catch (Exception ignored) {}
            }
        }
    }
}
```

关键点：手动管理 Channel 时，务必在 `finally` 块中关闭。`CachingConnectionFactory` 下 `channel.close()` 不是真正关闭，而是归还到缓存池供下次复用。Channel 绝不能跨线程共享。

## Connection vs Channel 对比

| 维度 | Connection | Channel |
|---|---|---|
| 本质 | TCP 长连接 | 虚拟连接（逻辑通道） |
| 创建成本 | 高（三次握手 + AMQP 握手） | 极低（分配通道 ID） |
| 数量关系 | 1 个 Connection | N 个 Channel（默认无上限） |
| 线程安全 | 是（可跨线程共享） | **否**（不能跨线程共享） |
| 网络开销 | 每条 Connection 占一个 TCP 连接 | 多个 Channel 复用一条 TCP |
| 生命周期 | 应用级别（启动到关闭） | 请求级别（用完归还） |
| Broker 压力 | 连接数多了 Broker 扛不住 | Channel 数量对 Broker 影响小 |
| Spring AMQP | CachingConnectionFactory 管理 | RabbitTemplate 自动管理 |
| 最佳实践 | 1 个应用 1~2 个 Connection | 每线程 1 个 Channel |

> 面试要点：被问到「为什么要有 Channel」时，核心回答是「TCP 连接建立成本高，Channel 是多路复用的虚拟通道，让多个线程复用一条 TCP 连接，避免 Broker 连接数爆炸」。

## 一句话总结

**一句话总结：Connection 是昂贵的 TCP 高速公路、Channel 是廉价的虚拟车道——N 个 Channel 复用 1 条 TCP 连接实现多路复用，但 Channel 非线程安全，每个线程必须独占自己的车道。**
