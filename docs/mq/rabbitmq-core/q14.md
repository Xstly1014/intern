RabbitMQ 的四种 Exchange 类型按路由规则划分：Direct 要求 Routing Key 与 Binding Key 完全相等、Topic 用通配符 `*` / `#` 做模式匹配、Fanout 忽略 Routing Key 直接广播、Headers 按 headers 属性匹配（支持 all / any）。实际项目中 Topic Exchange 用得最多，因为它能同时兼顾精确路由与多维度模式匹配。

上自下依次展示了四种 Exchange 的路由判定差异：绿色 / 橙色实线箭头连接的队列能收到消息，红色虚线表示匹配失败被丢弃。可以看到 Topic 一条消息可同时命中多个队列，而 Fanout 则是无差别全覆盖。下面用 Spring AMQP 代码分别落地这四种配置与生产逻辑。

## 四种 Exchange 的 Spring AMQP 实现

> 以下代码基于 Spring AMQP，省略 `import`，聚焦每种类型的配置与生产者差异。

### 1. Direct Exchange — Routing Key 完全相等

配置层：声明 Exchange、Queue，并用 `with("order.error")` 指定精确的 binding key。

```java
@Configuration
public class DirectRabbitConfig {
    public static final String EXCHANGE = "exchange.order.direct";
    public static final String QUEUE_ERROR = "queue.order.error";

    @Bean
    public DirectExchange directExchange() {
        return new DirectExchange(EXCHANGE, true, false);
    }

    @Bean
    public Queue errorQueue() {
        return new Queue(QUEUE_ERROR, true);
    }

    // binding key 必须与消息 routing key 完全一致
    @Bean
    public Binding errorBinding(Queue errorQueue, DirectExchange directExchange) {
        return BindingBuilder.bind(errorQueue)
                .to(directExchange)
                .with("order.error");
    }
}
```

生产者：精确指定 routing key，差一个字符都不会路由。

```java
@Service
public class OrderDirectProducer {
    @Autowired
    private RabbitTemplate rabbitTemplate;

    public void sendError(String orderNo) {
        rabbitTemplate.convertAndSend(
                DirectRabbitConfig.EXCHANGE,
                "order.error",                 // 必须与 binding key 完全相等
                new OrderEvent(orderNo, "ERROR"));
    }
}
```

关键点：routing key 是字符串严格相等比较，没有通配符能力，适合「错误订单进错误队列」这种点对点精确分发。

### 2. Topic Exchange — 通配符 `*` / `#` 模式匹配（最常用）

配置层：`#` 匹配零或多个单词，`*` 匹配恰好一个单词。

```java
@Configuration
public class TopicRabbitConfig {
    public static final String EXCHANGE = "exchange.log.topic";

    @Bean
    public TopicExchange topicExchange() {
        return new TopicExchange(EXCHANGE, true, false);
    }

    @Bean
    public Queue allLogQueue() {
        return new Queue("queue.log.all", true);
    }

    @Bean
    public Queue createLogQueue() {
        return new Queue("queue.log.create", true);
    }

    // "#" 匹配零或多个单词：所有 log.* 日志都进
    @Bean
    public Binding allBinding(Queue allLogQueue, TopicExchange topicExchange) {
        return BindingBuilder.bind(allLogQueue).to(topicExchange).with("log.#");
    }

    // "*" 匹配一个单词：仅 log.<module>.<level> 三段式
    @Bean
    public Binding createBinding(Queue createLogQueue, TopicExchange topicExchange) {
        return BindingBuilder.bind(createLogQueue).to(topicExchange).with("log.create.*");
    }
}
```

生产者：用点号拼接多维度 routing key，一条消息可同时命中多个队列。

```java
@Service
public class LogTopicProducer {
    @Autowired
    private RabbitTemplate rabbitTemplate;

    public void send(String module, String action, String level, String msg) {
        // routing key = log.create.info → 同时命中 queue.log.all 与 queue.log.create
        String routingKey = String.join(".", "log", module, action, level);
        rabbitTemplate.convertAndSend(TopicRabbitConfig.EXCHANGE, routingKey, msg);
    }
}
```

关键点：`log.create.info` 命中 `log.#`（# 吃掉 `create.info`）和 `log.create.*`（* 匹配 `info`），但不会命中 `log.cancel.*`。这是实际项目首选——既能做精确路由，又能按业务维度灵活订阅。

### 3. Fanout Exchange — 忽略 Routing Key，全量广播

配置层：绑定时不传 routing key，`BindingBuilder.bind(queue).to(fanoutExchange)` 即可。

```java
@Configuration
public class FanoutRabbitConfig {
    public static final String EXCHANGE = "exchange.notify.fanout";

    @Bean
    public FanoutExchange fanoutExchange() {
        return new FanoutExchange(EXCHANGE, true, false);
    }

    @Bean
    public Queue smsQueue()   { return new Queue("queue.notify.sms", true); }
    @Bean
    public Queue emailQueue() { return new Queue("queue.notify.email", true); }
    @Bean
    public Queue pushQueue()  { return new Queue("queue.notify.push", true); }

    // Fanout 绑定不需要 routing key
    @Bean public Binding smsBinding(Queue smsQueue, FanoutExchange fanoutExchange) {
        return BindingBuilder.bind(smsQueue).to(fanoutExchange);
    }
    @Bean public Binding emailBinding(Queue emailQueue, FanoutExchange fanoutExchange) {
        return BindingBuilder.bind(emailQueue).to(fanoutExchange);
    }
    @Bean public Binding pushBinding(Queue pushQueue, FanoutExchange fanoutExchange) {
        return BindingBuilder.bind(pushQueue).to(fanoutExchange);
    }
}
```

生产者：routing key 传空串即可，发一条三个队列全收到。

```java
@Service
public class NotifyFanoutProducer {
    @Autowired
    private RabbitTemplate rabbitTemplate;

    public void broadcast(String content) {
        // routing key 传空串，会被 Exchange 忽略
        rabbitTemplate.convertAndSend(
                FanoutRabbitConfig.EXCHANGE,
                "",
                new NotifyEvent(content));
    }
}
```

关键点：消息被复制到每一个绑定队列，与 routing key 完全无关，适合「下单后同时发短信、邮件、App 推送」这类广播通知。

### 4. Headers Exchange — 按 headers 匹配 all / any（少用）

配置层：用 `whereAll`（x-match=all，全部满足）和 `whereAny`（x-match=any，任一满足）按 headers 匹配，不看 routing key。

```java
@Configuration
public class HeadersRabbitConfig {
    public static final String EXCHANGE = "exchange.doc.headers";

    @Bean
    public HeadersExchange headersExchange() {
        return new HeadersExchange(EXCHANGE, true, false);
    }

    @Bean
    public Queue pdfReportQueue() {
        return new Queue("queue.doc.pdf.report", true);
    }

    // x-match=all：format=pdf 且 type=report 才命中
    @Bean
    public Binding pdfReportBinding(Queue pdfReportQueue, HeadersExchange headersExchange) {
        Map<String, Object> headers = new HashMap<>();
        headers.put("format", "pdf");
        headers.put("type", "report");
        return BindingBuilder.bind(pdfReportQueue)
                .to(headersExchange)
                .whereAll(headers)        // 对应 x-match=all
                .match();
    }

    @Bean
    public Queue anyReportQueue() {
        return new Queue("queue.doc.any.report", true);
    }

    // x-match=any：format=docx 或 type=report 任一满足即命中
    @Bean
    public Binding anyReportBinding(Queue anyReportQueue, HeadersExchange headersExchange) {
        Map<String, Object> headers = new HashMap<>();
        headers.put("format", "docx");
        headers.put("type", "report");
        return BindingBuilder.bind(anyReportQueue)
                .to(headersExchange)
                .whereAny(headers)        // 对应 x-match=any
                .match();
    }
}
```

生产者：通过 `MessagePostProcessor` 写入 headers，routing key 在此模式下无效。

```java
@Service
public class DocHeadersProducer {
    @Autowired
    private RabbitTemplate rabbitTemplate;

    public void send() {
        MessagePostProcessor postProcessor = message -> {
            Map<String, Object> h = message.getMessageProperties().getHeaders();
            h.put("format", "pdf");
            h.put("type", "report");
            return message;
        };
        // 同时命中 pdfReportQueue（all 满足）与 anyReportQueue（type=report 满足 any）
        rabbitTemplate.convertAndSend(
                HeadersRabbitConfig.EXCHANGE,
                "",                 // routing key 在 headers 模式下无效
                "report-body",
                postProcessor);
    }
}
```

关键点：匹配依据是 headers 而非 routing key，`all` 要求全部命中、`any` 要求任一命中。灵活但性能与可读性都不如 Topic，实际项目中很少使用。

## 四种类型对比

| 维度 | Direct | Topic | Fanout | Headers |
|---|---|---|---|---|
| 路由规则 | Routing Key 完全相等 | 通配符模式匹配 | 忽略 Routing Key | 按 headers 匹配 |
| Routing Key | 必须，精确值 | 必须，含 `*` / `#` | 不使用 | 不使用 |
| 匹配性能 | 高 | 略低（需解析通配符） | 最高（无匹配逻辑） | 较低（解析 headers） |
| 灵活性 | 低 | 高 | 低（仅广播） | 中 |
| 典型场景 | 点对点精确路由 | 多维度日志/事件路由 | 广播通知 | 按 header 复杂条件 |
| 使用频率 | 中 | 最高（首选） | 高 | 很低 |

## 一句话总结

**一句话总结：Direct 是按门牌号精准投递的快递员、Fanout 是全村大喇叭、Headers 是对暗号接头，而 Topic 是带通配符的智能分拣员——实际项目里它一个顶仨。**
