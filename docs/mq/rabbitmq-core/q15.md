# Q15 Direct Exchange 路由规则

Direct Exchange 的路由规则是 **Routing Key 与 Binding Key 完全相等**——字符串严格匹配，差一个字符都不会路由。它是四种 Exchange 中最简单的路由模型，适合「按类型精确投递到对应队列」的点对点场景，比如日志级别路由和任务分发。

上图展示了 Direct Exchange 的核心路由逻辑：三条不同 routingKey 的消息分别走不同路径——`error` 精确匹配到 Queue A、`info` 精确匹配到 Queue B、`warning` 无队列匹配被丢弃。底部两个色块分别展示了日志级别路由和任务类型分发两个典型场景。下面用代码逐步实现。

## 日志级别路由的完整实现

### Layer 1 — 配置层：声明 Exchange + Queue + Binding

```java
@Configuration
public class LogDirectConfig {
    public static final String EXCHANGE = "exchange.log.direct";
    public static final String QUEUE_ERROR = "queue.log.error";
    public static final String QUEUE_INFO  = "queue.log.info";

    @Bean
    public DirectExchange logExchange() {
        // durable=true, autoDelete=false
        return new DirectExchange(EXCHANGE, true, false);
    }

    @Bean
    public Queue errorQueue() {
        return new Queue(QUEUE_ERROR, true);
    }

    @Bean
    public Queue infoQueue() {
        return new Queue(QUEUE_INFO, true);
    }

    // 核心路由规则：binding key "error" 只收 routing key 为 "error" 的消息
    @Bean
    public Binding errorBinding(Queue errorQueue, DirectExchange logExchange) {
        return BindingBuilder.bind(errorQueue)
                .to(logExchange)
                .with("error");          // ← 字符串严格相等，不支持通配符
    }

    @Bean
    public Binding infoBinding(Queue infoQueue, DirectExchange logExchange) {
        return BindingBuilder.bind(infoQueue)
                .to(logExchange)
                .with("info");           // ← routing key 必须恰好是 "info"
    }
}
```

关键点：`with("error")` 指定的就是 binding key，生产者发送时 routing key 必须与此完全一致。没有 `*` 或 `#`，就是纯字符串 `equals` 比较。

### Layer 2 — 生产者：精确指定 routing key

```java
@Service
public class LogDirectProducer {
    @Autowired
    private RabbitTemplate rabbitTemplate;

    public void sendError(String msg) {
        // routing key = "error" → 命中 Queue A
        rabbitTemplate.convertAndSend(
                LogDirectConfig.EXCHANGE,
                "error",                    // ← 必须与 binding key 完全相等
                msg);
    }

    public void sendInfo(String msg) {
        // routing key = "info" → 命中 Queue B
        rabbitTemplate.convertAndSend(
                LogDirectConfig.EXCHANGE,
                "info",                     // ← 多一个空格都不会匹配
                msg);
    }

    public void sendWarning(String msg) {
        // routing key = "warning" → 无队列匹配，消息丢弃！
        rabbitTemplate.convertAndSend(
                LogDirectConfig.EXCHANGE,
                "warning",                  // ← 没有 binding key == "warning"
                msg);
    }
}
```

关键点：`"error"` 能匹配，但 `"Error"` 或 `" error"` 都不会匹配——大小写敏感、空白敏感。这就是 Direct 的「精确」含义。

### Layer 3 — 消费者：各队列独立消费

```java
@Component
public class LogDirectConsumer {

    @RabbitListener(queues = LogDirectConfig.QUEUE_ERROR)
    public void handleError(String msg) {
        // error 日志 → 触发告警（短信/电话/钉钉）
        alertService.sendCriticalAlert(msg);
    }

    @RabbitListener(queues = LogDirectConfig.QUEUE_INFO)
    public void handleInfo(String msg) {
        // info 日志 → 写入 Elasticsearch 做统计分析
        elasticsearchClient.index("logs-info", msg);
    }
}
```

关键点：两个消费者互不影响，error 队列堆积不影响 info 队列的消费速度。

## Direct Exchange vs 其他路由方式对比

| 维度 | Direct Exchange | Topic Exchange | 默认 Exchange ("" ) |
|---|---|---|---|
| 匹配规则 | Routing Key == Binding Key | 通配符 `*` / `#` | Routing Key == Queue 名 |
| 灵活性 | 低（精确值，无通配符） | 高（模式匹配） | 最低（只能发到单个 Queue） |
| 一条消息命中多个队列 | 可以（多个 Queue 绑同一 key） | 可以 | 不可以 |
| 典型场景 | 日志级别路由、任务分发 | 多维度事件路由 | 简单点对点 |
| routing key 大小写敏感 | 是 | 是 | 是 |
| 不匹配时的行为 | 消息丢弃（除非有 Alternate Exchange） | 消息丢弃 | 消息丢弃 |

> 注意：默认 Exchange（名字为空串 `""`）本质是一个特殊的 Direct Exchange，它的规则是 routing key 必须等于 queue 名字。这是 RabbitMQ 内置的，不需要声明。

## 一句话总结

**一句话总结：Direct Exchange 是一个只认门牌号的快递员——routing key 和 binding key 差一个字母都不送，简单粗暴但精确可靠，适合「按类型一刀切」的路由场景。**
