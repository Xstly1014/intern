# Q19 Queue 属性详解

Queue 的三个关键属性控制其生命周期：**durable**（持久化）决定 Broker 重启后队列是否存活，**exclusive**（独占）限制队列只能被创建它的 Connection 使用且断开即删，**auto-delete**（自动删除）在最后一个消费者断开后自动删除队列。生产环境标准配置是 `durable=true, exclusive=false, auto-delete=false`，此外还有 `x-message-ttl`、`x-max-length` 等可选参数控制消息行为。

## 各种 Queue 属性的 Spring AMQP 实现

### Layer 1 — 生产环境标准队列（durable + 非独占 + 非自动删除）

```java
@Configuration
public class StandardQueueConfig {

    // 生产环境标准配置：durable=true, exclusive=false, auto-delete=false
    @Bean
    public Queue orderQueue() {
        return new Queue("queue.order", true);
        //                             ↑ durable=true
        // exclusive 和 auto-delete 默认都是 false
    }

    @Bean
    public Queue paymentQueue() {
        return new Queue("queue.payment", true);
    }
}
```

关键点：`new Queue(name, durable)` 是最常用的构造方法，exclusive 和 auto-delete 默认 false。Broker 重启后队列自动恢复，消费者全部断开后队列仍保留。

### Layer 2 — 临时回调队列（exclusive = true，RPC 场景）

```java
@Service
public class RpcClientService {
    @Autowired
    private RabbitTemplate rabbitTemplate;

    public Object callRemote(String request) {
        // exclusive 队列：Connection 断开自动删除，适合一次性 RPC 回调
        String replyQueueName = rabbitTemplate.execute(channel -> {
            return channel.queueDeclare(
                    "",          // 队列名空串 → Broker 自动生成随机名
                    false,       // durable=false（临时队列不需要持久化）
                    true,        // exclusive=true → 绑定当前 Connection
                    true,        // auto-delete=true
                    null         // 额外参数
            ).getQueue();
        });

        // 发送 RPC 请求，设置 replyTo 为刚创建的临时队列
        Message reply = rabbitTemplate.sendAndReceive(
                "rpc.exchange",
                "rpc.request",
                new Message(request.getBytes(), new MessageProperties()),
                // replyTo 已通过临时队列设置
                null);

        return new String(reply.getBody());
        // Connection 关闭后，replyQueue 自动删除，不留垃圾
    }
}
```

关键点：exclusive 队列的 `durable` 必须为 `false`（独占队列不允许持久化）。RPC 场景用完即走，Connection 断开自动清理。

### Layer 3 — 带可选参数的队列（TTL + 最大长度）

```java
@Configuration
public class AdvancedQueueConfig {

    // 带消息 TTL 的队列：消息存活 30 秒后自动过期
    @Bean
    public Queue ttlQueue() {
        return QueueBuilder.durable("queue.order.ttl")
                .withArgument("x-message-ttl", 30000)      // 消息 30 秒后过期
                .withArgument("x-dead-letter-exchange", "dlx.exchange")  // 过期后转死信
                .build();
    }

    // 带最大长度的队列：超过 10000 条消息，旧消息被丢弃
    @Bean
    public Queue maxLengthQueue() {
        return QueueBuilder.durable("queue.notification")
                .withArgument("x-max-length", 10000)        // 最多 10000 条
                .withArgument("x-overflow", "reject-publish") // 满了拒绝新消息
                .build();
    }
}
```

关键点：`x-message-ttl` 控制消息存活时间，过期后消息变成死信（需配合 `x-dead-letter-exchange`）。`x-max-length` 限制队列长度，超出策略由 `x-overflow` 决定（`drop-head` 丢旧消息或 `reject-publish` 拒新消息）。

## 三大属性对比

| 属性 | 作用 | true 含义 | false 含义 | 生产环境建议 |
|---|---|---|---|---|
| durable | 元数据持久化 | Broker 重启后队列存活 | Broker 重启后队列消失 | **true**（必须） |
| exclusive | 绑定 Connection | 只有创建者可用，断开即删 | 所有 Connection 可用 | **false**（标准） |
| auto-delete | 绑定消费者 | 最后一个消费者断开即删 | 消费者全断队列保留 | **false**（标准） |

> 注意：durable 只持久化 Queue 的元数据（名称、属性），不持久化消息本身。消息持久化需要在发送时设置 `deliveryMode=2`（Spring AMQP 默认已设置）。

## 可选参数速查

| 参数 | 作用 | 典型值 |
|---|---|---|
| x-message-ttl | 队列内消息的存活时间（毫秒） | 30000（30 秒） |
| x-max-length | 队列最大消息数 | 10000 |
| x-overflow | 超出 max-length 的策略 | drop-head / reject-publish |
| x-dead-letter-exchange | 死信交换机 | dlx.exchange |
| x-dead-letter-routing-key | 死信 routing key | dead.letter |
| x-max-priority | 队列支持优先级 | 10 |

## 一句话总结

**一句话总结：durable 决定队列「能不能活过重启」、exclusive 决定「能不能活过 Connection 断开」、auto-delete 决定「能不能活过消费者断开」——生产环境三个属性的标准答案是 true / false / false，让队列尽可能长寿。**
