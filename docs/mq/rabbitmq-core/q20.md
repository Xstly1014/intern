# Q20 Binding 与 Routing Key

Binding 是 Exchange 和 Queue 之间的**绑定关系**，可以携带一个 Binding Key（也叫 Routing Key）。生产者发消息时带一个 Routing Key，Exchange 根据自己的类型和 Binding Key 的匹配规则决定消息路由到哪些 Queue。一个 Exchange 可以绑定多个 Queue，每个 Binding 可以有不同的 Binding Key；甚至一个 Queue 可以被多次绑定到同一个 Exchange（用不同 Binding Key）。这种灵活的组合是 RabbitMQ 路由能力的核心。

上图展示了一条 `routing key = order.payment` 的消息如何同时命中三个 Queue——`order.*`（匹配第二段）、`*.payment`（匹配第一段）、`order.#`（匹配后缀），但不会命中 `order.cancel`（精确匹配失败）。这正是 Binding 灵活组合的威力：一个 Exchange 上挂多个不同 Binding Key，一条消息可以扇出到多个 Queue。下面用代码实现这套多重绑定。

## 多重绑定的 Spring AMQP 实现

### Layer 1 — 配置层：一个 Exchange + 四个不同 Binding

```java
@Configuration
public class MultiBindingConfig {
    public static final String EXCHANGE = "exchange.order.topic";

    @Bean
    public TopicExchange orderExchange() {
        return new TopicExchange(EXCHANGE, true, false);
    }

    // Queue A: 绑定 order.* → 匹配 order.xxx（两段式）
    @Bean
    public Queue queueA() {
        return new Queue("queue.order.all-action", true);
    }

    @Bean
    public Binding bindingA(Queue queueA, TopicExchange orderExchange) {
        return BindingBuilder.bind(queueA)
                .to(orderExchange)
                .with("order.*");          // ← 匹配 order.payment / order.refund
    }

    // Queue B: 绑定 *.payment → 匹配 xxx.payment（第一段任意）
    @Bean
    public Queue queueB() {
        return new Queue("queue.all-payment", true);
    }

    @Bean
    public Binding bindingB(Queue queueB, TopicExchange orderExchange) {
        return BindingBuilder.bind(queueB)
                .to(orderExchange)
                .with("*.payment");        // ← 匹配 order.payment / refund.payment
    }

    // Queue C: 绑定 order.# → 匹配 order 开头的所有消息
    @Bean
    public Queue queueC() {
        return new Queue("queue.order.audit", true);
    }

    @Bean
    public Binding bindingC(Queue queueC, TopicExchange orderExchange) {
        return BindingBuilder.bind(queueC)
                .to(orderExchange)
                .with("order.#");          // ← 匹配 order / order.payment / order.payment.success
    }

    // Queue D: 精确绑定 order.cancel → 只匹配 order.cancel
    @Bean
    public Queue queueD() {
        return new Queue("queue.order.cancel", true);
    }

    @Bean
    public Binding bindingD(Queue queueD, TopicExchange orderExchange) {
        return BindingBuilder.bind(queueD)
                .to(orderExchange)
                .with("order.cancel");     // ← 无通配符，精确匹配
    }
}
```

关键点：四个 Binding 挂在同一个 Exchange 上，每个 Binding Key 不同。当消息的 routing key 为 `order.payment` 时，Binding A/B/C 都匹配，Binding D 不匹配——一条消息同时进入三个 Queue。

### Layer 2 — 生产者：一条消息，扇出到多个 Queue

```java
@Service
public class OrderProducer {
    @Autowired
    private RabbitTemplate rabbitTemplate;

    public void sendPayment(String orderId) {
        // routing key = "order.payment"
        // → 命中 queue.order.all-action（order.* 匹配 payment）
        // → 命中 queue.all-payment（*.payment 匹配 order）
        // → 命中 queue.order.audit（order.# 匹配 payment）
        // → 不命中 queue.order.cancel（精确匹配失败）
        rabbitTemplate.convertAndSend(
                MultiBindingConfig.EXCHANGE,
                "order.payment",               // ← 一条消息，三个 Queue 同时收到
                new OrderEvent(orderId, "PAID"));
    }

    public void sendCancel(String orderId) {
        // routing key = "order.cancel"
        // → 命中 queue.order.all-action（order.* 匹配 cancel）
        // → 命中 queue.order.audit（order.# 匹配 cancel）
        // → 命中 queue.order.cancel（精确匹配 order.cancel）
        // → 不命中 queue.all-payment（*.payment 不匹配 cancel）
        rabbitTemplate.convertAndSend(
                MultiBindingConfig.EXCHANGE,
                "order.cancel",
                new OrderEvent(orderId, "CANCELLED"));
    }
}
```

关键点：生产者只管发消息和设 routing key，完全不关心有哪些 Queue。新增一个 Queue 只需加一条 Binding，生产者代码零改动——这就是 Binding 带来的解耦能力。

### Layer 3 — 同一 Queue 多重绑定（一个 Queue 绑多个 Key）

```java
@Configuration
public class MultiKeyQueueConfig {

    // 同一个 Queue 绑定到 Exchange 两次，用不同 Binding Key
    @Bean
    public Queue notificationQueue() {
        return new Queue("queue.notify.combined", true);
    }

    // 绑定 1：匹配 order.created
    @Bean
    public Binding notifyBinding1(Queue notificationQueue, TopicExchange exchange) {
        return BindingBuilder.bind(notificationQueue)
                .to(exchange)
                .with("order.created");     // ← 订单创建通知
    }

    // 绑定 2：匹配 order.cancelled（同一个 Queue，不同 Key）
    @Bean
    public Binding notifyBinding2(Queue notificationQueue, TopicExchange exchange) {
        return BindingBuilder.bind(notificationQueue)
                .to(exchange)
                .with("order.cancelled");   // ← 订单取消通知也进同一 Queue
    }
}
```

关键点：一个 Queue 可以被多次绑定到同一个 Exchange，每次用不同 Binding Key。这意味着 `order.created` 和 `order.cancelled` 的消息都会进入同一个 `queue.notify.combined`，消费者只需监听一个 Queue 就能收到多种事件。

## Binding 关系对比

| 维度 | 一对一绑定 | 一对多绑定 | 多对一绑定 | 多对多绑定 |
|---|---|---|---|---|
| Exchange 数量 | 1 | 1 | N | N |
| Queue 数量 | 1 | N | 1 | N |
| Binding Key | 1 个 | N 个不同 | N 个不同 | N×M 个 |
| 典型场景 | 简单点对点 | 事件扇出 | 多事件聚合 | 复杂路由网络 |
| 一条消息命中 | 1 个 Queue | 0~N 个 Queue | 0~1 个 Queue | 0~N 个 Queue |

> 核心认知：Binding 是 Exchange 和 Queue 之间的「多对多」关系。Exchange 像路由器查路由表（Binding 列表），Queue 像信箱可以订阅多个频道（多个 Binding Key）。

## 一句话总结

**一句话总结：Binding 是 Exchange 和 Queue 之间的「多对多订阅关系」——一个 Exchange 能绑 N 个 Queue、一个 Queue 也能绑 N 个 Key，一条消息按匹配规则扇出到多个 Queue，新增消费者只需加一条 Binding 而生产者零改动。**
