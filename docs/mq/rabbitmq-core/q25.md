# Q25 优先级队列

优先级队列通过声明 Queue 时设置 `x-max-priority` 参数（0-255）实现，发送消息时设置 `priority` 属性，消费者会优先消费高优先级消息。核心限制有三点：优先级是消费顺序优先而非抢占式（正在消费的低优先级消息不会被中断）、消费者 `prefetch` 过大会导致优先级失效（太多消息已到客户端缓冲）、性能有损耗（Broker 要维护优先级堆排序）。建议 `x-max-priority` 设小一点（如 0-10），`prefetch` 设 1。

上图展示了优先级队列的工作机制：Producer 发送不同 priority 的消息，Broker 内部维护优先级堆排序，Consumer 按 prefetch=1 拉取时先消费高优先级。三个限制分别说明非抢占式、prefetch 失效和性能损耗。下面用代码实现。

## 优先级队列实现

### Layer 1 — 配置层：声明带 x-max-priority 的队列

```java
@Configuration
public class PriorityQueueConfig {

    @Bean
    public Queue priorityQueue() {
        return QueueBuilder.durable("queue.task.priority")
                .withArgument("x-max-priority", 10)  // 最大优先级 0-10
                .build();
    }

    @Bean
    public DirectExchange taskExchange() {
        return new DirectExchange("exchange.task", true, false);
    }

    @Bean
    public Binding priorityBinding(Queue priorityQueue, DirectExchange taskExchange) {
        return BindingBuilder.bind(priorityQueue).to(taskExchange).with("task.process");
    }
}
```

关键点：`x-max-priority=10` 限制队列支持的最大优先级为 0-10。设太大（如 255）会增加 Broker 的堆排序开销，建议设小一点，10 个级别足够区分业务优先级。

### Layer 2 — 生产者：发送带 priority 的消息

```java
@Service
public class TaskPriorityProducer {
    @Autowired
    private RabbitTemplate rabbitTemplate;

    // 发送高优先级消息（VIP 用户 / 告警）
    public void sendHighPriority(String taskId, String content) {
        rabbitTemplate.convertAndSend(
                "exchange.task",
                "task.process",
                new TaskEvent(taskId, content),
                message -> {
                    message.getMessageProperties().setPriority(10);  // 最高优先级
                    return message;
                });
    }

    // 发送普通优先级消息
    public void sendNormalPriority(String taskId, String content) {
        rabbitTemplate.convertAndSend(
                "exchange.task",
                "task.process",
                new TaskEvent(taskId, content),
                message -> {
                    message.getMessageProperties().setPriority(5);   // 中等优先级
                    return message;
                });
    }

    // 发送低优先级消息（普通日志 / 批量任务）
    public void sendLowPriority(String taskId, String content) {
        rabbitTemplate.convertAndSend(
                "exchange.task",
                "task.process",
                new TaskEvent(taskId, content),
                message -> {
                    message.getMessageProperties().setPriority(1);   // 低优先级
                    return message;
                });
    }
}
```

关键点：通过 `setPriority()` 设置消息优先级，值越大优先级越高。如果消息 priority 超过 `x-max-priority`，Broker 会将其降为 `x-max-priority` 的值。

### Layer 3 — 消费者：prefetch=1 让优先级生效

```java
@Component
public class PriorityTaskConsumer {

    // ⚠ prefetch 必须设 1，否则优先级失效
    @RabbitListener(
            queues = "queue.task.priority",
            containerFactory = "priorityContainerFactory")
    public void handleTask(TaskEvent event) {
        // 先消费高优先级消息，再消费低优先级
        // 但如果正在处理低优先级消息，高优先级进来不会中断当前处理
        taskService.process(event);
    }
}

@Configuration
public class PriorityConsumerConfig {

    @Bean
    public SimpleRabbitListenerContainerFactory priorityContainerFactory(
            ConnectionFactory connectionFactory) {
        SimpleRabbitListenerContainerFactory factory = new SimpleRabbitListenerContainerFactory();
        factory.setConnectionFactory(connectionFactory);
        factory.setPrefetchCount(1);  // ← 关键！prefetch=1 让 Broker 优先级堆生效
        factory.setConcurrentConsumers(3);  // 多消费者并行处理
        factory.setMaxConcurrentConsumers(10);
        return factory;
    }
}
```

关键点：`setPrefetchCount(1)` 是优先级队列生效的关键——如果 prefetch 设 100，Consumer 一次性拉取 100 条消息到本地缓冲，后续到达的高优先级消息只能在 Broker 队列中等待，优先级完全失效。

## 优先级队列三大限制详解

| 限制 | 说明 | 影响 | 解决方案 |
|---|---|---|---|
| 非抢占式 | 优先级只影响下次拉取顺序 | 正在消费的低优先级不会被中断 | 接受特性，或缩短单条处理时间 |
| prefetch 过大 | 消息已到客户端缓冲 | 优先级完全失效 | prefetch=1 |
| 性能损耗 | Broker 维护堆排序 | 吞吐量下降 | x-max-priority 设 0-10 |
| priority 超限 | 超过 x-max-priority | 被降为最大值 | 确保发送值在范围内 |
| 无消费者时 | 消息堆积在队列 | 优先级只在消费时排序 | 确保有足够消费者 |

> 面试要点：优先级队列的三个限制是核心考点。最容易被忽略的是 prefetch 问题——很多人设了优先级但 prefetch 用默认值（250），导致优先级完全失效。记住：`prefetch=1` 是优先级队列生效的前提。

## 一句话总结

**一句话总结：优先级队列是 RabbitMQ 的「VIP 通道」——通过 x-max-priority 和 priority 属性让高优先级消息先被消费，但它只影响消费顺序而非抢占式中断，且必须配合 prefetch=1 才能真正生效。**
