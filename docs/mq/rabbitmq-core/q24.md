# Q24 延迟队列实现

RabbitMQ 本身不支持延迟队列，但可以通过三种方案实现「30 分钟后自动取消未支付订单」：**TTL + DLX**（经典方案，消息进带 TTL 的队列，过期后通过死信交换机转发）、**rabbitmq_delayed_message_exchange 插件**（推荐方案，声明 x-delayed-message 类型 Exchange，发消息时带 x-delay 头指定延迟毫秒数）、**多级 TTL 队列**（按延迟时长建多个队列避免队头阻塞）。实际项目中插件方案最简单，但高并发场景需评估性能开销。

## 方案一：TTL + DLX 实现延迟队列

### Layer 1 — 配置层：TTL 队列 + DLX + 处理队列

```java
@Configuration
public class TtlDlxConfig {

    // ===== 死信交换机 + 处理队列 =====
    @Bean
    public DirectExchange dlxExchange() {
        return new DirectExchange("dlx.order.exchange", true, false);
    }

    @Bean
    public Queue processQueue() {
        return new Queue("queue.order.process", true);
    }

    @Bean
    public Binding processBinding(Queue processQueue, DirectExchange dlxExchange) {
        return BindingBuilder.bind(processQueue).to(dlxExchange).with("order.timeout");
    }

    // ===== TTL 队列（消息 30 分钟后过期转 DLX） =====
    @Bean
    public Queue ttlQueue() {
        return QueueBuilder.durable("queue.order.ttl")
                .withArgument("x-message-ttl", 1800000)                    // 30 分钟过期
                .withArgument("x-dead-letter-exchange", "dlx.order.exchange")
                .withArgument("x-dead-letter-routing-key", "order.timeout")
                .build();
    }
}
```

关键点：`x-message-ttl=1800000` 让队列内所有消息统一 30 分钟过期，过期后自动转发到 `dlx.order.exchange`。队列级 TTL 不存在队头阻塞，因为所有消息的过期时间相同。

### Layer 2 — 生产者：发送延迟消息

```java
@Service
public class OrderDelayProducer {
    @Autowired
    private RabbitTemplate rabbitTemplate;

    // 方式1：队列级 TTL（统一 30 分钟，无队头阻塞）
    public void sendOrderTimeout(String orderId) {
        rabbitTemplate.convertAndSend(
                "",                    // 默认 Exchange
                "queue.order.ttl",      // 直发 TTL 队列
                new OrderEvent(orderId, "PENDING"));
        // 消息 30 分钟后自动过期 → 转 DLX → 进处理队列
    }

    // 方式2：消息级 TTL（每条消息不同延迟，但有队头阻塞风险）
    public void sendCustomDelay(String orderId, long delayMs) {
        MessagePostProcessor postProcessor = message -> {
            message.getMessageProperties().setExpiration(String.valueOf(delayMs));
            return message;
        };
        rabbitTemplate.convertAndSend(
                "",
                "queue.order.ttl",
                new OrderEvent(orderId, "PENDING"),
                postProcessor);
        // ⚠ 队头阻塞：如果前面消息 delay=30min，后面 delay=5s
        // 后面的消息要等前面的过期后才会被检查
    }
}
```

关键点：消息级 TTL 通过 `setExpiration` 设置每条消息不同延迟，但 RabbitMQ 对消息级 TTL 的过期检测是惰性的——只有消息到达队列头部才检查。如果队首消息 TTL 未到期，后面即使先过期也不会出队。

### Layer 3 — 消费者：处理超时订单

```java
@Component
public class OrderTimeoutConsumer {

    @RabbitListener(queues = "queue.order.process")
    public void handleTimeout(OrderEvent event) {
        Order order = orderService.getById(event.getOrderId());

        if (order != null && "PENDING".equals(order.getStatus())) {
            orderService.cancelOrder(order.getId(), "超时未支付，自动取消");
            notificationService.notifyUser(order.getUserId(), "订单已超时取消");
        }
        // 幂等检查：如果已支付则忽略
    }
}
```

关键点：消费者从处理队列收到的消息是 30 分钟前发出的，需要做幂等检查——用户可能在 30 分钟内已支付，此时应忽略该死信消息。

## 方案二：rabbitmq_delayed_message_exchange 插件（推荐）

### Layer 1 — 安装插件并声明延迟 Exchange

```bash
# 1. 下载插件（版本需匹配 RabbitMQ 版本）
# https://github.com/rabbitmq/rabbitmq-delayed-message-exchange/releases

# 2. 放到 RabbitMQ 插件目录
cp rabbitmq_delayed_message_exchange.ez /usr/lib/rabbitmq/lib/rabbitmq_server-3.12.0/plugins/

# 3. 启用插件
rabbitmq-plugins enable rabbitmq_delayed_message_exchange
```

```java
@Configuration
public class DelayedExchangeConfig {

    // 声明 x-delayed-message 类型的 Exchange
    @Bean
    public CustomExchange delayedExchange() {
        Map<String, Object> args = new HashMap<>();
        args.put("x-delayed-type", "direct");  // 底层路由类型
        return new CustomExchange(
                "exchange.delayed.order",
                "x-delayed-message",  // 插件提供的类型
                true,                  // durable
                false,                 // auto-delete
                args);
    }

    @Bean
    public Queue delayedQueue() {
        return new Queue("queue.delayed.order", true);
    }

    @Bean
    public Binding delayedBinding(Queue delayedQueue, CustomExchange delayedExchange) {
        return BindingBuilder.bind(delayedQueue)
                .to(delayedExchange)
                .with("order.timeout")
                .noargs();
    }
}
```

关键点：插件提供 `x-delayed-message` 类型 Exchange，底层用 Mnesia 存储定时投递。`x-delayed-type` 指定底层路由类型（direct/topic/fanout/headers）。

### Layer 2 — 生产者：发送带 x-delay 头的消息

```java
@Service
public class DelayedExchangeProducer {
    @Autowired
    private RabbitTemplate rabbitTemplate;

    public void sendOrderTimeout(String orderId, long delayMs) {
        rabbitTemplate.convertAndSend(
                "exchange.delayed.order",
                "order.timeout",
                new OrderEvent(orderId, "PENDING"),
                message -> {
                    // 通过 x-delay header 指定延迟毫秒数
                    message.getMessageProperties()
                            .setHeader("x-delay", delayMs);
                    return message;
                });
        // 插件内部用 Mnesia 存储消息，到时间后自动投递
        // 每条消息独立计时，无队头阻塞问题
    }
}
```

关键点：`x-delay` header 指定延迟毫秒数，每条消息可以有不同的延迟值。插件内部用 Mnesia 存储消息并定时投递，不存在 TTL+DLX 方案的队头阻塞问题。

### Layer 3 — 消费者：与普通消费者完全一样

```java
@Component
public class DelayedExchangeConsumer {

    @RabbitListener(queues = "queue.delayed.order")
    public void handleTimeout(OrderEvent event) {
        Order order = orderService.getById(event.getOrderId());

        if (order != null && "PENDING".equals(order.getStatus())) {
            orderService.cancelOrder(order.getId(), "超时未支付，自动取消");
        }
        // 消费者代码与 TTL+DLX 方案完全一样
        // 区别只在 Exchange 类型和消息投递机制
    }
}
```

关键点：消费者端无任何特殊处理，插件对消费者完全透明。延迟逻辑全部封装在 Exchange 层。

## 三种延迟队列方案对比

| 维度 | TTL + DLX | 延迟消息插件 | 多级 TTL 队列 |
|---|---|---|---|
| 实现复杂度 | 中（需配 TTL+DLX） | 低（插件透明） | 高（需建多个队列） |
| 队头阻塞 | 有（消息级 TTL） | 无 | 无（同级别在同一队列） |
| 每条消息不同延迟 | 支持但有精度问题 | 完美支持 | 不支持（按级别分） |
| 额外依赖 | 无 | 需安装插件 | 无 |
| 性能 | 高（原生） | 中（Mnesia 存储） | 高（原生） |
| 高并发评估 | 稳定 | 需评估插件性能 | 稳定 |
| 推荐场景 | 统一延迟时长 | 灵活延迟（推荐） | 固定几个延迟级别 |

> 面试要点：TTL+DLX 的队头阻塞是核心考点。原因在于 RabbitMQ 对消息级 TTL 的过期检测是惰性的——只有消息到达队列头部才检查。解决方案是改用队列级 TTL（统一过期）、多级 TTL 队列（分级别），或直接用延迟消息插件。

## 一句话总结

**一句话总结：延迟队列的本质是「先存后发」——TTL+DLX 用队列过期机制实现但受困于队头阻塞，延迟消息插件用 Mnesia 定时器实现每条消息独立计时，多级 TTL 用分队列绕开队头阻塞；实际项目能用插件就用插件，最简单且无队头阻塞。**
