# Q4 点对点 vs 发布订阅

点对点（P2P）是一条消息只能被一个消费者消费——生产者把消息丢进队列，谁先抢到谁处理；发布订阅（Pub/Sub）是一条消息被所有订阅者各消费一次——生产者发到 Topic，每个订阅者各自拿到一份副本。RabbitMQ 本质是 P2P 模型（一条消息一个消费者），但通过 Fanout Exchange 可以实现 Pub/Sub 效果（每个队列各收到一份）；Kafka 原生是 Pub/Sub 模型，但通过 Consumer Group 机制模拟出了 P2P 效果（同组内竞争消费）。选型上：任务分发用 P2P，事件通知用 Pub/Sub。

上图核心区别在 Queue 的消费方式：P2P 中多个消费者竞争消费同一个 Queue，每条消息只被其中一个拿走；Pub/Sub 中 Topic 给每个订阅者复制一份副本，互不影响。下面用代码看 RabbitMQ 和 Kafka 分别怎么实现这两种模型。

## RabbitMQ：Queue 实现 P2P，Exchange 实现 Pub/Sub

### P2P 模式 — 多个消费者竞争同一个 Queue

```java
// 生产者：发送到默认 Exchange，路由到指定 Queue
rabbitTemplate.convertAndSend("", "task.queue", "process order #1001");

// 消费者 A 和 消费者 B 都监听同一个 Queue，竞争消费
@RabbitListener(queues = "task.queue")
public class OrderWorkerA {
    @RabbitHandler
    public void handle(String message) {
        // 消费者 A 拿到 "process order #1001"
    }
}
@RabbitListener(queues = "task.queue")  // 同一个 Queue
public class OrderWorkerB {
    @RabbitHandler
    public void handle(String message) {
        // 消费者 B 可能拿到下一条，不会重复拿到 #1001
    }
}
```

### Pub/Sub 模式 — Fanout Exchange 广播到多个 Queue

```java
// 生产者：发送到 Fanout Exchange，忽略 routing key
rabbitTemplate.convertAndSend("order.fanout", "", new OrderCreatedEvent(order));

// 每个下游各有一个独立 Queue，绑定到同一个 Exchange
@RabbitListener(bindings = @QueueBinding(
    value = @Queue("inventory.queue"),
    exchange = @Exchange(value = "order.fanout", type = "fanout")
))
public class InventoryConsumer {
    @RabbitHandler
    public void handle(OrderCreatedEvent event) {
        // 库存消费者拿到一份副本
    }
}

@RabbitListener(bindings = @QueueBinding(
    value = @Queue("notification.queue"),
    exchange = @Exchange(value = "order.fanout", type = "fanout")
))
public class NotificationConsumer {
    @RabbitHandler
    public void handle(OrderCreatedEvent event) {
        // 通知消费者也拿到一份副本，互不干扰
    }
}
```

关键区别：P2P 中多个消费者共享一个 Queue；Pub/Sub 中每个消费者有独立 Queue，Exchange 负责把消息复制到所有绑定的 Queue。

## Kafka：Topic + Consumer Group 同时实现两种模型

### Pub/Sub 模式 — 每个消费者属于不同的 Consumer Group

```java
// 订阅者 A：独立 Consumer Group
@KafkaListener(topics = "order.created", groupId = "inventory-group")
public class InventoryConsumer {
    public void handle(OrderCreatedEvent event) {
        // 库存组拿到消息
    }
}

// 订阅者 B：另一个 Consumer Group
@KafkaListener(topics = "order.created", groupId = "notification-group")
public class NotificationConsumer {
    public void handle(OrderCreatedEvent event) {
        // 通知组也拿到同一条消息，各消费一次
    }
}
// 两个不同 groupId → Pub/Sub：每组各拿一份
```

### P2P 模式 — 多个消费者属于同一个 Consumer Group

```java
// 同一个 groupId → P2P：竞争消费，每条消息只被组内一个消费者处理
@KafkaListener(topics = "order.created", groupId = "order-worker-group")
public class OrderWorkerA {
    public void handle(OrderCreatedEvent event) {
        // Worker A 拿到 partition 0 的消息
    }
}

@KafkaListener(topics = "order.created", groupId = "order-worker-group")  // 同一个 groupId
public class OrderWorkerB {
    public void handle(OrderCreatedEvent event) {
        // Worker B 拿到 partition 1 的消息
    }
}
// 同一个 groupId → P2P：同组内竞争，按 partition 分配
```

关键区别：Kafka 没有独立的 P2P 和 Pub/Sub 之分，**通过 groupId 区分**——同组竞争（P2P），不同组各自消费（Pub/Sub）。

## P2P vs Pub/Sub 对比

| 维度 | 点对点（P2P） | 发布订阅（Pub/Sub） |
|---|---|---|
| 消息消费方式 | 每条消息只被一个消费者消费 | 每条消息被所有订阅者各消费一次 |
| 消费者关系 | 竞争关系，分担负载 | 独立关系，各自处理 |
| RabbitMQ 实现 | 多个消费者监听同一个 Queue | Fanout Exchange 绑定多个独立 Queue |
| Kafka 实现 | 同一个 Consumer Group 内多个实例 | 不同 Consumer Group 各自订阅 |
| 典型场景 | 任务分发、订单处理、邮件发送 | 事件广播、通知、数据同步 |
| 扩展方式 | 加消费者到同组，提高消费速度 | 加订阅者，各自独立 Queue/Group |
| 消息副本 | 无，消息只存一份 | 有，每个订阅者各一份副本 |

**In one sentence: P2P 是"一条消息一个人干"——多个消费者竞争分担负载；Pub/Sub 是"一条消息大家都听一遍"——每个订阅者各自独立消费，RabbitMQ 用 Exchange vs Queue 区分，Kafka 用 Consumer Group 的 groupId 巧妙地统一了两种模型。**
