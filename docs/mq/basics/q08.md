# Q8 消息模型术语

消息队列的核心术语构成一条单向数据链：**Producer**（生产者）发消息到 **Broker**（消息代理），Broker 内部用 **Topic/Queue** 存储消息，按 **Exchange/Partition** 路由分发，**Consumer**（消费者）从 Broker 拉取或被推送消息。RabbitMQ 的模型是 Producer → Exchange → Queue → Consumer；Kafka 的模型是 Producer → Topic → Partition → Consumer Group。

上图对比了 RabbitMQ 和 Kafka 的术语映射关系。RabbitMQ 多了 Exchange 和 Binding 层做路由，Queue 是存储单元；Kafka 没有 Exchange，直接用 Topic 下的 Partition 做分区存储和并行。下面用代码把这些术语和实际 API 对应起来。

## RabbitMQ 术语对应

### Producer 层 — 发消息到 Exchange

```java
// Producer：指定 Exchange 和 routing key
rabbitTemplate.convertAndSend(
    "order.exchange",           // Exchange（交换机）：接收消息的入口
    "order.created.premium",    // routing key：Exchange 根据它决定路由到哪个 Queue
    new OrderCreatedEvent(order) // Message：消息体
);
```

### Binding 层 — 把 Queue 绑定到 Exchange

```java
// Binding：建立 Exchange → Queue 的路由规则
@QueueBinding(
    value = @Queue(name = "premium.order.queue", durable = "true"),  // Queue：存储消息的队列
    exchange = @Exchange(name = "order.exchange", type = "direct"),  // Exchange 类型决定路由方式
    key = "order.created.premium"  // routing key：匹配规则
)
// Broker = RabbitMQ Server，管理 Exchange + Queue + Binding
```

### Consumer 层 — 从 Queue 消费

```java
// Consumer：监听 Queue，Broker 推消息过来
@RabbitListener(queues = "premium.order.queue")  // Queue：消息从这里被消费
public class PremiumOrderConsumer {
    @RabbitHandler
    public void handle(OrderCreatedEvent event) {
        // 消费消息
    }
}
```

## Kafka 术语对应

### Producer 层 — 发消息到 Topic

```java
// Producer：指定 Topic 和 partition key
kafkaTemplate.send(
    "order.created",                // Topic：消息的主题
    order.getUserId(),              // partition key：决定消息进入哪个 Partition
    new OrderCreatedEvent(order)    // Message
);
// 没有 Exchange 概念，直接写 Topic
```

### Topic/Partition 层 — Broker 内部结构

```java
// Topic 配置示例：3 个 Partition，每个 Partition 有 Leader + Follower
// Topic: order.created
//   ├── Partition 0  → Leader(Broker 1) + Follower(Broker 2)
//   ├── Partition 1  → Leader(Broker 2) + Follower(Broker 3)
//   └── Partition 2  → Leader(Broker 3) + Follower(Broker 1)
// Partition 是并行消费的最小单位

// Offset：消费者在 Partition 中的消费位置
props.put("auto.offset.reset", "earliest");  // 从最早的消息开始消费
```

### Consumer Group 层 — 消费者组消费 Topic

```java
// Consumer Group：同一组内竞争消费，不同组各自消费
@KafkaListener(topics = "order.created", groupId = "order-processing-group")
public class OrderConsumer {
    public void handle(OrderCreatedEvent event) {
        // Partition 0,1,2 被分配给组内不同 Consumer 实例
    }
}
```

## 术语对照表

| 术语 | 含义 | RabbitMQ 对应 | Kafka 对应 |
|---|---|---|---|
| Producer | 消息生产者 | `rabbitTemplate.convertAndSend()` | `kafkaTemplate.send()` |
| Consumer | 消息消费者 | `@RabbitListener` | `@KafkaListener` |
| Broker | 消息代理服务器 | RabbitMQ Server | Kafka Broker |
| Topic | 消息主题/分类 | 通过 routing key 模拟 | 原生概念，一级分类 |
| Queue | 消息存储队列 | 原生概念，FIFO 有序 | 无（用 Partition 替代） |
| Partition | 分区/分片 | 无（用多个 Queue 模拟） | 原生概念，并行消费单位 |
| Exchange | 消息交换机 | 原生概念，4 种类型 | 无（直接写 Topic） |
| Binding | 交换机和队列的绑定 | 原生概念，含 routing key | 无 |
| Offset | 消费位置标记 | 无（用 ACK 机制） | 原生概念，消费者管理 |
| Consumer Group | 消费者组 | 无（用多个 Queue 模拟） | 原生概念，同组竞争 |

**In one sentence: 消息队列的术语就是一条数据链——Producer 把消息交给 Broker，Broker 内部用 Exchange/Topic 分类、用 Queue/Partition 存储、用 Binding/Offset 路由，Consumer 从 Broker 取走消息，RabbitMQ 的核心是 Exchange 路由，Kafka 的核心是 Partition 分区。**
