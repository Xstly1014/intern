# Q10 JMS vs AMQP

JMS 是 Java 平台的**消息 API 标准**（只定义接口，不定义协议），AMQP 是跨语言的**网络协议标准**（定义了 wire format 和语义）。简单说：JMS 管你 Java 代码怎么写，AMQP 管网络上字节怎么传。RabbitMQ 原生实现 AMQP 协议（也支持 JMS 客户端），Kafka 用自定义协议（不属于 JMS 也不属于 AMQP）。

上图对比了 JMS 和 AMQP 的层级差异。JMS 只到 API 层，下面的网络协议由各 Provider 自己定；AMQP 连网络协议都标准化了，所以能跨语言。下面用代码看两者的实际写法差异。

## JMS 写法 — 标准 Java API

### 生产者层 — JMS 标准接口

```java
import javax.jms.*;

// JMS 用标准 API：ConnectionFactory → Connection → Session → Producer
ConnectionFactory factory = new ActiveMQConnectionFactory("tcp://localhost:61616");
Connection connection = factory.createConnection();
Session session = connection.createSession(false, Session.AUTO_ACKNOWLEDGE);

// JMS 模型只有两种：Queue（P2P）和 Topic（Pub/Sub）
Destination destination = session.createQueue("order.queue");
// 或者：Destination destination = session.createTopic("order.topic");

MessageProducer producer = session.createProducer(destination);
producer.send(session.createTextMessage("order created #1001"));
```

### 消费者层 — JMS 标准监听

```java
MessageConsumer consumer = session.createConsumer(destination);
consumer.setMessageListener(message -> {
    TextMessage textMessage = (TextMessage) message;
    // 处理消息
});
connection.start();
```

关键特点：JMS 代码和具体 MQ 无关——换 ActiveMQ 到另一个 JMS Provider 只需改 ConnectionFactory。

## AMQP 写法 — RabbitMQ 客户端

### 生产者层 — AMQP 协议直连

```java
import com.rabbitmq.client.*;

// AMQP 直连 Broker，用 Exchange + routing key
ConnectionFactory factory = new ConnectionFactory();
factory.setHost("localhost");
Connection connection = factory.newConnection();
Channel channel = connection.createChannel();

// AMQP 模型：Exchange → Queue → Binding（比 JMS 多了路由层）
channel.exchangeDeclare("order.exchange", "direct");
channel.queueDeclare("order.queue", true, false, false, null);
channel.queueBind("order.queue", "order.exchange", "order.created");

// 发送到 Exchange，不是直接发到 Queue
channel.basicPublish("order.exchange", "order.created",
    null, "order created #1001".getBytes());
```

### 消费者层 — AMQP 消费回调

```java
channel.basicConsume("order.queue", false, (consumerTag, delivery) -> {
    String message = new String(delivery.getBody());
    // 处理消息
    channel.basicAck(delivery.getEnvelope().getDeliveryTag(), false);
}, consumerTag -> {});
```

关键差异：AMQP 有 Exchange 路由层，JMS 没有；AMQP 客户端任何语言都能写，JMS 只能 Java。

## JMS vs AMQP 对比

| 维度 | JMS | AMQP |
|---|---|---|
| 本质 | Java API 标准（接口） | 网络协议标准（wire format） |
| 定义层级 | 只定义 API，不定义协议 | 从 API 到协议全定义 |
| 语言支持 | 仅 Java | 跨语言（Java/Python/Go/Ruby...） |
| 消息模型 | Queue（P2P）+ Topic（Pub/Sub） | Exchange + Queue + Binding（4 种 Exchange） |
| 路由能力 | 弱（只有 Queue 和 Topic） | 强（Direct/Topic/Fanout/Headers） |
| 协议层 | 由 Provider 自定义（OpenWire/STOMP） | 统一 AMQP 0-9-1 / 1.0 |
| 代表实现 | ActiveMQ、OpenJMS | RabbitMQ |
| Kafka 关系 | 不遵循 JMS | 不遵循 AMQP（自定义协议） |
| 换 Provider | 代码几乎不改（JMS 标准接口） | 客户端库不同需适配 |

**In one sentence: JMS 是 Java 世界给自己定的规矩"大家都按这套 API 写"，AMQP 是跨语言的规矩"不管你什么语言网络上传的字节格式必须一样"——前者管接口不管协议，后者连协议一起管，所以 AMQP 能跨语言而 JMS 只能在 Java 圈里玩。**
