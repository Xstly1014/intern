# Q91 集群扩容与数据迁移

Kafka 集群扩容通过 kafka-reassign-partitions 工具实现不停服数据迁移，核心四步流程 --generate（生成方案）--execute（执行迁移）--verify（验证完成）--清理旧副本，配合 throttle 限速和低峰期执行可安全完成集群横向扩展。

上图为 kafka-reassign-partitions 工具的完整使用流程。核心思路：先生成迁移方案（指定 Topics + 目标 Broker），再执行迁移（新旧副本共存同步），验证通过后即可清理旧副本。需重点注意磁盘翻倍和 throttle 限速两个关键点。

## 分层操作代码

### Layer 1 — --generate 生成迁移 JSON 方案

```bash
#!/bin/bash
# Step 1: 生成 Partition 重分布方案
# 前提：新 Broker (3,4) 已加入集群，确保没有残留数据
BROKERS="localhost:9092"
TARGET_BROKERS="0,1,2,3,4"  # 扩容到 5 个 Broker

# 1.1 编写要迁移的 Topic 列表
cat > topics-to-move.json <<EOF
{
  "topics": [
    {"topic": "order-events"},
    {"topic": "payment-events"},
    {"topic": "user-activity"}
  ],
  "version": 1
}
EOF

# 1.2 生成重分布方案 (会输出 current 和 proposed 两份 JSON)
echo "=== 生成迁移方案 ==="
kafka-reassign-partitions.sh \
  --bootstrap-server $BROKERS \
  --topics-to-move-json-file topics-to-move.json \
  --broker-list "$TARGET_BROKERS" \
  --generate

# 1.3 将 proposed 部分保存为 reassignment.json
kafka-reassign-partitions.sh \
  --bootstrap-server $BROKERS \
  --topics-to-move-json-file topics-to-move.json \
  --broker-list "$TARGET_BROKERS" \
  --generate | tail -n +2 | head -n -1 > reassignment.json

echo "已生成 reassignment.json"
cat reassignment.json | python -m json.tool 2>/dev/null || cat reassignment.json
```

### Layer 2 — --execute 执行迁移 + throttle 限速

```bash
#!/bin/bash
# Step 2: 执行迁移 (低峰期操作)
BROKERS="localhost:9092"

# 2.1 先给所有 Broker 设置迁移限速 (避免打满带宽)
THROTTLE_RATE=104857600  # 100MB/s

for BROKER_ID in 0 1 2 3 4; do
  # leader 副本限速
  kafka-configs.sh --bootstrap-server $BROKERS \
    --entity-type brokers --entity-name $BROKER_ID \
    --alter --add-config leader.replication.throttled.rate=$THROTTLE_RATE
  # follower 副本限速
  kafka-configs.sh --bootstrap-server $BROKERS \
    --entity-type brokers --entity-name $BROKER_ID \
    --alter --add-config follower.replication.throttled.rate=$THROTTLE_RATE
done

# 2.2 给迁移涉及的 Topic Partition 打上 throttle 标记
TOPICS=("order-events" "payment-events" "user-activity")
for TOPIC in "${TOPICS[@]}"; do
  kafka-configs.sh --bootstrap-server $BROKERS \
    --entity-type topics --entity-name $TOPIC \
    --alter --add-config leader.replication.throttled.replicas="*",follower.replication.throttled.replicas="*"
done

# 2.3 执行迁移
echo "=== 开始执行迁移 (将在低峰期运行) ==="
kafka-reassign-partitions.sh \
  --bootstrap-server $BROKERS \
  --reassignment-json-file reassignment.json \
  --execute

echo ""
echo "=== 迁移状态监控 ==="
echo "可以通过以下命令查看进度："
echo "  kafka-reassign-partitions.sh --bootstrap-server $BROKERS \\"
echo "    --reassignment-json-file reassignment.json --verify"

# 2.4 持续监控 ISR 状态直到稳定
echo "监控 ISR 收缩情况..."
while true; do
  UNDER_REPLICATED=$(kafka-topics.sh --bootstrap-server $BROKERS --describe --under-replicated-partitions 2>/dev/null | wc -l)
  echo "$(date): 未同步分区数 = $UNDER_REPLICATED"
  [ "$UNDER_REPLICATED" -eq 0 ] && break
  sleep 30
done
echo "所有副本已同步"
```

### Layer 3 — --verify 验证 + 查看进度

```bash
#!/bin/bash
# Step 3: 验证迁移完成
BROKERS="localhost:9092"

# 3.1 核心验证命令
echo "=== 验证迁移状态 ==="
kafka-reassign-partitions.sh \
  --bootstrap-server $BROKERS \
  --reassignment-json-file reassignment.json \
  --verify

# 输出示例:
# Status of partition reassignment:
# Reassignment of partition order-events-0 is complete.
# Reassignment of partition order-events-1 is complete.
# ...

# 3.2 人工检查: 确认每个 Topic Partition 的 Replicas 分布是否正确
echo ""
echo "=== 检查最终分布 ==="
kafka-topics.sh --bootstrap-server $BROKERS --describe --topic order-events
# Topic: order-events  Partition: 0  Leader: 1  Replicas: 0,3  Isr: 0,3

# 3.3 检查 Broker 上的分区数量分布是否均衡
echo ""
echo "=== Broker 分区分布 ==="
for BROKER in 0 1 2 3 4; do
  COUNT=$(kafka-topics.sh --bootstrap-server $BROKERS --describe 2>/dev/null \
    | awk "/Replicas.*$BROKER/" | wc -l)
  echo "Broker $BROKER: 持有 $COUNT 个分区副本"
done

# 3.4 移除 throttle 限制
echo ""
echo "=== 清除 throttle 配置 ==="
for BROKER_ID in 0 1 2 3 4; do
  kafka-configs.sh --bootstrap-server $BROKERS \
    --entity-type brokers --entity-name $BROKER_ID \
    --alter --delete-config leader.replication.throttled.rate,follower.replication.throttled.rate
done
```

### Layer 4 — 迁移完成后清理旧副本

```bash
#!/bin/bash
# Step 4: 迁移完成后清理 (可选操作)
# 确认所有分区已不在旧 Broker 上后，才可安全下线旧 Broker

BROKERS="localhost:9092"

# 4.1 检查旧 Broker 上是否还持有 Leader 分区
#     (假设旧 Broker 0/1/2 上仍保留部分副本需要确认)
echo "=== 确认旧 Broker 无残留分区 ==="
for OLD_BROKER in 0 1 2; do
  REMAINING=$(kafka-topics.sh --bootstrap-server $BROKERS --describe 2>/dev/null \
    | grep "Leader: $OLD_BROKER" | wc -l)
  echo "Broker $OLD_BROKER Leader 分区数: $REMAINING"
done

# 4.2 如果确认无误，可以从 reassignment.json 中移除旧 Broker 的副本配置
#     然后重新执行一次 reassign（仅保留新 Broker 副本）

# 4.3 关闭旧 Broker (优雅下线)
echo "=== 旧 Broker 准备下线 ==="
# 确保旧 Broker 上无 Leader 分区后，逐个停止:
# kafka-server-stop.sh

# 4.4 集群清理：验证集群健康
echo "=== 下线后集群健康检查 ==="
kafka-metadata-quorum.sh --bootstrap-server $BROKERS --describe --status 2>/dev/null \
  || echo "注意：Kafka 3.3+ 使用 KRaft 模式时使用 kafka-metadata-quorum.sh"

kafka-broker-api-versions.sh --bootstrap-server $BROKERS 2>/dev/null | head -5

# 4.5 如果有 consumer 正在消费迁移过的 Topic
echo "=== Consumer Group 状态 ==="
kafka-consumer-groups.sh --bootstrap-server $BROKERS --list 2>/dev/null | while read g; do
  kafka-consumer-groups.sh --bootstrap-server $BROKERS --group "$g" --describe 2>/dev/null | head -3
done

echo "=== 迁移与清理完成 ==="
```

| 维度 | kafka-reassign-partitions | 新建 Topic + 生产者双写迁移 |
|------|--------------------------|---------------------------|
| 停机要求 | 不停服（滚动迁移） | 需要切换消费/生产（有短暂中断） |
| 数据完整性 | 副本级别同步，保证不丢 | 依赖双写逻辑，需自行校验一致性 |
| 操作复杂度 | 低：3 条命令即可完成 | 高：需修改生产者+消费者代码 |
| 迁移速度 | 受 throttle 控制，可调节 | 取决于消费/生产吞吐 |
| 磁盘占用 | 迁移期间临时翻倍 (新旧共存) | 翻倍（新老 Topic 同时存在） |
| Offset 连续性 | 完全保留，Consumer 无感知 | 需处理 offset 映射关系 |
| 回滚能力 | 重新 execute 回收旧 Broker 副本 | 切回老 Topic，丢失窗口数据 |
| 适用场景 | 集群扩容、故障 Broker 替换 | Topic 格式变更、Schema 不兼容、跨集群迁移 |
| 生产推荐 | 扩容首选方案 | 仅在 re-partition 无法满足需求时使用 |

## 一句话总结

**kafka-reassign-partitions 是 Kafka 集群扩容的核心利器，--generate 生成方案 --execute 执行迁移 --verify 验证三步走即可安全完成数据重分布，关键记住三个要点：磁盘翻倍提前检查容量、throttle 限速保护业务、低峰期执行降低影响。**
