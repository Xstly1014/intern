# Q88 监控指标体系

Kafka 核心监控围绕 **Lag（积压量）** 与 **ISR 副本状态**，RabbitMQ 核心监控围绕 **队列消息数** 与 **内存使用率**。两者均通过 Prometheus + Grafana 建立统一可观测体系，配合 **P0/P1/P2 分级告警** 实现问题快速发现与响应。

监控体系采用三层金字塔结构：底层基础设施指标（CPU、内存、磁盘、网络）是所有上层指标的基石；中层聚焦 Broker 自身健康状态，Kafka 关注 ISR、Controller、请求延迟，RabbitMQ 关注内存、连接数、Channel 数；顶层以 **Lag 积压量** 为最核心的业务指标，直接反映消费端处理能力是否匹配生产速率。告警按紧急程度分为 P0（Lag 超过 10 万需 5 分钟内响应）、P1（Lag 超过 1 万或磁盘使用率超过 80%，30 分钟内处理）、P2（趋势性异常，工作时间处理），形成逐级递进的问题发现与响应机制。

## 代码配置分层

### Layer 1 -- Kafka JMX Exporter + Prometheus 采集配置

```yaml
# jmx_exporter.yml -- Kafka JMX 指标暴露配置
startDelaySeconds: 0
hostPort: "127.0.0.1:9404"
ssl: false
lowercaseOutputName: true
lowercaseOutputLabelNames: true
rules:
  # Broker 级别指标
  - pattern: "kafka.server<type=BrokerTopicMetrics, name=(BytesInPerSec|BytesOutPerSec|MessagesInPerSec)>"
    name: "kafka_server_brokertopicmetrics_$1"
    type: GAUGE
  # ISR 收缩
  - pattern: "kafka.server<type=ReplicaManager, name=UnderReplicatedPartitions><>Value"
    name: "kafka_server_underreplicatedpartitions"
    type: GAUGE
  # Active Controller 检查
  - pattern: "kafka.controller<type=KafkaController, name=ActiveControllerCount><>Value"
    name: "kafka_controller_activecontroller"
    type: GAUGE
  # 请求延迟
  - pattern: "kafka.network<type=RequestMetrics, name=(TotalTimeMs|RequestQueueTimeMs), request=(Produce|FetchConsumer)><>50thPercentile"
    name: "kafka_network_requestmetrics_$2_$1_p50"
    type: GAUGE
  - pattern: "kafka.network<type=RequestMetrics, name=(TotalTimeMs), request=(Produce|FetchConsumer)><>99thPercentile"
    name: "kafka_network_requestmetrics_$2_$1_p99"
    type: GAUGE
```

### Layer 2 -- Kafka 核心指标 PromQL 查询

```promql
# 1. Consumer Group Lag（最核心指标）
sum(kafka_consumer_group_lag) by (consumergroup, topic, partition)
# 告警阈值: > 100000 → P0 | > 10000 → P1

# 2. ISR 收缩率（期望值 = replication.factor）
kafka_server_replicamanager_partitioncount / kafka_server_replicamanager_leadercount
# ≠ 1 时说明有副本掉线

# 3. Under-replicated Partitions（须为 0）
kafka_server_underreplicatedpartitions

# 4. Active Controller Count（须等于 1）
kafka_controller_activecontroller
# ≠ 1 时说明存在脑裂风险

# 5. 磁盘使用率
(1 - node_filesystem_avail_bytes / node_filesystem_size_bytes) * 100

# 6. 吞吐量
rate(kafka_server_brokertopicmetrics_bytesinpersec[1m])
rate(kafka_server_brokertopicmetrics_bytesoutpersec[1m])

# 7. Produce/Fetch P99 延迟
kafka_network_requestmetrics_produce_total_time_p99
kafka_network_requestmetrics_fetch_consumer_total_time_p99
```

### Layer 4 -- Alertmanager 告警规则

```yaml
# kafka_alerts.yml -- Prometheus Alert Rules
groups:
  - name: kafka_critical
    rules:
      # P0: Lag 超过 10 万 — 立即处理
      - alert: KafkaConsumerLagP0
        expr: sum(kafka_consumer_group_lag) by (consumergroup, topic) > 100000
        for: 1m
        labels:
          severity: P0
          component: kafka
        annotations:
          summary: "Consumer Lag 超过 10 万"
          description: "消费组 {{ $labels.consumergroup }} Topic {{ $labels.topic }} Lag={{ $value }}"

      # P1: ISR 收缩
      - alert: KafkaISRShrinkP1
        expr: kafka_server_replicamanager_partitioncount / kafka_server_replicamanager_leadercount != 1
        for: 2m
        labels:
          severity: P1
          component: kafka
        annotations:
          summary: "ISR 收缩，副本掉线"

      # P1: 磁盘使用率 > 80%
      - alert: KafkaDiskUsage80P1
        expr: (1 - node_filesystem_avail_bytes / node_filesystem_size_bytes) * 100 > 80
        for: 5m
        labels:
          severity: P1
          component: infra
        annotations:
          summary: "磁盘使用率超过 80%"

      # P2: Controller 脑裂
      - alert: KafkaControllerSplitBrainP2
        expr: kafka_controller_activecontroller != 1
        for: 1m
        labels:
          severity: P2
          component: kafka
        annotations:
          summary: "ActiveController 数量异常（脑裂风险）"

      # RabbitMQ P1: 内存使用率水位
      - alert: RabbitMQMemoryHighP1
        expr: rabbitmq_node_mem_used / rabbitmq_node_mem_limit > 0.8
        for: 2m
        labels:
          severity: P1
          component: rabbitmq
        annotations:
          summary: "RabbitMQ 内存使用超过 80% 水位"
```

## 指标对比：Kafka vs RabbitMQ

| 监控维度 | Kafka | RabbitMQ |
|---|---|---|
| **核心业务指标** | Consumer Group Lag 积压量 | Queue 消息数 / unacked 数 |
| **P0 告警阈值** | Lag > 100,000 | 内存高水位触发 + 磁盘剩余空间不足 |
| **副本健康** | ISR 收缩率 / Under-replicated Partitions | Mirrored Queue 同步状态 |
| **Broker 状态** | Active Controller 数量（须 = 1） | 节点内存使用率 / 磁盘剩余空间 |
| **吞吐指标** | BytesIn/Out、MessagesIn/Out 速率 | Publish/Deliver Rate |
| **延迟指标** | Produce/Fetch 请求 P99 延迟 | Queue Ingress/Egress 延迟 |
| **连接状态** | 与 ZooKeeper/KRaft 的连接状态 | 连接数 / Channel 数 / 消费者数 |
| **采集方案** | JMX Exporter（端口 :9404） | rabbitmq_exporter（端口 :9419） |
| **统一平台** | Prometheus + Grafana + Alertmanager | Prometheus + Grafana + Alertmanager |

## 一句话总结

**Kafka 监控以 Consumer Lag 和 ISR 状态为双核心，RabbitMQ 监控以队列消息数和内存使用率为重点，两者统一通过 Prometheus + Grafana 构建三层金字塔监控体系，配合 P0/P1/P2 分级告警实现从基础设施到业务的端到端可观测性。**
