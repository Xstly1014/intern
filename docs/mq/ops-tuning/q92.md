以上为 Kafka 六步滚动升级与 RabbitMQ 三步升级的流程对比。Kafka 通过 inter.broker.protocol.version 实现新旧协议兼容的"软升级"模式，RabbitMQ 则依赖集群的自动发现与 feature flags 机制。两者的核心原则一致：逐节点滚动、等待恢复、监控验证。

## 分层操作代码

### Layer 1 — 升级前检查（版本兼容性 + 元数据备份 + ZK 升级）

```bash
#!/bin/bash
# upgrade_precheck.sh — Kafka 升级前检查与准备
BROKERS="localhost:9092"

# 1.1 记录当前版本信息
echo "=== 当前集群版本 ==="
kafka-broker-api-versions.sh --bootstrap-server $BROKERS 2>/dev/null | grep -E "broker|id:|version" | head -10
echo ""
echo "inter.broker.protocol.version:"
grep -r "inter.broker.protocol.version" /etc/kafka/server.properties 2>/dev/null \
  || grep -r "inter.broker.protocol.version" /opt/kafka/config/server.properties 2>/dev/null

# 1.2 确认版本兼容性 (Kafka 官方兼容矩阵)
# 例：2.8 → 3.0 可以直接升级；2.4 → 3.0 需先升级到 2.8
echo ""
echo "=== 版本兼容性检查 ==="
CURRENT_VERSION=$(kafka-broker-api-versions.sh --bootstrap-server $BROKERS 2>/dev/null \
  | grep "broker" | awk '{print $NF}' | sort -u)
echo "当前版本: $CURRENT_VERSION"
echo "目标版本: 请参考 Kafka 官方 Upgrade Guide 确认兼容性"
echo "跨大版本升级需要中间版本过渡！"

# 1.3 备份集群元数据
echo ""
echo "=== 备份集群元数据 ==="
BACKUP_DIR="/backup/kafka/$(date +%Y%m%d_%H%M%S)"
mkdir -p $BACKUP_DIR

# 备份所有 Topic 配置
kafka-topics.sh --bootstrap-server $BROKERS --describe 2>/dev/null > "$BACKUP_DIR/topics.txt"

# 备份所有 Consumer Group Offset
kafka-consumer-groups.sh --bootstrap-server $BROKERS --list 2>/dev/null | while read g; do
  kafka-consumer-groups.sh --bootstrap-server $BROKERS --group "$g" --describe 2>/dev/null \
    > "$BACKUP_DIR/consumer_group_${g}.txt"
done

# 备份 ACL (如果启用了授权)
kafka-acls.sh --bootstrap-server $BROKERS --list 2>/dev/null > "$BACKUP_DIR/acls.txt"

# 备份 Broker 配置
cp /opt/kafka/config/server.properties "$BACKUP_DIR/server.properties.bak" 2>/dev/null
cp /etc/kafka/server.properties "$BACKUP_DIR/server.properties.bak" 2>/dev/null

echo "备份完成: $BACKUP_DIR"
ls -la "$BACKUP_DIR/"

# 1.4 ZK 模式：升级 ZooKeeper (如果使用 ZK 且需要升级)
# 如果使用 KRaft 模式 (3.3+)，跳过此步骤
echo ""
echo "=== ZK 升级 (如适用) ==="
echo "逐个 ZK 节点升级: stop → 替换 jar → start → 等 quorum 稳定"
# zkServer.sh stop → 替换 ZK 版本包 → zkServer.sh start

# 1.5 通知所有相关方
echo ""
echo "=== 升级窗口通知 ==="
echo "升级窗口: YYYY-MM-DD HH:00 ~ HH:30 (业务低峰期)"
echo "影响: 无停机，可能有短暂 Leader 切换"
```

### Layer 2 — Kafka 逐个 Broker 滚动升级脚本

```bash
#!/bin/bash
# kafka_rolling_upgrade.sh — 逐个 Broker 滚动升级
# 用法: ./kafka_rolling_upgrade.sh <broker_id> <kafka_new_path>

set -e
BROKER_ID=$1
KAFKA_NEW=$2
KAFKA_CURRENT="/opt/kafka/current"
LOG_DIR="/var/log/kafka"
BROKERS="broker1:9092,broker2:9092,broker3:9092"

echo "========================================="
echo "Kafka 滚动升级: Broker $BROKER_ID"
echo "========================================="

# 2.1 记录升级前状态
echo "升级前 ISR 状态:"
kafka-topics.sh --bootstrap-server $BROKERS --describe --under-replicated-partitions 2>/dev/null

# 2.2 触发 Leader 迁移 (优雅地将 Leader 从当前 Broker 迁走)
echo "触发 Leader 迁移..."
# 注意: controlled shutdown 会自动迁移 Leader
# 也可以手动触发 Preferred Leader Election:
# kafka-leader-election.sh --bootstrap-server $BROKERS --election-type preferred --all-topic-partitions

# 2.3 停止当前 Broker (优雅关闭)
echo "停止 Broker $BROKER_ID..."
kafka-server-stop.sh
sleep 10

# 等待 Broker 完全关闭
while pgrep -f "kafka.Kafka.*broker.id=$BROKER_ID" > /dev/null 2>&1; do
  echo "等待 Broker $BROKER_ID 完全关闭..."
  sleep 5
done
echo "Broker $BROKER_ID 已停止"

# 2.4 备份旧版本
echo "备份旧版本..."
cp -r $KAFKA_CURRENT "${KAFKA_CURRENT}.bak.$(date +%Y%m%d)"

# 2.5 替换为新版本二进制
echo "安装新版本 Kafka..."
rm -rf $KAFKA_CURRENT
cp -r $KAFKA_NEW $KAFKA_CURRENT

# 复制配置文件到新版本
cp "${KAFKA_CURRENT}.bak."*/config/server.properties "$KAFKA_CURRENT/config/" 2>/dev/null || true

# 2.6 更新 inter.broker.protocol.version (如果升级涉及协议变更)
# 注意: 先不改 protocol.version，等所有 Broker 升级完毕后再 finalize
echo "注意: inter.broker.protocol.version 保持旧版本值，待所有 Broker 升级完毕后统一 finalize"

# 2.7 启动 Broker
echo "启动 Broker $BROKER_ID..."
kafka-server-start.sh -daemon "$KAFKA_CURRENT/config/server.properties"

# 2.8 等待 Broker 加入集群
echo "等待 Broker $BROKER_ID 加入集群..."
sleep 15
MAX_WAIT=300  # 最多等 5 分钟
WAITED=0
while ! kafka-broker-api-versions.sh --bootstrap-server $BROKERS 2>/dev/null \
  | grep -q "id: $BROKER_ID"; do
  echo "等待 Broker $BROKER_ID 注册到集群... ($WAITED s)"
  sleep 10
  WAITED=$((WAITED + 10))
  if [ $WAITED -ge $MAX_WAIT ]; then
    echo "ERROR: Broker $BROKER_ID 启动超时!"
    exit 1
  fi
done
echo "Broker $BROKER_ID 已加入集群"

# 2.9 等待 ISR 恢复
echo "等待 ISR 恢复..."
MAX_ISR_WAIT=600  # 最多等 10 分钟
ISR_WAITED=0
while true; do
  UNDER_REP=$(kafka-topics.sh --bootstrap-server $BROKERS \
    --describe --under-replicated-partitions 2>/dev/null | wc -l)
  echo "Under-replicated partitions: $UNDER_REP (${ISR_WAITED}s)"
  if [ "$UNDER_REP" -eq 0 ]; then
    echo "ISR 已完全恢复!"
    break
  fi
  sleep 15
  ISR_WAITED=$((ISR_WAITED + 15))
  if [ $ISR_WAITED -ge $MAX_ISR_WAIT ]; then
    echo "WARNING: ISR 恢复超时，请手动检查!"
    break
  fi
done

echo "========================================="
echo "Broker $BROKER_ID 升级完成！"
echo "========================================="
echo "请确认稳定后继续升级下一个 Broker"
```

### Layer 3 — Finalize 完成化（inter.broker.protocol.version）

```bash
#!/bin/bash
# kafka_finalize.sh — 升级完成化: 更新协议版本
BROKERS="localhost:9092"
NEW_METADATA_VERSION="3.7"  # 示例: 升级到 Kafka 3.7
NEW_PROTOCOL_VERSION="3.7"

echo "========================================="
echo "Kafka 升级 Finalize 完成化"
echo "========================================="

# 3.1 确认所有 Broker 已升级
echo "=== Broker 版本检查 ==="
kafka-broker-api-versions.sh --bootstrap-server $BROKERS 2>/dev/null \
  | grep -E "id:|broker" | sort

# 3.2 更新 inter.broker.protocol.version (逐个 Broker 动态更新)
echo ""
echo "=== 更新 inter.broker.protocol.version ==="
for BROKER in 0 1 2; do
  echo "更新 Broker $BROKER 的 protocol.version..."
  kafka-configs.sh --bootstrap-server $BROKERS \
    --entity-type brokers --entity-name $BROKER \
    --alter --add-config \
    inter.broker.protocol.version=$NEW_PROTOCOL_VERSION
  
  # 等待生效
  sleep 5
done

# 3.3 使用 kafka-features.sh 完成化 (Kafka 2.8+ / KRaft 模式)
echo ""
echo "=== kafka-features finalize ==="
kafka-features.sh --bootstrap-server $BROKERS describe
echo ""
echo "执行 finalize:"
kafka-features.sh --bootstrap-server $BROKERS \
  upgrade --feature metadata.version=$NEW_METADATA_VERSION

# 确认完成化结果
echo ""
echo "=== Finalize 后状态 ==="
kafka-features.sh --bootstrap-server $BROKERS describe

# 3.4 更新 log.message.format.version (如果需要)
echo ""
echo "=== 更新 log.message.format.version ==="
for BROKER in 0 1 2; do
  kafka-configs.sh --bootstrap-server $BROKERS \
    --entity-type brokers --entity-name $BROKER \
    --alter --add-config \
    log.message.format.version=$NEW_PROTOCOL_VERSION
done

# 3.5 逐个重启 Broker 使新 protocol.version 生效
echo ""
echo "=== 逐个重启 Broker 以激活新 protocol ==="
for BROKER in 0 1 2; do
  echo "重启 Broker $BROKER..."
  # 使用滚动升级脚本中的重启逻辑
  kafka-server-stop.sh  # 针对特定 Broker
  sleep 5
  kafka-server-start.sh -daemon /opt/kafka/config/server.properties
  sleep 10
  
  echo "等待 ISR 恢复..."
  while [ $(kafka-topics.sh --bootstrap-server $BROKERS \
    --describe --under-replicated-partitions 2>/dev/null | wc -l) -gt 0 ]; do
    sleep 10
  done
  echo "Broker $BROKER 重启完成"
done

# 3.6 最终验证
echo ""
echo "=== 最终验证 ==="
echo "1. Broker 版本:"
kafka-broker-api-versions.sh --bootstrap-server $BROKERS 2>/dev/null | grep "broker"

echo ""
echo "2. ISR 状态:"
kafka-topics.sh --bootstrap-server $BROKERS --describe --under-replicated-partitions 2>/dev/null \
  | head -10

echo ""
echo "3. Consumer Group 滞后:"
kafka-consumer-groups.sh --bootstrap-server $BROKERS --list 2>/dev/null | while read g; do
  echo "Group: $g"
  kafka-consumer-groups.sh --bootstrap-server $BROKERS --group "$g" --describe 2>/dev/null | head -3
done

echo ""
echo "========================================="
echo "升级完成！Kafka 已运行在版本 $NEW_PROTOCOL_VERSION"
echo "========================================="
```

### Layer 4 — RabbitMQ 滚动升级脚本

```bash
#!/bin/bash
# rabbitmq_rolling_upgrade.sh — RabbitMQ 逐个节点滚动升级
NODE=$1  # rabbit@node1, rabbit@node2, rabbit@node3

echo "========================================="
echo "RabbitMQ 滚动升级: $NODE"
echo "========================================="

# 4.1 升级前备份定义
echo "=== 备份集群定义 ==="
BACKUP_FILE="/backup/rabbitmq/definitions_$(date +%Y%m%d_%H%M%S).json"
rabbitmqctl export_definitions "$BACKUP_FILE"
echo "定义已备份到: $BACKUP_FILE"

# 4.2 检查集群状态
echo ""
echo "=== 升级前集群状态 ==="
rabbitmqctl cluster_status | grep -E "Cluster name|Nodes|Running"
rabbitmqctl list_queues name messages consumers state 2>/dev/null | head -10

# 4.3 优雅停止当前节点
echo ""
echo "=== 停止节点 $NODE ==="
rabbitmqctl stop_app
echo "节点 $NODE 已停止应用"

# 4.4 升级 RabbitMQ 二进制
echo ""
echo "=== 升级 RabbitMQ 二进制 ==="
# 根据操作系统选择升级方式:
# RHEL/CentOS: rpm -Uvh rabbitmq-server-<version>.rpm
# Debian/Ubuntu: dpkg -i rabbitmq-server_<version>_all.deb
# 通用: 停止后替换 /usr/lib/rabbitmq 目录
echo "请在此停止 RabbitMQ 服务并升级安装包..."
# systemctl stop rabbitmq-server  (或 rabbitmqctl stop)
# rpm -Uvh rabbitmq-server-NEW.rpm
# 或 dpkg -i rabbitmq-server_NEW_all.deb

# 4.5 启动节点
echo ""
echo "=== 启动节点 $NODE ==="
# systemctl start rabbitmq-server  (或 rabbitmq-server -detached)
sleep 5

# 启动应用
rabbitmqctl start_app
echo "节点 $NODE 应用已启动"

# 4.6 等待节点加入集群
echo ""
echo "=== 等待集群同步 ==="
sleep 10
for i in $(seq 1 30); do
  if rabbitmqctl cluster_status | grep -q "$NODE.*running"; then
    echo "节点 $NODE 已加入集群并运行"
    break
  fi
  echo "等待中... ($((i * 5))s)"
  sleep 5
done

# 4.7 验证节点升级后状态
echo ""
echo "=== 升级后验证 ==="
rabbitmqctl status | grep -E "RabbitMQ version|Erlang|Uptime"
rabbitmqctl cluster_status | grep -E "Nodes|Running"

echo ""
echo "=== Queues 验证 ==="
rabbitmqctl list_queues name messages consumers state | head -10

echo ""
echo "========================================="
echo "节点 $NODE 升级完成"
echo "========================================="
echo "请确认队列镜像同步完成后再升级下一个节点"

# 4.8 升级完成后的 feature flags 管理
echo ""
echo "提示: 所有节点升级完成后启用新版本 feature flags:"
echo "  rabbitmqctl list_feature_flags"
echo "  rabbitmqctl enable_feature_flag <feature_name>"
```

| 维度 | Kafka | RabbitMQ |
|------|-------|----------|
| 升级方式 | 逐个 Broker 滚动升级 | 逐个节点 stop_app / start_app |
| 停机时间 | 零停机（单 Broker 下线时由其他 Broker 接管） | 零停机（集群模式，队列镜像切换） |
| 协议兼容 | inter.broker.protocol.version 保证新旧兼容 | 通过 feature flags 逐步启用新特性 |
| 完成化步骤 | finalize 更新 metadata.version | 启用 feature flags |
| Leader 切换 | 自动触发 Leader 重选举 | 队列主副本自动迁移 |
| 回滚方式 | 替换回旧二进制 + protocol.version 回退 | 重装旧版本 + import_definitions |
| 跨大版本 | 可能需要中间版本过渡（如 2.4→2.8→3.0） | 建议逐版本升级，不跳过中间版本 |
| 元数据备份 | 备份 Topic 配置 + Consumer Offset + ACL | export_definitions 导出 JSON |
| 空闲磁盘要求 | 无需额外磁盘（仅替换二进制） | 无需额外磁盘 |
| 监控重点 | ISR 恢复、under-replicated、Consumer Lag | 队列主从同步、内存/磁盘水位 |
| 前置依赖 | ZK 集群先升级（如适用） | Erlang 版本需与新 RabbitMQ 兼容 |

## 一句话总结

**Kafka 和 RabbitMQ 的滚动升级均遵循"逐节点升级、等待恢复、最后完成化"三阶段模式，核心区别在于 Kafka 通过 inter.broker.protocol.version 维持协议兼容性需 double restart，而 RabbitMQ 通过 stop_app/start_app 和 feature flags 实现更轻量的升级流程，无论哪种方案，先测试、备份、低峰期、保留回滚、持续监控五项黄金法则缺一不可。**
