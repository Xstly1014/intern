# Q90 生产环境调优参数

Kafka 生产环境调优围绕 Producer（可靠性+吞吐）、Broker（集群稳定性）和 Consumer（消费效率）三个维度展开，核心参数如 acks=all、enable.idempotence=true、min.insync.replicas=2 必须显式配置，默认值在大多数生产场景下不够安全。

以上参数按生产环境优先级排列：可靠性类参数（蓝色）必须首先保证，吞吐类参数（绿色）在可靠性基础上按需调整，延迟与稳定性参数（橙色）用于精细化控制和异常防护。

## 分层配置代码

### Layer 1 — Producer 全参数配置 (Spring Kafka)

```yaml
# application.yml — Spring Kafka Producer 生产级配置
spring:
  kafka:
    producer:
      # === 可靠性 ===
      acks: all                              # 等待所有 ISR 副本确认
      properties:
        enable.idempotence: true             # 幂等生产者，防止重复
      retries: 2147483647                    # Integer.MAX_VALUE，无限重试
      # === 吞吐 ===
      batch-size: 65536                      # 批量发送大小 64KB
      properties:
        linger.ms: 10                        # 等待 10ms 凑批
        compression.type: zstd               # zstd 高压缩比
      # === 并发控制 ===
      properties:
        max.in.flight.requests.per.connection: 5  # 保证顺序 + 并发
      # === 超时 ===
      properties:
        delivery.timeout.ms: 120000          # 120s 投递超时
        request.timeout.ms: 30000            # 30s 请求超时
      # === 缓冲区 ===
      buffer-memory: 33554432                # 32MB 发送缓冲区
      key-serializer: org.apache.kafka.common.serialization.StringSerializer
      value-serializer: org.apache.kafka.common.serialization.StringSerializer
```

### Layer 2 — Broker server.properties 关键配置

```properties
# server.properties — Kafka Broker 生产级配置
# === 网络 & IO 线程 ===
num.network.threads=8              # 处理网络请求的线程数
num.io.threads=16                  # 处理磁盘 IO 的线程数
# === 日志保留 ===
log.retention.hours=168            # 保留 7 天
log.segment.bytes=1073741824       # 1GB 分段
log.retention.check.interval.ms=300000  # 5 分钟检查一次
# === 副本 & Leader 选举 ===
min.insync.replicas=2              # 最小 ISR 数，配合 acks=all
unclean.leader.election.enable=false  # 禁止非同步副本当选 Leader
# === Topic 控制 ===
auto.create.topics.enable=false    # 禁止自动创建 Topic
delete.topic.enable=true           # 允许删除 Topic
# === 日志刷盘 ===
log.flush.interval.messages=10000  # 每 1w 条消息刷盘
log.flush.interval.ms=1000         # 每 1s 刷盘
# === Socket ===
socket.send.buffer.bytes=102400    # 100KB 发送缓冲
socket.receive.buffer.bytes=102400 # 100KB 接收缓冲
socket.request.max.bytes=104857600 # 100MB 最大请求
```

### Layer 3 — Consumer 全参数配置

```yaml
# application.yml — Spring Kafka Consumer 生产级配置
spring:
  kafka:
    consumer:
      # === 手动提交 ===
      enable-auto-commit: false
      # === 拉取控制 ===
      max-poll-records: 500                    # 每批最多 500 条
      # === 超时 ===
      properties:
        session.timeout.ms: 30000              # 30s 会话超时
        max.poll.interval.ms: 300000           # 5min 拉取间隔
        heartbeat.interval.ms: 3000            # 3s 心跳间隔
        request.timeout.ms: 30000              # 30s 请求超时
      # === Offset 策略 ===
      auto-offset-reset: latest                # 新 consumer group 从最新开始
      # === 拉取大小 ===
      fetch-min-size: 1                        # 最小 1 字节即返回
      fetch-max-wait: 500                      # 最多等 500ms
      max-partition-fetch-bytes: 1048576       # 每分区 1MB
      # === 反序列化 ===
      key-deserializer: org.apache.kafka.common.serialization.StringDeserializer
      value-deserializer: org.apache.kafka.common.serialization.StringDeserializer
```

### Layer 4 — 调优检查清单 (Shell 诊断脚本)

```bash
#!/bin/bash
# kafka_checkup.sh — 快速检查当前集群配置是否符合推荐值
BROKERS="broker1:9092,broker2:9092,broker3:9092"
echo "========== Kafka 调优检查 =========="

# 1. 检查 Producer 关键配置
echo "[Producer] acks 配置:"
kafka-configs.sh --bootstrap-server $BROKERS \
  --entity-type brokers --describe 2>/dev/null | grep -E "acks|idempotence" || echo "  请确认 client 端配置"

# 2. 检查 Broker 配置
echo ""
echo "[Broker] 关键服务端配置:"
for BROKER in 0 1 2; do
  echo "--- Broker $BROKER ---"
  kafka-configs.sh --bootstrap-server $BROKERS \
    --entity-type brokers --entity-name $BROKER --describe 2>/dev/null \
    | grep -E "num.network.threads|num.io.threads|min.insync.replicas|log.retention|unclean|auto.create"
done

# 3. 检查 Consumer Group 状态
echo ""
echo "[Consumer] Group 滞后检查:"
kafka-consumer-groups.sh --bootstrap-server $BROKERS --list 2>/dev/null | while read g; do
  LAG=$(kafka-consumer-groups.sh --bootstrap-server $BROKERS --group "$g" --describe 2>/dev/null \
    | tail -n +3 | awk '{sum+=$6} END {print sum}')
  [ "$LAG" -gt 1000 ] && echo "  WARN: Group $g LAG=$LAG (>1000)"
done

# 4. Topic 副本分布检查
echo ""
echo "[Topic] 副本分布:"
kafka-topics.sh --bootstrap-server $BROKERS --describe 2>/dev/null \
  | awk 'NR>1 {print $1, "Replicas="$3, "ISR="$4}' | head -10

echo "========== 检查完成 =========="
```

## 一句话总结

**Kafka 生产环境调优的核心是"可靠性优先"：Producer 端 acks=all + 幂等确保不丢不重，Broker 端 min.insync.replicas=2 + 禁止非同步选举防止脑裂丢数据，Consumer 端手动提交 + 合理超时避免 rebalance 风暴，三端协同才能构建健壮的流处理通道。**
