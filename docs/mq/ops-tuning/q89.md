# Q89 RabbitMQ 内存管理

RabbitMQ 内存管理核心是 **vm_memory_high_watermark** 水位线机制，默认值 **0.4（总内存 40%）** 时触发流控阻塞生产者以保护系统。配合 **prefetch、max-length、持久化** 等策略优化内存使用，并结合 **disk_free_limit** 防止磁盘耗尽，是实现 RabbitMQ 生产级稳定运行的关键。

RabbitMQ 内存管理以 **vm_memory_high_watermark** 水位线为核心控制点。内存使用率在 0% 至 40% 区间时系统正常运行，生产者与消费者均不受限制。当突破 40% 阈值时，Broker 进入 **Flow Control** 状态，阻塞所有新的生产者发布请求（消费者仍可正常消费，以排空队列释放内存）。若进一步升至 70%，则采取更激进的阻塞策略。内存占用主要由 unacked 消息（约 35%）、队列待消费消息（约 25%）、元数据结构（约 20%）和系统开销构成。三种优化策略分别针对不同内存来源：prefetch 减少 unacked 积压、max-length 限制队列长度、持久化让 Broker 将消息刷盘释放内存。同时，**disk_free_limit** 提供磁盘层面的保护，与内存水位线形成双重保障机制。

## 代码配置分层

### Layer 1 -- vm_memory_high_watermark 水位线核心配置

```erlang
%% rabbitmq.conf -- 内存水位线配置方式一：相对值（推荐）
vm_memory_high_watermark.relative = 0.4
%% 总内存 40% 触发 flow control，阻塞生产者连接

%% 方式二：绝对值（固定数值）
vm_memory_high_watermark.absolute = 2GB
%% 内存使用达到 2GB 时触发阻塞

%% 方式三：高级配置 — vm_memory_high_watermark_paging_ratio
%% 从 50% 水位开始将队列消息 paging 到磁盘
vm_memory_high_watermark_paging_ratio = 0.5
%% 默认值 0.5，即 watermark 的 50% 处开始 paging
%% 当 watermark=0.4 时，内存 20% 即开始预 paging

%% 环境变量方式（旧版兼容）
%% RABBITMQ_VM_MEMORY_HIGH_WATERMARK=0.4
```

### Layer 2 -- prefetch + max-length 内存优化配置

```python
# consumer.py -- 消费者 prefetch 减少 unacked 消息积压
import pika

connection = pika.BlockingConnection(
    pika.ConnectionParameters(host='localhost')
)
channel = connection.channel()

# 关键：设置 prefetch_count 限制消费者未确认消息数
# 默认值为 0（无限制），会导致 unacked 消息持续堆积占满内存
channel.basic_qos(prefetch_count=50)

def callback(ch, method, properties, body):
    # 业务处理逻辑
    process_message(body)
    # 手动确认，释放 Broker 侧 unacked 内存
    ch.basic_ack(delivery_tag=method.delivery_tag)

channel.basic_consume(
    queue='task_queue',
    on_message_callback=callback,
    auto_ack=False  # 必须设为 False，手动 ack
)
channel.start_consuming()
```

```python
# queue_declare.py -- 队列 max-length 限制与持久化
import pika

connection = pika.BlockingConnection(
    pika.ConnectionParameters(host='localhost')
)
channel = connection.channel()

# 声明队列时设置 max-length 和持久化参数
channel.queue_declare(
    queue='bounded_queue',
    durable=True,                        # 队列持久化（Broker 重启不丢失）
    arguments={
        'x-max-length': 10000,          # 最大消息数，超出后 drop-head
        'x-max-length-bytes': 104857600,# 可选：最大字节数（100MB）
        'x-overflow': 'drop-head',      # 溢出策略：丢弃最早消息
        # 'x-overflow': 'reject-publish' # 备选：拒绝新发布
    }
)

# 发布持久化消息
channel.basic_publish(
    exchange='',
    routing_key='bounded_queue',
    body='Hello World',
    properties=pika.BasicProperties(
        delivery_mode=2  # 消息持久化到磁盘，允许 Broker 释放内存
    )
)
```

### Layer 4 -- disk_free_limit 磁盘保护配置

```erlang
%% rabbitmq.conf -- 磁盘空间保护配置

%% 方式一：绝对值（默认 50MB）
disk_free_limit.absolute = 50MB

%% 方式二：相对值（推荐 — 与磁盘大小联动）
%% 当磁盘剩余空间低于总磁盘空间的 5% 时触发阻塞
disk_free_limit.relative = 0.05

%% 方式三：按内存倍数设置
%% RabbitMQ 3.8+ 支持：当自由空间低于 1.0 * 内存大小时触发
disk_free_limit.absolute = {mem_relative, 1.0}

%% 环境变量方式（旧版兼容）
%% DISK_FREE_LIMIT=50000000
```

```yaml
# Prometheus 告警规则 — 内存与磁盘联动告警
groups:
  - name: rabbitmq_memory_disk
    rules:
      # 内存接近水位线 — 预警
      - alert: RabbitMQMemoryNearWatermark
        expr: rabbitmq_node_mem_used / rabbitmq_node_mem_limit > 0.85
        for: 2m
        labels:
          severity: P1
          component: rabbitmq
        annotations:
          summary: "RabbitMQ 内存使用率 {{ $value | humanizePercentage }}，接近水位线"

      # 内存告警已触发 — flow control 生效
      - alert: RabbitMQMemoryAlarmActive
        expr: rabbitmq_node_mem_alarm > 0
        for: 1m
        labels:
          severity: P0
          component: rabbitmq
        annotations:
          summary: "RabbitMQ 内存告警已触发，生产者已被阻塞"

      # 磁盘空间不足 — 即将触发保护
      - alert: RabbitMQDiskSpaceLow
        expr: rabbitmq_disk_space_free < rabbitmq_disk_space_free_limit * 2
        for: 2m
        labels:
          severity: P1
          component: rabbitmq
        annotations:
          summary: "RabbitMQ 磁盘剩余空间不足，即将阻塞生产者"
```

## 内存水位线配置对比

| 配置维度 | watermark=0.4（默认） | watermark=0.6 | watermark=0.9（不推荐） |
|---|---|---|---|
| **触发时机** | 内存使用达总内存 40% | 内存使用达总内存 60% | 内存使用达总内存 90% |
| **安全边际** | 高，剩余 60% 缓冲空间 | 中，剩余 40% 缓冲空间 | 极低，仅剩余 10% |
| **生产者阻塞频率** | 较早触发，短期内可能频繁 flow control | 中等，延迟触发但缓冲更小 | 极晚触发，几乎不阻塞 |
| **OOM 风险** | 低，Erlang GC 在 40% 时效率高 | 中等，GC 开始承压 | 高，Erlang GC 在高内存下效率骤降 |
| **paging 开始时机** | 内存 20%（0.4 * 0.5）时 paging | 内存 30%（0.6 * 0.5）时 paging | 内存 45%（0.9 * 0.5）时 paging |
| **适用场景** | 通用生产环境，多节点集群 | 大内存独占节点（32GB+），内存敏感应用 | **仅测试环境**，生产绝对禁止 |
| **消费者体验** | 略有阻塞但保护稳定，消费持续 | 阻塞较晚，但风险加大 | 看似无阻塞，实则 OOM 风险极高 |
| **推荐等级** | 强烈推荐 | 有条件使用（大内存 + 充分压测） | 强烈不推荐 |

## 一句话总结

**RabbitMQ 内存管理通过 vm_memory_high_watermark（推荐 0.4-0.6）在内存达到阈值时阻塞生产者实现自我保护，配合 prefetch 限流减少 unacked 积压、max-length 限制队列长度、持久化刷盘释放内存三大策略，以及 disk_free_limit 磁盘空间保护形成双重防线，是实现 RabbitMQ 生产级稳定运行的核心运维配置。**
