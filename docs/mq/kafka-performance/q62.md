# Q62 批量发送

Kafka Producer 将消息按 Topic-Partition 在内存 accumulator 中累积成 Batch 后一次性发送，通过 `batch.size` 和 `linger.ms` 两个参数协同控制触发时机，以此权衡延迟与吞吐——任一条件满足即触发发送，是 Kafka 高吞吐的核心设计之一。

上图展示了 Kafka Producer 批量发送的完整链路：消息经 Serializer 和 Partitioner 后进入 RecordAccumulator，按 Topic-Partition 分组成 Deque 队列，累积到 ProducerBatch 中。两个触发条件--batch.size（16KB 满即发）和 linger.ms（5ms 超时即发）--以 OR 逻辑协同工作。右侧对比清晰地展示了批量发送将 N 次网络调用合并为 1 次，大幅提升吞吐。

## 批量发送代码配置

### Layer 1 -- Producer 批量核心配置

```java
@Configuration
public class KafkaProducerConfig {

    @Bean
    public ProducerFactory<String, String> producerFactory() {
        Map<String, Object> props = new HashMap<>();
        props.put(ProducerConfig.BOOTSTRAP_SERVERS_CONFIG, "localhost:9092");
        props.put(ProducerConfig.KEY_SERIALIZER_CLASS_CONFIG, StringSerializer.class);
        props.put(ProducerConfig.VALUE_SERIALIZER_CLASS_CONFIG, StringSerializer.class);

        // 批量发送核心配置
        props.put(ProducerConfig.BATCH_SIZE_CONFIG, 16384);         // 16KB，每个 Batch 上限
        props.put(ProducerConfig.LINGER_MS_CONFIG, 5);              // 等待 5ms，攒更多消息
        props.put(ProducerConfig.BUFFER_MEMORY_CONFIG, 33554432);   // 32MB，accumulator 总缓冲区

        return new DefaultKafkaProducerFactory<>(props);
    }

    @Bean
    public KafkaTemplate<String, String> kafkaTemplate() {
        return new KafkaTemplate<>(producerFactory());
    }
}
```

### Layer 3 -- RecordAccumulator 内部工作机制

```java
/**
 * Kafka 源码简化版：RecordAccumulator.append()
 * 展示消息如何进入 Batch 队列
 */
public class RecordAccumulator {

    // key: TopicPartition, value: Deque<ProducerBatch>
    private final ConcurrentMap<TopicPartition, Deque<ProducerBatch>> batches;

    public RecordAppendResult append(TopicPartition tp, long timestamp,
                                      byte[] key, byte[] value,
                                      Callback callback, long maxTimeToBlock) {
        // 1. 获取或创建该 TopicPartition 的 Batch 队列
        Deque<ProducerBatch> dq = getOrCreateDeque(tp);

        synchronized (dq) {
            // 2. 尝试向最后一个 Batch 追加消息
            ProducerBatch last = dq.peekLast();
            if (last != null) {
                FutureRecordMetadata future = last.tryAppend(timestamp, key, value, callback);
                if (future != null) {
                    return new RecordAppendResult(future, false, dq.size() > 1);
                }
            }
        }

        // 3. 当前 Batch 已满（>= batch.size）或为 null，创建新 Batch
        int size = Math.max(key.length + value.length, RecordsBatch.RECORDS_HEADER_SIZE);
        int maxSize = Math.max(batchSize, size);  // batchSize 是上限非下限
        buffer = free.allocate(maxSize, maxTimeToBlock);

        synchronized (dq) {
            ProducerBatch batch = new ProducerBatch(tp, buffer, maxSize);
            FutureRecordMetadata future = batch.tryAppend(timestamp, key, value, callback);
            dq.addLast(batch);
            return new RecordAppendResult(future, dq.size() > 1, false);
        }
    }

    // Sender 线程唤醒条件：
    // 1. Batch 满了 → 立即唤醒 Sender
    // 2. linger.ms 定时器到期 → Sender 线程超时发送
}
```

### Layer 4 -- 监控批量发送效果

```java
/**
 * 通过 Spring Boot Actuator + Micrometer 监控 Producer 批量发送效果
 */
@Component
public class ProducerBatchMetrics {

    private final KafkaTemplate<String, String> kafkaTemplate;

    public ProducerBatchMetrics(KafkaTemplate<String, String> kafkaTemplate) {
        this.kafkaTemplate = kafkaTemplate;
    }

    /**
     * 定时打印 Producer Metrics，观察批量效果
     * 关键指标:
     *   batch-size-avg  : 平均 Batch 大小，越大批量化越充分
     *   batch-size-max  : 最大 Batch 大小
     *   records-per-request-avg : 每次网络请求携带的平均消息数
     *   buffer-available-bytes  : accumulator 剩余缓冲区
     */
    @Scheduled(fixedDelay = 10000)
    public void printProducerMetrics() {
        kafkaTemplate.executeInTransaction(producer -> {
            producer.metrics().forEach((name, metric) -> {
                String metricName = name.name();
                if (metricName.contains("batch-size") ||
                    metricName.contains("records-per-request") ||
                    metricName.contains("buffer")) {
                    System.out.printf("[Producer Metrics] %s = %.2f%n",
                            metricName, metric.metricValue());
                }
            });
            return null;
        });
    }

    /**
     * JMX / Prometheus 暴露指标示例
     * curl http://localhost:8080/actuator/metrics/kafka.producer.batch-size-avg
     */
    @EventListener(ApplicationReadyEvent.class)
    public void logConfig() {
        log.info("批量发送已启用: batch.size={}, linger.ms={}",
                "16384", "5");
    }
}
```

| 维度 | 低延迟配置 | 高吞吐配置 | 均衡配置 |
|------|-----------|-----------|---------|
| **batch.size** | 16KB（默认） | 64KB - 128KB | 32KB |
| **linger.ms** | 0（立即发送） | 5 - 50ms | 3 - 10ms |
| **buffer.memory** | 32MB（默认） | 64MB - 128MB | 32MB - 64MB |
| **网络调用次数** | 高（每条/小批） | 低（大批次合并） | 中 |
| **端到端延迟** | 毫秒级（~1ms） | 十毫秒级（~10ms） | 数毫秒（~5ms） |
| **吞吐量** | 低 | 高（提升 5-10x） | 中高 |
| **CPU 开销** | 较高（频繁网络 IO） | 低（批量处理） | 中 |
| **适用场景** | 实时交易、即时通知 | 日志采集、埋点上报 | 通用业务消息 |

## 一句话总结

**batch.size 决定 Batch 的上限（不是下限），linger.ms 决定等待的上限，两者以 OR 逻辑协同——任一条件满足即触发 Sender 线程发送，调优的核心是在可接受的延迟增量内最大化批量效果。**
