# Q64 分区并行

Partition 是 Kafka 并行的基本单位，端到端并行度由 `min(Partition 数, Consumer 数)` 决定，12 个 Partition 分布在 3 个 Broker 上时，3 个 Producer 线程可并发写入、12 个 Consumer 可独立消费，整体并行度达到 12，且超过 Partition 数的 Consumer 将处于空闲状态。

## 分区并行代码配置

### Layer 1 -- Producer 多线程并行发送

```java
@Configuration
public class KafkaParallelProducerConfig {

    @Bean
    public KafkaTemplate<String, String> kafkaTemplate() {
        Map<String, Object> props = new HashMap<>();
        props.put(ProducerConfig.BOOTSTRAP_SERVERS_CONFIG, "localhost:9092,localhost:9093,localhost:9094");
        props.put(ProducerConfig.KEY_SERIALIZER_CLASS_CONFIG, StringSerializer.class);
        props.put(ProducerConfig.VALUE_SERIALIZER_CLASS_CONFIG, StringSerializer.class);
        props.put(ProducerConfig.BATCH_SIZE_CONFIG, 32768);
        props.put(ProducerConfig.LINGER_MS_CONFIG, 5);

        ProducerFactory<String, String> factory = new DefaultKafkaProducerFactory<>(props);
        return new KafkaTemplate<>(factory);
    }
}

/**
 * Producer 并行发送示例：多线程 + 不同 key 路由到不同 Partition
 * 通过 hash(key) % partitionCount 实现并行写入
 */
@Component
public class ParallelProducerService {

    private final KafkaTemplate<String, String> kafkaTemplate;

    // 线程池 3 个线程，模拟多 Producer 线程并发
    private final ExecutorService executor = Executors.newFixedThreadPool(3);

    public ParallelProducerService(KafkaTemplate<String, String> kafkaTemplate) {
        this.kafkaTemplate = kafkaTemplate;
    }

    public void sendMessagesInParallel() {
        // 不同 key 会被 hash 到不同 Partition，实现并行写入
        String[] keys = {"user-A", "user-B", "user-C"};

        for (int i = 0; i < keys.length; i++) {
            final String key = keys[i];
            final int index = i;
            executor.submit(() -> {
                for (int j = 0; j < 100; j++) {
                    kafkaTemplate.send("order-topic", key, "message-" + index + "-" + j);
                }
            });
        }
    }
}
```

### Layer 2 -- Broker 端分区分布

```bash
# ========== 创建 Topic: 12 个 Partition, 3 个 Replica ==========

  --topic order-topic \
  --partitions 12 \
  --replication-factor 3 \
```

### Layer 3 -- Consumer Group 并行消费

```java
/**
 * Consumer 并行消费配置
 * concurrency 参数控制每个 @KafkaListener 创建的消费者线程数
 * 注意: concurrency <= 分配的 Partition 数，否则多余线程空闲
 */
@Component
public class ParallelConsumerService {

    /**
     * 方式 1: @KafkaListener concurrency 参数
     * 创建 6 个消费者线程，每个消费 2 个 Partition (12/6=2)
     */
    @KafkaListener(
        topics = "order-topic",
        groupId = "order-consumer-group",
        concurrency = "6"  // 6 个消费者线程，每个线程消费 2 个 Partition
    )
    public void consumeWithConcurrency(@Payload String message,
                                        @Header(KafkaHeaders.RECEIVED_PARTITION) int partition,
                                        @Header(KafkaHeaders.RECEIVED_TOPIC) String topic) {
        log.info("Thread={} | Topic={} | Partition={} | Message={}",
                Thread.currentThread().getName(), topic, partition, message);
        processMessage(message);
    }

    /**
     * 方式 2: ConcurrentKafkaListenerContainerFactory 线程池配置
     * 显式控制并发消费者数量
     */
    @Bean
    public ConcurrentKafkaListenerContainerFactory<String, String>
            parallelContainerFactory(ConsumerFactory<String, String> consumerFactory) {

        ConcurrentKafkaListenerContainerFactory<String, String> factory =
                new ConcurrentKafkaListenerContainerFactory<>();
        factory.setConsumerFactory(consumerFactory);

        // 关键配置：并发消费者数量 = 12（与 Partition 数一致，达到最大并行度）
        factory.setConcurrency(12);

        // 批量消费模式：配合并行，进一步提升吞吐
        factory.setBatchListener(true);

        return factory;
    }

    }
}
```

### Layer 4 -- 分区数选择策略

```java
/**
 * 分区数选择策略 —— Producer 端计算
 *
 * 核心公式:
 *   Partition 数 >= max(目标吞吐 / 单分区吞吐上限, 预期 Consumer 实例数)
 *
 * 示例:
 *   目标吞吐: 100 MB/s
 *   单分区吞吐: 10 MB/s (含网络+磁盘)
 *   预期 Consumer 数: 12
 *   → Partition 数 >= max(100/10, 12) = max(10, 12) = 12
 */
public class PartitionSizingStrategy {

    /**
     * 计算推荐的分区数量
     * @param targetThroughputMBps  目标吞吐量 (MB/s)
     * @param singlePartitionThroughputMBps 单分区吞吐上限 (MB/s)
     * @param expectedConsumers  预期的 Consumer Group 实例数
     * @return 推荐分区数
     */
    public static int calculatePartitions(
            double targetThroughputMBps,
            double singlePartitionThroughputMBps,
            int expectedConsumers) {

        int byThroughput = (int) Math.ceil(targetThroughputMBps / singlePartitionThroughputMBps);
        int byConsumers = expectedConsumers;

        // 分区数应能支撑目标吞吐，且匹配 Consumer 并行度
        int recommended = Math.max(byThroughput, byConsumers);

        // 注意：分区数过多会带来管理开销
        // 元数据更新、Leader 选举、Rebalance 时间都会随分区数增加
        // 单个 Broker 建议分区数 < 4000（依据硬件调整）
        if (recommended > 200) {
            log.warn("推荐分区数 {} 较大，请注意 Broker 管理开销", recommended);
        }

        return recommended;
    }

    /**
     * 典型场景的推荐值
     */
    public static Map<String, Integer> typicalRecommendations() {
        Map<String, Integer> recs = new LinkedHashMap<>();
        recs.put("低吞吐日志采集 (10 MB/s, 3 Consumer)",  3);   // max(1, 3) = 3
        recs.put("中吞吐业务消息 (50 MB/s, 8 Consumer)",  8);   // max(5, 8) = 8
        recs.put("高吞吐埋点数据 (200 MB/s, 20 Consumer)", 20);  // max(20, 20) = 20
        recs.put("超高吞吐实时计算 (500 MB/s, 32 Consumer)", 50); // max(50, 32) = 50
        return recs;
    }
}
```

| 维度 | 分区数少 | 分区数多 | 最佳实践 |
|------|---------|---------|---------|
| **并行度** | 低，Consumer 上限有限 | 高，可匹配更多 Consumer | 分区数 = max(吞吐需求, Consumer 数) |
| **单分区吞吐** | 每条消息分配到更少分区，压力集中 | 每条消息分散，单分区压力小 | 单分区 5-10 MB/s 较合理 |
| **端到端延迟** | Consumer 数受限时延迟高 | Consumer 可横向扩展，延迟低 | 满足延迟 SLA 的前提下不过度分区 |
| **Rebalance 时间** | 短（分区少，分配快） | 长（分区多，Consumer 协调慢） | 避免单个 Topic 超过 500+ 分区 |
| **内存开销** | Producer/Consumer 内存占用低 | 每个分区维护独立缓冲区 | 监控 heap 使用率 |
| **故障恢复** | Leader 选举快 | Leader 选举涉及分区多，恢复慢 | 每个 Broker 承载分区数 < 4000 |
| **适用场景** | 低流量 Topic、有序性要求高 | 高吞吐 Topic、大规模 Consumer | 按 `ceil(吞吐/单分区上限)` 反推 |

## 一句话总结

**Partition 是 Kafka 并行度的原子单位，Producer 通过多线程 + key 路由实现写并行，Broker 通过 Partition 多 Broker 分布实现 IO 并行，Consumer 通过 Consumer Group 内实例数 ≤ Partition 数实现消费并行，整体并行度 = min(Partition 数, Consumer 数)，分区数的选择需在吞吐收益和管理开销之间取得平衡。**
