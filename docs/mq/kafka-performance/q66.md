# Q66 Time Index

`.timeindex` 是时间戳索引文件，存储 `(timestamp, offset)` 的稀疏映射对。它的核心用途是支持按时间查找消息（`offsetsForTimes`）和按时间删除过期 Segment（`log.retention.ms`），时间戳可以是 CreateTime（生产者创建时间）或 LogAppendTime（Broker 接收时间）。

`.timeindex` 与 `.index` 的设计思想一脉相承：都是稀疏索引，都是二分查找，都借助 mmap 实现零拷贝。区别在于 `.timeindex` 将时间维度映射到偏移量维度，让 Kafka 在空间定位（按 offset）之外还具备了时间定位能力。

## 代码：时间戳索引实战

### Layer 1 — 时间戳类型配置

```java
// Broker 端 topic 级别配置
// message.timestamp.type=CreateTime  (默认)
// message.timestamp.type=LogAppendTime

// Producer 端也可以在消息级别指定时间戳
ProducerRecord<String, String> record = new ProducerRecord<>(
    "test-topic",
    null,                    // partition (null = 自动分配)
    System.currentTimeMillis(), // timestamp (CreateTime)
    "key",
    "value"
);
producer.send(record);

// 或者让 Producer 自动生成 CreateTime（默认行为）
ProducerRecord<String, String> record2 = new ProducerRecord<>(
    "test-topic", "key", "value"
);
```

### Layer 2 — Consumer 按时间查找消息

```java
import org.apache.kafka.clients.consumer.*;
import org.apache.kafka.common.TopicPartition;
import java.time.Duration;
import java.util.*;

public class TimestampSeekExample {
    public static void main(String[] args) {
        Properties props = new Properties();
        props.put("bootstrap.servers", "localhost:9092");
        props.put("key.deserializer",
            "org.apache.kafka.common.serialization.StringDeserializer");
        props.put("value.deserializer",
            "org.apache.kafka.common.serialization.StringDeserializer");

        try (KafkaConsumer<String, String> consumer =
                new KafkaConsumer<>(props)) {

            TopicPartition tp = new TopicPartition("test-topic", 0);
            consumer.assign(Collections.singletonList(tp));

            // 查找 2 小时前的 offset
            long twoHoursAgo = System.currentTimeMillis()
                - Duration.ofHours(2).toMillis();

            // offsetsForTimes 底层使用 .timeindex 二分查找
            Map<TopicPartition, Long> timestampsToSearch =
                new HashMap<>();
            timestampsToSearch.put(tp, twoHoursAgo);

            Map<TopicPartition, OffsetAndTimestamp> offsets =
                consumer.offsetsForTimes(timestampsToSearch);

            OffsetAndTimestamp result = offsets.get(tp);
            if (result != null) {
                System.out.println("定位到 offset: " + result.offset());
                System.out.println("对应时间戳: " + result.timestamp());
                // seek 到该 offset 开始消费
                consumer.seek(tp, result.offset());
            }

            // 开始消费
            while (true) {
                ConsumerRecords<String, String> records =
                    consumer.poll(Duration.ofMillis(1000));
                records.forEach(r -> System.out.printf(
                    "offset=%d, ts=%d, value=%s%n",
                    r.offset(), r.timestamp(), r.value()));
            }
        }
    }
}
```

### Layer 4 — 日志保留策略（基于 .timeindex）

```java
// Broker 端配置：基于时间的日志保留
// server.properties

// ✅ 按时间删除：日志保留 7 天
log.retention.ms = 604800000      // 7 * 24 * 60 * 60 * 1000
log.retention.hours = 168         // 等效于 7 天（优先级低于 ms）

// ✅ 按大小删除：Segment 超过 1GB 滚动
log.segment.bytes = 1073741824    // 1GB

// ✅ 混合策略（同时生效，取更严格的）
// 如果同时设置了 retention.ms 和 retention.bytes，
// 只要有一个条件满足就会触发删除

// ⚠️ 注意：时间删除依赖 .timeindex
// Log Manager 会检查每个 Segment 的 .timeindex，
// 获取该 Segment 最后一条消息的时间戳，
// 如果 (now - lastTimestamp) > retention.ms，则删除该 Segment
```

## 对比表格

| 维度 | CreateTime | LogAppendTime |
|---|---|---|
| 时间戳来源 | Producer 端调用 `send()` 时的系统时间 | Broker Leader 写入 Log 时的系统时间 |
| 配置方式 | `message.timestamp.type=CreateTime`（默认） | `message.timestamp.type=LogAppendTime` |
| Producer 指定 | 支持，Producer 可在 Record 中显式设置 | 不支持，Producer 设置的时间戳会被覆盖 |
| 跨副本一致性 | 不一致（各 Producer 本地时钟可能不同） | 一致（Leader 统一打时间戳，Follower 同步） |
| 时间语义 | 业务事件发生时间（event time） | 系统处理时间（processing time） |
| 网络延迟影响 | 时间戳早于实际写入时间 | 时间戳精确反映写入时间 |
| 适用场景 | 事件溯源、IoT 传感器数据、金融交易 | 日志审核、消息顺序保证、严格写入顺序 |
| 时间回溯准确性 | 可能有偏差（网络延迟、时钟漂移） | 精确映射到写入顺序 |
| 与 .timeindex 配合 | 稀疏索引按 CreateTime 排序 | 稀疏索引按 LogAppendTime 排序（天然单调递增） |
| 重试/重发影响 | 同一条消息可能时间戳不一致 | 每次写入打新时间戳，单调递增 |

## 一句话总结

**.timeindex 通过稀疏的 `timestamp → offset` 映射让 Kafka 具备了时间维度的消息定位能力，与 .index 配合形成"时间→偏移量→物理位置"的双重定位链路，支撑按时间查找和按时间删除两大核心功能。**
