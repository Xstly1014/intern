# Q70 Kafka vs 传统 MQ

Kafka 和 RabbitMQ 的本质区别在于存储哲学：RabbitMQ 是"消息即内存对象，消费即销毁"，Kafka 是"消息即日志记录，消费即回溯"——前者擅长复杂路由和低延迟业务消息，后者擅长高吞吐流数据和消息回放，两者是互补关系而非替代。

RabbitMQ 通过 Exchange 的多级路由将消息精准投递到 Queue，推送给消费者后立即删除，延迟极低。Kafka 则直接将消息以日志方式追加到 Partition 文件中，Consumer 自助拉取并维护 Offset，支持随时回溯历史消息，吞吐高出 1~2 个数量级。

## 代码分层演示

### Layer 1 — RabbitMQ 经典模式代码

```java
// RabbitMQ — Exchange 路由 + Queue 绑定 + Consumer
// 依赖：spring-boot-starter-amqp
@Configuration
public class RabbitMQConfig {

    // 1. 声明 Exchange（支持 4 种类型）
    @Bean
    public TopicExchange orderExchange() {
        return new TopicExchange("order.exchange", true, false);
    }

    // 2. 声明 Queue（持久化）
    @Bean
    public Queue orderQueue() {
        return QueueBuilder.durable("order.queue").build();
    }

    // 3. 绑定：Exchange → Queue，支持通配符路由
    @Bean
    public Binding orderBinding() {
        return BindingBuilder.bind(orderQueue())
                .to(orderExchange())
                .with("order.#");  // 通配符匹配 order.create / order.pay / ...
    }
}

// RabbitMQ Producer — 指定 Exchange + routingKey 发送
@Service
public class RabbitMQProducer {
    @Autowired private RabbitTemplate rabbit;

    public void sendOrder(Order order) {
        rabbit.convertAndSend("order.exchange", "order.create", order);
        // 消息路由到 order.queue，Consumer 收到后内存队列出队
    }
}

// RabbitMQ Consumer — 推模式，消息自动推送
@Component
public class RabbitMQConsumer {
    @RabbitListener(queues = "order.queue")
    public void handleOrder(Order order) {
        processOrder(order); // 处理完即 ack，消息从 Queue 中删除
    }
}
```

### Layer 2 — Kafka 等效实现

```java
// Kafka — Topic + Partition + Consumer Group
// 依赖：spring-kafka
@Configuration
public class KafkaConfig {

    @Bean
    public NewTopic orderTopic() {
        return TopicBuilder.name("order")
                .partitions(6)        // 6 个 Partition 并行
                .replicas(3)          // 3 副本高可用
                .config("retention.ms", "604800000") // 保留 7 天
                .build();
    }
}

// Kafka Producer — 发送到 Topic，自动按 key 分区
@Service
public class KafkaProducer {
    @Autowired private KafkaTemplate<String, Order> kafka;

    public void sendOrder(Order order) {
        // 按 orderId 哈希分区，同 order 落在同一 Partition，保证顺序
        kafka.send("order", order.getOrderId(), order);
    }
}

// Kafka Consumer — 拉模式，Consumer Group 自动负载均衡
@Component
public class KafkaConsumer {
    @KafkaListener(topics = "order", groupId = "order-group")
    public void handleOrder(ConsumerRecord<String, Order> record) {
        Order order = record.value();
        processOrder(order);
        // 消费后消息仍保留在 Broker，可被另一 Consumer Group 重新消费
    }
}
```

// ============ RabbitMQ 实现 ============

@Configuration
public class OrderRabbitConfig {

    @Bean public Binding payBinding() {
        return BindingBuilder.bind(payQueue()).to(orderExchange()).with("order.pay");

    @Bean public Binding cancelBinding() {

### Layer 4 — 技术选型决策树

```java
// 技术选型决策模型
public class MQDecisionTree {

    public String select(String scenario, int maxQPS, boolean needReplay,
                          boolean needComplexRouting, int maxLatencyMs) {

        // 决策规则
        if (maxQPS > 50000) {
            return "Kafka — 高吞吐场景（日志、埋点、流处理）";
        }
        if (needReplay) {
            return "Kafka — 需要消息回溯（Event Sourcing、数据重放）";
        }
        if (needComplexRouting && maxLatencyMs < 5) {
            return "RabbitMQ — 复杂路由 + 低延迟（订单、支付、即时通知）";
        }
        if (scenario.contains("stream") || scenario.contains("log")) {
            return "Kafka — 流数据管道（Clickstream、CDC、日志聚合）";
        }
        if (scenario.contains("rpc") || scenario.contains("task")) {
            return "RabbitMQ — RPC/任务分发（延迟低、路由灵活）";
        }
        return "RabbitMQ — 默认业务消息场景";

        // 混合架构推荐：
        // RabbitMQ 处理实时业务消息 → Kafka 做数据管道和 Event Sourcing
    }
}
```

## 对比表

| 维度 | Kafka | RabbitMQ | ActiveMQ |
|:---|:---|:---|:---|
| **设计哲学** | 分布式 Commit Log | 智能 Broker + 哑 Consumer | JMS 标准实现 |
| **存储模型** | 日志文件（Log Segment），消费后保留 | 内存队列，消费后删除 | 支持内存 + 持久化（KahaDB） |
| **吞吐量** | 百万级 QPS | 万级 QPS | 万级 QPS |
| **延迟** | 毫秒级（批量场景 < 10ms） | 微秒级（< 1ms） | 毫秒级 |
| **消费模型** | Pull（拉模式） | Push（推模式） | Push / Pull 均可 |
| **路由能力** | Topic → Partition（扁平） | 4 种 Exchange + 通配符（强大） | 基于 JMS Selector |
| **消息回溯** | 原生支持（重置 Offset） | 不支持（消费即删） | 不支持 |
| **消息顺序** | 单 Partition 内严格有序 | 单 Queue 有序（多 Consumer 破序） | 单 Queue 有序 |
| **持久化** | 磁盘日志 + 零拷贝 | 可选持久化（性能下降） | 可选持久化 |
| **集群扩展** | 天然分布式 + Partition 水平扩展 | 镜像队列（有性能代价） | Master-Slave |
| **协议** | 自定义二进制协议 | AMQP 0-9-1 | JMS / AMQP / MQTT / STOMP |
| **适用场景** | 日志采集、流处理、Event Sourcing、大数据管道 | 订单/支付、RPC 调用、即时通知、业务解耦 | 传统企业 JMS 集成 |
| **运维复杂度** | 中等（需 ZooKeeper/KRaft + 多组件） | 较低（Erlang OTP 自带高可用） | 较低 |

## 一句话总结

**RabbitMQ 和 Kafka 的选型口诀：看吞吐选 Kafka，看路由选 RabbitMQ，两者都用是大多数大型系统的标准答案。**
