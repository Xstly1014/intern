# Q63 压缩算法

Kafka 在 Producer 端支持 gzip、snappy、lz4、zstd 四种压缩算法，压缩后的数据 Broker 零开销存储、Consumer 端自动解压，能有效减少 50-70% 的网络带宽和磁盘占用，其中 zstd（Kafka 2.1+）在压缩率和速度之间取得了最佳平衡，是生产环境的首选推荐。

从 Producer 压缩到 Consumer 解压，Kafka 实现了端到端的透明压缩链路。Broker 以 `compression.type=producer` 保留原始压缩数据零开销存储，Consumer 根据消息头中的压缩算法标识自动解压。四种压缩算法在压缩率、速度方面各有侧重，zstd 凭借接近 gzip 的压缩率和接近 lz4 的压缩速度，成为 Kafka 2.1+ 生产环境的最佳选择。

## 压缩算法代码配置

### Layer 1 -- Producer 压缩配置

```java
@Configuration
public class KafkaCompressionConfig {

    /**
     * Producer 端配置压缩算法
     * compression.type 可选值: none, gzip, snappy, lz4, zstd
     */
    @Bean
    public ProducerFactory<String, String> producerFactory() {
        Map<String, Object> props = new HashMap<>();
        props.put(ProducerConfig.BOOTSTRAP_SERVERS_CONFIG, "localhost:9092");

        // 核心配置：压缩算法
        props.put(ProducerConfig.COMPRESSION_TYPE_CONFIG, "zstd");  // Kafka 2.1+ 推荐
        // props.put(ProducerConfig.COMPRESSION_TYPE_CONFIG, "gzip");   // 最高压缩率
        // props.put(ProducerConfig.COMPRESSION_TYPE_CONFIG, "snappy"); // 最快压缩
        // props.put(ProducerConfig.COMPRESSION_TYPE_CONFIG, "lz4");    // 最快解压

        // 配合批量发送，压缩效果更佳（压缩整个 Batch）
        props.put(ProducerConfig.BATCH_SIZE_CONFIG, 65536);   // 64KB
        props.put(ProducerConfig.LINGER_MS_CONFIG, 5);

        return new DefaultKafkaProducerFactory<>(props);
    }
}
```

### Layer 2 -- 不同消息大小的压缩率对比测试

```java
/**
 * 压缩效果对比测试：不同消息大小下四种算法的表现
 */
@Component
public class CompressionBenchmark {

    private final KafkaTemplate<String, String> kafkaTemplate;

    public CompressionBenchmark(KafkaTemplate<String, String> kafkaTemplate) {
        this.kafkaTemplate = kafkaTemplate;
    }

    /**
     * 发送不同大小的消息，观察压缩效果
     * 规律：消息越大，压缩收益越明显（压缩整个 Batch 的效果更好）
     */
    public Map<String, CompressionResult> testCompression() {
        Map<String, CompressionResult> results = new HashMap<>();
        int[] messageSizes = {100, 500, 1000, 5000}; // 字节

        for (int size : messageSizes) {
            String payload = "x".repeat(size);

            // 分别用四种算法发送并对比
            for (String algo : new String[]{"gzip", "snappy", "lz4", "zstd"}) {
                // 通过 Producer Metrics 观察 compression-rate-avg
                // compression-rate-avg = 压缩后大小 / 原始大小
                // 值越小压缩效果越好，0.3 表示压缩到原来的 30%
                kafkaTemplate.send("test-topic", payload);

                results.put(algo + "-" + size + "B",
                    new CompressionResult(algo, size, 0.35)); // 示例值
            }
        }
        return results;
    }

    @Data
    @AllArgsConstructor
    static class CompressionResult {
        String algorithm;
        int originalSize;
        double compressionRatio; // 0.35 = 节省 65%
    }
}
```

### Layer 3 -- Broker 端压缩保留配置

```properties
# ============ server.properties - Broker 端压缩配置 ============

# 保留 Producer 传来的压缩格式（默认值，推荐）
# Broker 不解压不重压缩，直接写入磁盘，零 CPU 开销
compression.type=producer

# 如果设为其他值，Broker 会解压后重新压缩（浪费 CPU，不推荐）

# compression.type=uncompressed  # 强制解压存原始数据

# ============ Topic 级别覆盖 ============
# 通过 kafka-topics.sh 为特定 Topic 设置压缩
# bin/kafka-topics.sh --alter --topic high-volume-logs \
#   --config compression.type=zstd \
#   --bootstrap-server localhost:9092
```

## 一句话总结

**Kafka 压缩的核心价值在于 Producer 端一次性压缩整个 Batch 后 Broker 零开销透传、Consumer 自动解压，zstd 凭借接近 gzip 的压缩率和接近 lz4 的速度成为 Kafka 2.1+ 生产环境的默认推荐算法，可减少 50-70% 的网络带宽和磁盘占用。**
