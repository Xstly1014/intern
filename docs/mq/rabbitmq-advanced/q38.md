# Q38 Shovel 数据迁移

Shovel 是从一个 Queue（源）消费消息再发布到另一个 Exchange/Queue（目标）的**消息搬运工**。与 Federation 的区别：Federation 是 Exchange/Queue 级别的自动联邦，按 upstream 配置自动连接转发；Shovel 是显式的点对点搬运，配置源和目标的具体 Queue/Exchange。Shovel 更细粒度，支持跨协议（AMQP 到 STOMP 等），源或目标可以是不同版本的 RabbitMQ。适用场景是数据迁移、特定队列跨 Broker 复制、版本升级期间的双写过渡。

## Shovel 配置

### Layer 1 — 启用 Shovel 插件

```bash
# ===== 在源和目标 Broker 上启用 Shovel 插件 =====

# 通常在源 Broker（运行 Shovel 进程的一端）启用
rabbitmq-plugins enable rabbitmq_shovel

# 如果需要 Management UI 管理 Shovel 配置
rabbitmq-plugins enable rabbitmq_shovel_management

# 验证
rabbitmq-plugins list | grep shovel
# [e] rabbitmq_shovel ...
# [e] rabbitmq_shovel_management ...
```

关键点：Shovel 是插件机制。`rabbitmq_shovel` 提供核心搬运功能，`rabbitmq_shovel_management` 提供 Web UI 管理。Shovel 进程运行在源 Broker 上（源 Broker 主动消费并发送到目标）。

### Layer 2 — 配置 Shovel（静态配置）

```bash
# ===== 通过 rabbitmqctl 配置 Shovel =====

# 配置一个 Shovel：从老集群 queue.order.old 搬运到新集群 exchange.order.new
rabbitmqctl set_parameter shovel shovel-order-migration \
  '{
    "src-uri": "amqp://admin:password@old-cluster:5672",
    "src-queue": "queue.order.old",
    "dest-uri": "amqp://admin:password@new-cluster:5672",
    "dest-exchange": "exchange.order.new",
    "dest-exchange-key": "order.created",
    "ack-mode": "on-confirm",
    "delete-after": "never"
  }'

# 参数说明：
# - src-uri: 源 Broker 的 AMQP 连接地址
# - src-queue: 源 Queue（从这里消费）
# - dest-uri: 目标 Broker 的 AMQP 连接地址
# - dest-exchange: 目标 Exchange（发布到这里）
# - dest-exchange-key: 目标 routing key
# - ack-mode: 确认模式
#   - on-confirm: 目标 Broker 确认后才 ack 源消息（最安全）
#   - on-publish: 目标 Broker 收到后即 ack 源消息
#   - no-ack: 不确认（最快，可能丢消息）
# - delete-after: 搬运完成后是否删除 Shovel
#   - never: 永不删除（持续搬运）
#   - 数字: 搬运 N 条后删除
```

关键点：`ack-mode=on-confirm` 是最安全的模式——目标 Broker 确认收到后才 ack 源消息，保证消息不丢。`delete-after=never` 表示持续搬运（适合长期复制），设为数字则搬运指定条数后自动删除 Shovel（适合一次性迁移）。

### Layer 3 — Spring AMQP 配合 Shovel 迁移

```java
// ===== 数据迁移期间的双写过渡方案 =====

// 迁移阶段1：老集群继续服务，Shovel 同步数据到新集群
// 迁移阶段2：灰度切流，部分消费者切到新集群
// 迁移阶段3：全部切到新集群，停止 Shovel

// 新集群的消费者（迁移后启用）
@Component
public class NewClusterOrderConsumer {

    @RabbitListener(queues = "queue.order.new")
    public void handle(OrderEvent event) {
        // 消息来自 Shovel 从老集群搬运过来
        // 消费者无需感知数据来源
        orderService.process(event);
    }
}

// 双写过渡：生产者同时发到老集群和新集群
@Service
public class DualWriteOrderProducer {

    @Autowired
    @Qualifier("oldClusterRabbitTemplate")
    private RabbitTemplate oldTemplate;

    @Autowired
    @Qualifier("newClusterRabbitTemplate")
    private RabbitTemplate newTemplate;

    public void sendOrder(OrderEvent event) {
        // 先发新集群（主）
        newTemplate.convertAndSend("exchange.order.new", "order.created", event);
        // 再发老集群（备），Shovel 也会同步到新集群（幂等去重）
        oldTemplate.convertAndSend("exchange.order.old", "order.created", event);
    }
}
```

关键点：数据迁移期间用双写 + Shovel 同步实现平滑过渡。生产者同时发新老集群，Shovel 也从老集群同步到新集群，新集群消费者做幂等去重。灰度切流完成后停止双写和 Shovel，完全切换到新集群。

### Layer 4 — 动态 Shovel 管理

```bash
# ===== 动态管理 Shovel =====

# 查看所有 Shovel 状态
rabbitmqctl list_parameters | grep shovel

# 通过 Management UI 查看 Shovel 运行状态
# Admin → Shovel Status → 查看 running/stopped

# 启动/停止 Shovel
rabbitmqctl restart_shovel shovel-order-migration

# 删除 Shovel（迁移完成后清理）
rabbitmqctl clear_parameter shovel shovel-order-migration

# 查看 Shovel 日志
# /var/log/rabbitmq/rabbit@hostname.log 中搜索 shovel 相关日志
```

关键点：Shovel 可以动态创建、停止、删除。迁移完成后通过 `clear_parameter` 清理 Shovel 配置。运行状态可在 Management UI 的 Shovel Status 页面实时监控。

## Shovel vs Federation 对比

| 维度 | Shovel | Federation |
|---|---|---|
| 粒度 | Queue → Exchange（点对点） | Exchange/Queue 级别（自动联邦） |
| 配置方式 | 显式指定源和目标 | upstream 配置 + 策略匹配 |
| 协议支持 | 跨协议（AMQP/STOMP 等） | 仅 AMQP |
| 版本兼容 | 源和目标可不同版本 | 需相同大版本 |
| 消息变换 | 支持自定义过滤/修改 | 不支持 |
| 方向 | 单向（可配置双向） | 单向（可配置双向） |
| 适用场景 | 数据迁移、临时搬运 | 长期联邦、跨地域同步 |
| 运行位置 | 源 Broker 上 | downstream Broker 上 |
| 持续性 | 可一次性或持续 | 通常持续运行 |

> 面试要点：Shovel 是 Broker 间的消息搬运工——从源 Queue 消费再发布到目标 Exchange。与 Federation 的区别：Federation 是 Exchange/Queue 级别自动联邦，Shovel 是显式点对点搬运。Shovel 更细粒度，支持跨协议和跨版本。适合数据迁移、版本升级双写过渡。Federation 适合长期联邦。

## 一句话总结

**一句话总结：Federation 是「按配置自动联邦整个 Exchange」的粗粒度长期同步机制，Shovel 是「指定源 Queue 到目标 Exchange」的细粒度显式搬运工——前者适合跨地域长期联邦，后者适合数据迁移和版本升级过渡，Shovel 还支持跨协议和跨版本。**
