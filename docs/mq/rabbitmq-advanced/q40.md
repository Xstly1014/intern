# Q40 RabbitMQ 插件体系

RabbitMQ 的插件体系非常丰富，常用插件包括：`rabbitmq_management`（Web 管理界面，几乎必装）、`rabbitmq_delayed_message_exchange`（延迟消息插件）、`rabbitmq_federation`/`rabbitmq_shovel`（联邦和数据搬运）、`rabbitmq_auth_backend_ldap`（LDAP 认证）、`rabbitmq_mqtt`/`rabbitmq_stomp`（MQTT/STOMP 协议支持，IoT 场景）、`rabbitmq_top`（Erlang 进程资源监控）、`rabbitmq_event_exchange`（内部事件发到 Exchange 便于监控）。项目中最常用的是 management（管理）、delayed_message_exchange（延迟队列）、federation（跨机房同步）。

## 插件安装与使用

### Layer 1 — 插件管理命令

```bash
# ===== 插件管理基础命令 =====

# 查看所有可用插件
rabbitmq-plugins list

# 启用插件（-e 表示 enabled，持久化到配置）
rabbitmq-plugins enable rabbitmq_management
rabbitmq-plugins enable rabbitmq_federation
rabbitmq-plugins enable rabbitmq_shovel

# 禁用插件
rabbitmq-plugins disable rabbitmq_management

# 批量启用
rabbitmq-plugins enable rabbitmq_management rabbitmq_federation rabbitmq_shovel

# 查看已启用的插件
rabbitmq-plugins list -e
# [e] rabbitmq_management ...
# [e] rabbitmq_management_agent ...
# [e] rabbitmq_federation ...
```

关键点：`rabbitmq-plugins enable` 启用插件后立即生效（部分插件需重启 Broker）。`-e` 参数只列出已启用的插件。插件配置持久化到 `/etc/rabbitmq/enabled_plugins` 文件，重启后自动恢复。

### Layer 2 — 延迟消息插件使用

```bash
# ===== 安装延迟消息插件 =====

# 1. 下载插件 .ez 文件到 plugins 目录
# 从 GitHub 下载对应版本：
# https://github.com/rabbitmq/rabbitmq-delayed-message-exchange/releases
cp rabbitmq_delayed_message_exchange-3.12.0.ez /usr/lib/rabbitmq/plugins/

# 2. 启用插件
rabbitmq-plugins enable rabbitmq_delayed_message_exchange

# 3. 重启 RabbitMQ（部分版本需要）
systemctl restart rabbitmq-server
```

```java
// ===== 延迟消息插件使用（Spring AMQP）=====

@Configuration
public class DelayedExchangeConfig {

    // 声明延迟 Exchange（x-delayed-message 类型）
    @Bean
    public CustomExchange delayedExchange() {
        Map<String, Object> args = new HashMap<>();
        args.put("x-delayed-type", "direct");  // 底层路由类型
        return new CustomExchange(
                "exchange.delayed",
                "x-delayed-message",  // 插件提供的 Exchange 类型
                true, false, args);
    }

    @Bean
    public Queue delayedQueue() {
        return QueueBuilder.durable("queue.delayed").build();
    }

    @Bean
    public Binding delayedBinding(Queue delayedQueue, CustomExchange delayedExchange) {
        return BindingBuilder.bind(delayedQueue)
                .to(delayedExchange)
                .with("delayed.task")
                .noargs();
    }
}

// 生产者：发送延迟消息
@Service
public class DelayedTaskProducer {

    @Autowired
    private RabbitTemplate rabbitTemplate;

    public void sendDelayedTask(String taskId, long delayMs) {
        rabbitTemplate.convertAndSend(
                "exchange.delayed",
                "delayed.task",
                taskId,
                message -> {
                    // 设置延迟时间（毫秒）
                    message.getMessageProperties().setHeader("x-delay", delayMs);
                    return message;
                });
        // 消息到达 Exchange 后不会立即路由到 Queue
        // 等待 delayMs 毫秒后才投递
        log.info("延迟任务已发送: taskId={}, delay={}ms", taskId, delayMs);
    }
}

// 消费者：延迟到达后消费
@Component
public class DelayedTaskConsumer {

    @RabbitListener(queues = "queue.delayed")
    public void handle(String taskId) {
        // 消息在延迟时间到达后才被投递到这里
        log.info("延迟任务执行: taskId={}, 实际执行时间={}",
                taskId, LocalDateTime.now());
        taskService.execute(taskId);
    }
}
```

关键点：延迟消息插件提供 `x-delayed-message` Exchange 类型。生产者通过 `x-delay` 消息头设置延迟时间（毫秒），消息到达 Exchange 后不立即路由，等延迟时间到达后才投递到 Queue。比 TTL + DLX 方案更简洁，不需要额外队列。

### Layer 3 — MQTT 插件与 IoT 场景

```bash
# ===== MQTT 插件：IoT 设备消息接入 =====

# 启用 MQTT 插件
rabbitmq-plugins enable rabbitmq_mqtt

# 配置 MQTT（/etc/rabbitmq/rabbitmq.conf）
# mqtt.default_vhost = /
# mqtt.default_user = guest
# mqtt.default_password = guest
# mqtt.allow_anonymous = false
# mqtt.tcp_listeners.1 = 1883       # MQTT 端口
# mqtt.ssl_listeners.1 = 8883        # MQTT over TLS

# 重启生效
systemctl restart rabbitmq-server

# IoT 设备通过 MQTT 协议连接 RabbitMQ
# 设备发布的消息自动路由到 AMQP Exchange（amq.topic）
# AMQP 消费者也可以通过 AMQP 协议消费 MQTT 设备的消息
```

```java
// ===== AMQP 消费者消费 MQTT 设备消息 =====

// MQTT 设备发布的消息会被路由到 amq.topic Exchange
// routing key 是 MQTT topic（如 sensor/temperature/room1）

@Component
public class IotMessageConsumer {

    @RabbitListener(bindings = @QueueBinding(
            value = @org.springframework.amqp.rabbit.annotation.Queue(
                    value = "queue.iot.sensor", durable = "true"),
            exchange = @Exchange(value = "amq.topic", type = "topic"),
            key = "sensor.#"))  // 匹配 sensor 开头的所有 topic
    public void handleSensorData(SensorData data) {
        // 消息来自 MQTT 设备，通过 AMQP 协议消费
        // RabbitMQ 自动在 MQTT 和 AMQP 之间桥接
        log.info("收到传感器数据: device={}, value={}",
                data.getDeviceId(), data.getValue());
        monitoringService.record(data);
    }
}
```

关键点：MQTT 插件让 RabbitMQ 支持 MQTT 协议，IoT 设备可以直接用 MQTT 连接 RabbitMQ。消息自动在 MQTT 和 AMQP 之间桥接——MQTT 设备发布的消息路由到 `amq.topic` Exchange，AMQP 消费者可以直接消费。这使得 RabbitMQ 可以同时服务应用层（AMQP）和设备层（MQTT）。

### Layer 4 — Event Exchange 插件与监控

```bash
# ===== Event Exchange 插件：内部事件监控 =====

# 启用插件
rabbitmq-plugins enable rabbitmq_event_exchange

# 插件会创建一个 amq.rabbitmq.event Exchange（topic 类型）
# RabbitMQ 内部事件会发布到这个 Exchange：
# - queue.created / queue.deleted
# - exchange.created / exchange.deleted
# - connection.created / connection.closed
# - user.authentication.success / user.authentication.failure
```

```java
// ===== 订阅内部事件做监控告警 =====

@Component
public class RabbitMQEventMonitor {

    // 监听队列创建/删除事件
    @RabbitListener(bindings = @QueueBinding(
            value = @org.springframework.amqp.rabbit.annotation.Queue(
                    value = "queue.monitor.events", durable = "true"),
            exchange = @Exchange(value = "amq.rabbitmq.event", type = "topic"),
            key = "queue.#"))  // 匹配 queue 开头的所有事件
    public void handleQueueEvent(Message message) {
        String eventType = message.getMessageProperties().getReceivedRoutingKey();
        Map<String, Object> body = parseJson(new String(message.getBody()));

        log.info("RabbitMQ 事件: type={}, details={}", eventType, body);

        if (eventType.equals("queue.deleted")) {
            // 队列被删除 → 可能是误操作，发告警
            alertService.sendAlert("队列被删除: " + body.get("name"));
        }
    }

    // 监听认证失败事件
    @RabbitListener(bindings = @QueueBinding(
            value = @org.springframework.amqp.rabbit.annotation.Queue(
                    value = "queue.monitor.auth", durable = "true"),
            exchange = @Exchange(value = "amq.rabbitmq.event", type = "topic"),
            key = "user.authentication.failure"))
    public void handleAuthFailure(Message message) {
        // 认证失败 → 可能是攻击，记录并告警
        Map<String, Object> body = parseJson(new String(message.getBody()));
        log.warn("认证失败: {}", body);
        securityService.recordFailure(body);
    }
}
```

关键点：`rabbitmq_event_exchange` 插件把 RabbitMQ 内部事件（队列创建/删除、连接建立/断开、认证成功/失败等）发布到 `amq.rabbitmq.event` Exchange。订阅这些事件可以实现自动化监控告警——比如队列被误删时立即告警、认证频繁失败时触发安全策略。

## 常用插件对比

| 插件 | 功能 | 必装度 | 典型场景 |
|---|---|---|---|
| rabbitmq_management | Web 管理界面 | 必装 | 日常监控管理 |
| rabbitmq_delayed_message_exchange | 延迟消息 | 常用 | 订单超时、延迟任务 |
| rabbitmq_federation | 跨 Broker 联邦 | 按需 | 跨机房同步 |
| rabbitmq_shovel | 消息搬运 | 按需 | 数据迁移 |
| rabbitmq_mqtt | MQTT 协议 | 按需 | IoT 设备接入 |
| rabbitmq_stomp | STOMP 协议 | 按需 | WebSocket 通信 |
| rabbitmq_auth_backend_ldap | LDAP 认证 | 企业 | 统一账号管理 |
| rabbitmq_top | Erlang 进程监控 | 推荐 | 性能排查 |
| rabbitmq_event_exchange | 内部事件监控 | 推荐 | 自动化告警 |

> 面试要点：RabbitMQ 插件体系丰富，最常用的是 management（Web 管理）、delayed_message_exchange（延迟队列）、federation（跨机房同步）。其他按需使用：MQTT/STOMP 用于 IoT/WebSocket、LDAP 用于企业认证、event_exchange 用于监控告警。插件通过 `rabbitmq-plugins enable` 启用。

## 一句话总结

**一句话总结：RabbitMQ 插件体系是「按需加载的能力扩展」——management 是必装的 Web 管理，delayed_message_exchange 把延迟队列从 TTL+DLX 的多队列方案简化成一个 Exchange + x-delay 头，federation/shovel 解决跨 Broker 通信，MQTT/STOMP 桥接 IoT 和 WebSocket——项目里 management + delayed_message_exchange + federation 是三大主力。**
