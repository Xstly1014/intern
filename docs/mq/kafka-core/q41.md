# Q41 Kafka 核心架构

Kafka 是一个分布式消息流平台，核心由 Broker（服务节点）、Topic（消息分类）、Partition（物理分片）、Producer（生产者）、Consumer Group（消费者组）和 ZooKeeper/KRaft（元数据管理）组成——消息从 Producer 写入 Topic 的多个 Partition，分散存储在 Broker 集群上，Consumer Group 内的消费者各自分摊分区并行消费。

上图展示了 Kafka 的完整数据链路：Producer 将消息写入 Topic 的 3 个 Partition，每个 Partition 的 Leader 副本分布在不同 Broker 上（P0 Leader 在 Broker1、P1 Leader 在 Broker2、P2 Leader 在 Broker3），其余 Broker 上存放 Follower 副本做数据冗余；ZooKeeper/KRaft 负责集群元数据管理和 Controller 选举；Consumer Group 内 3 个消费者分别拉取各自分到的 Partition，互不干扰。

## 代码实现：Spring Kafka 分层示例

### Layer 1 — Producer 配置与发送

```yaml
# application.yml — Producer 核心配置
spring:
  kafka:
    bootstrap-servers: broker1:9092,broker2:9092,broker3:9092
    producer:
      key-serializer: org.apache.kafka.common.serialization.StringSerializer
      value-serializer: org.springframework.kafka.support.serializer.JsonSerializer
      acks: all              # 等所有 ISR 副本确认
      retries: 3             # 发送失败重试次数
```

```java
@Service
public class OrderEventProducer {
    @Autowired
    private KafkaTemplate<String, OrderEvent> kafkaTemplate;

    public void send(OrderEvent event) {
        // key = orderId，相同 key 路由到同一 Partition，保证顺序
        kafkaTemplate.send("order-events", event.getOrderId(), event);
    }
}
```

Producer 只需知道 Topic 名和 Bootstrap Server 地址，Kafka 客户端会自动从 Broker 拉取元数据，找到对应 Partition 的 Leader 所在 Broker 并发送。

### Layer 2 — Topic 与 Partition 创建

```java
@Configuration
public class KafkaTopicConfig {

    // 声明式创建：3 Partition × 3 副本
    @Bean
    public NewTopic orderEventsTopic() {
        return TopicBuilder.name("order-events")
                .partitions(3)
                .replicas(3)
                .build();
    }
}
```

```java
// 编程式创建：通过 AdminClient 精确控制
public void createTopic() {
    AdminClient admin = AdminClient.create(props);
    NewTopic topic = new NewTopic("order-events", 3, (short) 3);
    admin.createTopics(Collections.singleton(topic));
}
```

`NewTopic` 会在应用启动时自动检测并创建 Topic（如果不存在），`partitions(3)` 决定并行度，`replicas(3)` 决定数据冗余度。

### Layer 3 — Consumer Group 消费

```yaml
spring:
  kafka:
    consumer:
      group-id: order-consumer-group
      auto-offset-reset: earliest
      enable-auto-commit: false
      key-deserializer: org.apache.kafka.common.serialization.StringDeserializer
      value-deserializer: org.springframework.kafka.support.serializer.JsonDeserializer
    listener:
      ack-mode: manual_immediate
```

```java
@Component
@Slf4j
public class OrderEventConsumer {

    @KafkaListener(topics = "order-events", groupId = "order-consumer-group")
    public void handle(OrderEvent event, Acknowledgment ack) {
        log.info("消费订单事件: orderId={}", event.getOrderId());
        // 业务处理
        ack.acknowledge();   // 手动提交 offset
    }
}
```

同一个 `groupId` 下的多个消费者实例自动组成 Consumer Group，Kafka 将 Partition 分配给组内消费者，一个 Partition 只被一个消费者消费。

### Layer 4 — Broker 集群配置

```properties
# broker1 / server.properties 关键参数
broker.id=1
listeners=PLAINTEXT://:9092
log.dirs=/var/lib/kafka/data

# 默认 Partition 数与副本数
num.partitions=3
default.replication.factor=3
min.insync.replicas=2

# ZooKeeper 集群地址（KRaft 模式下替换为 controller.quorum.voters）
zookeeper.connect=zk1:2181,zk2:2181,zk3:2181
```

每个 Broker 通过 `broker.id` 唯一标识，`log.dirs` 指定日志存储目录，`min.insync.replicas=2` 要求至少 2 个副本写入成功才算提交，与 `acks=all` 配合保证数据不丢。

## Kafka 核心组件对比

| 组件 | 职责 | 类比 |
|---|---|---|
| Broker | Kafka 服务节点，存储和转发消息 | 快递分拣中心 |
| Topic | 逻辑消息分类，如 order-events | 快递分类（生鲜、电器） |
| Partition | Topic 物理分片，并行度基本单位 | 分拣中心的传送带 |
| Producer | 发送消息到指定 Topic | 寄件人 |
| Consumer / Consumer Group | 拉取消息，组内分摊分区消费 | 一组快递员分区配送 |
| ZooKeeper / KRaft | 集群元数据管理、Controller 选举 | 调度中心 |
| Offset | 消费者在 Partition 中的消费位置 | 取件进度条 |
| Leader / Follower | 副本角色，Leader 读写、Follower 同步 | 主柜员 / 备份柜员 |

## 一句话总结

**一句话总结：Kafka 用 Topic 分 Partition、Partition 分布到 Broker、Consumer Group 分摊消费的三层分片模型，把"海量消息的高吞吐存储"和"多消费者并行处理"统一成了一个可水平扩展的分布式日志系统。**
