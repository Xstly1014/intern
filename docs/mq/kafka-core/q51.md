# Q51 Producer 发送流程

Producer 发送消息经历 7 个步骤：序列化（把消息对象转为字节数组）、分区器（决定发到哪个 Partition）、拦截器（执行 ProducerInterceptor.onSend 可修改消息）、accumulator 消息累加器（按 Topic-Partition 累积批，batch.size 满或 linger.ms 到时间就发送）、Sender 线程（把 batch 通过网络发给 Leader Broker）、Broker 处理（Leader 写入本地日志等 ISR 同步根据 acks 返回响应）、回调（收到响应执行回调成功或重试）。批量加异步是 Kafka 高吞吐的关键。

上图展示了 Producer 发送消息的完整 7 步流水线。左侧是主流程：消息经过序列化转为字节数组，分区器根据规则决定目标 Partition，拦截器可在发送前修改消息，随后进入 accumulator 消息累加器。accumulator 是 Kafka 高吞吐的核心，消息按 Topic-Partition 维度累积成 batch，有两个触发发送的条件：batch.size 达到阈值（默认 16384 bytes）或 linger.ms 等待超时（默认 0ms 即立即发送）。Sender 线程将 batch 发往 Leader Broker，Broker 根据 acks 配置决定持久化级别后返回响应，Producer 收到响应执行回调。右侧标注了分区器的三条决策规则和 acks 的三种持久化级别。

## Producer 代码实践

### Layer 1 — Producer 基础配置

```yaml
# application.yml — Producer 核心参数配置
spring:
  kafka:
    producer:
      bootstrap-servers: localhost:9092
      # 序列化器：消息 Key 和 Value 的序列化方式
      key-serializer: org.apache.kafka.common.serialization.StringSerializer
      value-serializer: org.springframework.kafka.support.serializer.JsonSerializer
      # acks: 持久化保证级别
      #   0   → 不等待任何确认（最高吞吐，可能丢消息）
      #   1   → Leader 写入即返回确认（默认）
      #   -1  → ISR 全部同步才返回确认（最安全，推荐生产环境）
      acks: all
      # batch.size: 单个 batch 的最大字节数（默认 16384 = 16KB）
      # 增大可容纳更多消息，提高吞吐但增加延迟
      batch-size: 32768
      # linger.ms: batch 等待发送的最大时间（毫秒，默认 0）
      # 0 = 消息立即发送（无批量化）
      # 增大可积攒更多消息提高吞吐，但增加延迟
      linger-ms: 10
      # buffer.memory: Producer 可用缓冲区总大小（默认 33554432 = 32MB）
      # 缓冲区满时 send() 会阻塞或抛异常
      buffer-memory: 67108864
      # retries: 发送失败重试次数（默认 Integer.MAX_VALUE）
      retries: 3
      # compression.type: 压缩算法（none/gzip/snappy/lz4/zstd）
      compression-type: lz4
      # max.in.flight.requests.per.connection:
      # 单连接上未确认请求的最大数（默认 5）
      # 若需保证顺序需设为 1（配合 enable.idempotence）
      properties:
        max.in.flight.requests.per.connection: 5
        enable.idempotence: true
```

### Layer 2 — 自定义 Partitioner

```java
/**
 * 自定义分区器：实现 Partitioner 接口
 * 决定消息发到哪个 Partition
 */
public class OrderPartitioner implements Partitioner {

    /**
     * 分区决策核心方法
     *
     * @param topic      Topic 名称
     * @param key        消息 Key
     * @param keyBytes   Key 的字节数组
     * @param value      消息 Value
     * @param valueBytes Value 的字节数组
     * @param cluster    集群信息
     * @return 目标 Partition 编号
     */
    @Override
    public int partition(String topic, Object key, byte[] keyBytes,
                         Object value, byte[] valueBytes, Cluster cluster) {

        // 获取该 Topic 的 Partition 列表
        List<PartitionInfo> partitions = cluster.partitionsForTopic(topic);
        int numPartitions = partitions.size();

        // 规则 1：没有 Key，使用轮询
        if (keyBytes == null) {
            // 粘性分区：同一个 batch 内的消息发到同一个 Partition
            // Kafka 2.4+ 默认行为，减少请求次数
            return ThreadLocalRandom.current().nextInt(numPartitions);
        }

        // 规则 2：Key 是订单类型，按类型分区
        if (key instanceof String orderType) {
            return switch (orderType) {
                case "URGENT" -> 0;                    // 紧急订单 → P0
                case "NORMAL" -> hashPartition(keyBytes, numPartitions);
                case "BULK" -> numPartitions - 1;      // 批量订单 → 最后一个 Partition
                default -> Math.abs(key.hashCode()) % numPartitions;
            };
        }

        // 规则 3：有 Key 但非特殊类型，hash 分区
        return Math.abs(key.hashCode()) % numPartitions;
    }

    /**
     * hash 分区工具方法
     */
    private int hashPartition(byte[] keyBytes, int numPartitions) {
        // Kafka 内部使用 murmur2 哈希算法
        int hash = Utils.toPositive(Utils.murmur2(keyBytes));
        return hash % numPartitions;
    }

    @Override
    public void close() {
        // 清理资源
    }

    @Override
    public void configure(Map<String, ?> configs) {
        // 初始化配置
    }
}

/**
 * 注册自定义 Partitioner
 */
```

### Layer 3 — 自定义 ProducerInterceptor

```java
/**
 * 自定义 Producer 拦截器：实现 ProducerInterceptor 接口
 * 在消息发送前 (onSend) 和收到响应后 (onAcknowledgement) 执行
 */
public class AuditProducerInterceptor implements ProducerInterceptor<String, Object> {

    /**
     * onSend：消息发送前调用（步骤 3）
     * 可以修改消息内容、Header 等
     */
    @Override
    public ProducerRecord<String, Object> onSend(
            ProducerRecord<String, Object> record) {

        // 添加追踪 Header
        Headers headers = record.headers();
        headers.add("traceId", generateTraceId().getBytes());
        headers.add("timestamp", String.valueOf(System.currentTimeMillis()).getBytes());
        headers.add("source", "order-service".getBytes());

        // 日志记录
        System.out.printf("[Interceptor] onSend: topic=%s, partition=%d, key=%s%n",
                record.topic(), record.partition(), record.key());

        // 返回修改后的 ProducerRecord
        return new ProducerRecord<>(
                record.topic(),
                record.partition(),
                record.timestamp(),
                record.key(),
                record.value(),
                headers
        );
    }

    /**
     * onAcknowledgement：收到 Broker 响应后调用（步骤 7 之后）
     * 注意：此方法在 Producer 的 I/O 线程中执行，不要做耗时操作
     */
    @Override
    public void onAcknowledgement(RecordMetadata metadata, Exception exception) {
        if (exception != null) {
            // 发送失败
            System.err.printf("[Interceptor] 发送失败: %s%n", exception.getMessage());
            // 可在此上报监控指标
            MetricsService.recordSendFailure(metadata.topic());
        } else {
            // 发送成功
            System.out.printf("[Interceptor] 发送成功: topic=%s, partition=%d, offset=%d%n",
                    metadata.topic(), metadata.partition(), metadata.offset());
            MetricsService.recordSendSuccess(metadata.topic());
        }
    }

    @Override
    public void close() {
        // 清理资源
    }

    @Override
    public void configure(Map<String, ?> configs) {
        // 初始化配置
    }

    private String generateTraceId() {
        return UUID.randomUUID().toString().replace("-", "");
    }
}

/**
 * 注册拦截器
 */
@Configuration
public class InterceptorConfig {

    @Bean
    public ProducerFactory<String, Object> producerFactory() {
        Map<String, Object> config = new HashMap<>();
        config.put(ProducerConfig.BOOTSTRAP_SERVERS_CONFIG, "localhost:9092");
        config.put(ProducerConfig.KEY_SERIALIZER_CLASS_CONFIG,

        // 注册拦截器（多个按逗号分隔，按顺序执行）
```

### Layer 4 — 异步发送与回调

```java
/**
 * 异步发送与回调：使用 KafkaTemplate.send + Callback
 * 这是 Producer 最常用的发送方式
 */
@Service
@Slf4j
public class OrderMessageProducer {

    private final KafkaTemplate<String, Object> kafkaTemplate;

    public OrderMessageProducer(KafkaTemplate<String, Object> kafkaTemplate) {
        this.kafkaTemplate = kafkaTemplate;
    }

    /**
     * 方式 1：异步发送 + Callback（推荐）
     * send() 立即返回，消息在后台异步发送
     */
    public void sendAsyncWithCallback(String topic, String key, OrderEvent order) {
        ListenableFuture<SendResult<String, Object>> future =
                kafkaTemplate.send(topic, key, order);

        // 添加回调
        future.addCallback(
                // 成功回调
                success -> {
                    SendResult<String, Object> result = success.getProducerRecord();
                    RecordMetadata metadata = success.getRecordMetadata();
                    log.info("发送成功: topic={}, partition={}, offset={}",
                            metadata.topic(), metadata.partition(), metadata.offset());
                },
                // 失败回调
                failure -> {
                    log.error("发送失败: {}", failure.getMessage(), failure);
                    // 可在此实现重试逻辑或告警
                    handleSendFailure(topic, key, order, failure);
                }
        );
    }

    /**
     * 方式 2：同步发送（不推荐，阻塞等待）
     * send().get() 会阻塞当前线程直到收到 Broker 确认
     */
    public void sendSync(String topic, String key, OrderEvent order)
            throws InterruptedException, ExecutionException, TimeoutException {
        try {
            SendResult<String, Object> result = kafkaTemplate.send(topic, key, order)
                    .get(10, TimeUnit.SECONDS); // 最多等待 10 秒
            log.info("同步发送成功: offset={}", result.getRecordMetadata().offset());
        } catch (ExecutionException e) {
            log.error("同步发送失败: {}", e.getCause().getMessage());
            throw e;
        }
    }

    /**
     * 方式 3：异步发送不带回调（fire-and-forget）
     * 最高吞吐但无法感知发送结果，可能静默丢消息
     */
    public void sendFireAndForget(String topic, String key, OrderEvent order) {
        kafkaTemplate.send(topic, key, order);
        // 不等待结果，不添加回调
        log.debug("已提交发送请求（fire-and-forget）");
    }

    /**
     * 发送失败处理
     */
    private void handleSendFailure(String topic, String key,
                                    OrderEvent order, Throwable failure) {
        // 策略 1：写入本地死信队列
        deadLetterStore.save(topic, key, order, failure.getMessage());
        // 策略 2：告警通知
        alertService.notify("Kafka 发送失败", failure.getMessage());
    }

    /**
     * 批量发送示例
     */
    public void sendBatch(String topic, List<OrderEvent> orders) {
        for (OrderEvent order : orders) {
            kafkaTemplate.send(topic, order.getOrderId(), order);
        }
        // flush 确保所有消息都发出去
        kafkaTemplate.flush();
        log.info("批量发送完成: {} 条消息", orders.size());
    }
}
```

## Producer 发送模式对比

| 维度 | 同步发送 (send().get()) | 异步发送 (send() 无回调) | 异步 + 回调 (send() + Callback) |
|------|------------------------|------------------------|-------------------------------|
| 调用方式 | `kafkaTemplate.send(topic, value).get()` | `kafkaTemplate.send(topic, value)` | `kafkaTemplate.send(topic, value).addCallback(...)` |
| 阻塞行为 | 阻塞当前线程等待 Broker 确认 | 立即返回，不等待 | 立即返回，回调中处理结果 |
| 吞吐量 | 最低（每条消息串行等待） | 最高（完全异步无额外开销） | 高（异步 + 回调在 I/O 线程执行） |
| 可靠性 | 最高（立即知道结果） | 最低（可能静默丢消息） | 高（失败有回调通知） |
| 适用场景 | 强一致性要求、低延迟场景 | 日志采集、可容忍少量丢失 | 生产环境推荐、业务消息发送 |
| 异常处理 | try-catch 直接捕获 | 无法感知异常 | 回调中处理失败逻辑 |
| 顺序保证 | 天然保证发送顺序 | 可能乱序 | 可能乱序（需配合 max.in.flight=1） |
| 超时控制 | 可设 get(timeout) | 无超时控制 | 无直接超时（依赖 Producer 配置） |
| 资源占用 | 发送线程被阻塞 | 最少资源 | 回调在 I/O 线程执行需注意耗时 |

## 一句话总结

**Producer 发送流程的 7 步流水线（序列化 → 分区器 → 拦截器 → accumulator → Sender → Broker → 回调）中，accumulator 的 batch.size 和 linger.ms 两个触发条件是批量加异步实现高吞吐的核心机制。**
