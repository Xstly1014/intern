# Q49 Offset 管理

Offset 是消费者在 Partition 中消费到的位置，一个单调递增的整数。Kafka 通过内部 Topic `__consumer_offsets` 记录每个 Consumer Group 在每个 Partition 的消费位置。自动提交简单但可能重复消费或丢失消息，手动提交让业务精确控制提交时机，配合幂等消费可实现 At Least Once 语义。

## Offset 管理代码分层

### Layer 1 — 自动提交配置

自动提交是最简单的方式，开启后消费者每隔固定间隔自动提交当前 offset。优点是零配置省事，缺点是提交时机不可控，可能导致重复消费或消息丢失。

```yaml
spring:
  kafka:
    consumer:
      group-id: order-consumer-group
      enable-auto-commit: true          # 开启自动提交（默认 true）
      auto-commit-interval-ms: 5000     # 提交间隔，默认 5s
      auto-offset-reset: earliest
      key-deserializer: org.apache.kafka.common.serialization.StringDeserializer
      value-deserializer: org.springframework.kafka.support.serializer.JsonDeserializer
```

```java
// 自动提交模式下，@KafkaListener 正常消费即可，无需手动提交
@KafkaListener(topics = "order-events", groupId = "order-consumer-group")
public void handleOrder(String message) {
    processOrder(message);
    // offset 由 Kafka 每 5s 自动提交，无需关心
}
```

自动提交的问题在于提交时机与业务处理时机脱节：如果处理完消息但还没到 5s 提交间隔就宕机，重启后会重复消费；如果恰好提交后处理失败，则消息丢失。

### Layer 2 — 手动同步提交

关闭自动提交后，使用 `Acknowledgment.acknowledge()` 在业务处理完成后同步提交 offset。Spring Kafka 的 `MANUAL` AckMode 要求显式调用 acknowledge，否则 offset 不前进。

```java
// 配置手动提交工厂
@Bean
public ConcurrentKafkaListenerContainerFactory<String, String> manualFactory(
        ConsumerFactory<String, String> consumerFactory) {
    ConcurrentKafkaListenerContainerFactory<String, String> factory =
            new ConcurrentKafkaListenerContainerFactory<>();
    factory.setConsumerFactory(consumerFactory);
    // 关键：设置为手动确认模式
    factory.getContainerProperties().setAckMode(ContainerProperties.AckMode.MANUAL);
    return factory;
}

// 消费者：处理成功才提交，失败则不提交（消息重投）
@KafkaListener(topics = "order-events", groupId = "order-group",
               containerFactory = "manualFactory")
public void handleOrderSync(String message, Acknowledgment ack) {
    try {
        processOrder(message);       // 先处理业务
        ack.acknowledge();           // 处理成功后提交 offset（同步）
    } catch (Exception e) {
        log.error("处理失败，不提交 offset，下次重新消费: {}", message, e);
        // 不调用 ack，offset 不前进，下次 poll 会重新拉取这条消息
    }
}
```

同步提交的关键是"先处理后提交"——只有业务成功才提交 offset，失败则不提交让消息重投。代价是如果处理一直失败会反复消费同一条消息，需要配合幂等消费。

### Layer 3 — 手动异步提交

异步提交不阻塞消费线程，吞吐量更高，但提交可能失败。适合对性能要求高、能容忍少量重复消费的场景。原生 Kafka Client 的 `commitAsync` 支持回调处理失败情况。

```java
// Spring Kafka 异步提交（Acknowledgment 默认异步）
@KafkaListener(topics = "order-events", groupId = "order-group",
               containerFactory = "manualFactory")
public void handleOrderAsync(String message, Acknowledgment ack) {
    try {
        processOrder(message);
        ack.acknowledge();           // Spring Kafka 默认异步提交，不阻塞
    } catch (Exception e) {
        log.error("处理失败，不提交: {}", message, e);
    }
}
```

```java
// 原生 Kafka Client：异步提交 + 回调补偿
consumer.subscribe(Collections.singletonList("order-events"));
while (true) {
    ConsumerRecords<String, String> records = consumer.poll(Duration.ofMillis(500));
    for (ConsumerRecord<String, String> record : records) {
        processOrder(record.value());
    }
    // 异步提交，带回调处理失败
    consumer.commitAsync((offsets, exception) -> {
        if (exception != null) {
            log.warn("异步提交失败，offset: {}", offsets, exception);
            // 失败不重试，等下次提交覆盖；或记录失败 offset 后续补偿
        }
    });
}
```

异步提交失败时通常不重试（因为重试时可能已经有更新的 offset 提交了），而是在关闭消费者前用 `commitSync` 做一次兜底提交，确保最后的 offset 不丢。

### Layer 4 — 手动提交 + 幂等消费（At Least Once 最佳实践）

At Least Once 的核心组合是：手动提交保证消息不丢 + 幂等消费保证重复不出错。幂等的实现方式包括唯一键去重、状态判断、数据库唯一约束等。

```java
// ========== At Least Once 最佳实践 ==========
// 手动提交（消息不丢）+ 幂等消费（重复不出错）

@KafkaListener(topics = "order-events", groupId = "order-group",
               containerFactory = "manualFactory")
public void handleOrderIdempotent(String message, Acknowledgment ack) {
    OrderEvent event = JSON.parseObject(message, OrderEvent.class);
    String orderId = event.getOrderId();

    // 幂等检查：用订单号去重，已处理则直接跳过
    if (orderCache.exists(orderId)) {
        log.info("订单 {} 已处理过，跳过（幂等保护）", orderId);
        ack.acknowledge();           // 重复消息也要提交，否则会无限重投
        return;
    }

    try {
        orderService.createOrder(event);          // 业务处理
        orderCache.markProcessed(orderId);        // 标记已处理（Redis/DB）
        ack.acknowledge();                        // 提交 offset
    } catch (Exception e) {
        log.error("订单处理失败: {}", orderId, e);
        // 不提交 offset，消息将重新投递
        // 幂等机制保证：即使之前部分处理了，重新消费也不会出错
    }
}
```

```java
// 幂等去重工具：基于 Redis 的订单号去重
@Component
public class OrderCache {
    @Autowired
    private StringRedisTemplate redis;

    public boolean exists(String orderId) {
        return Boolean.TRUE.equals(redis.hasKey("order:processed:" + orderId));
    }

    public void markProcessed(String orderId) {
        // 设置 24h 过期，避免 Redis 无限膨胀
        redis.opsForValue().set("order:processed:" + orderId, "1", 24, TimeUnit.HOURS);
    }
}
```

这套组合的逻辑闭环：手动提交确保处理成功才推进 offset（不丢消息），幂等去重确保即使消息重复投递也只处理一次（不重复执行），两者配合实现可靠的 At Least Once 语义。

## Offset 提交方式对比

| 维度 | 自动提交 | 手动同步提交 | 手动异步提交 |
|---|---|---|---|
| 配置 | enable.auto.commit=true | enable.auto.commit=false + MANUAL | enable.auto.commit=false + MANUAL |
| 提交时机 | 固定间隔（默认 5s） | 业务处理成功后 | 业务处理成功后 |
| 可靠性 | 低（时机不可控） | 高（失败自动重试） | 中（可能提交失败） |
| 性能 | 高（无阻塞） | 低（同步阻塞） | 高（异步不阻塞） |
| 重复消费 | 可能（处理完未提交就宕机） | 可能（但可配合幂等） | 可能（提交失败时） |
| 消息丢失 | 可能（提交后处理失败） | 不会 | 不会 |
| 适用场景 | 容忍少量重复/丢失的日志类 | 高可靠场景（订单、支付） | 高吞吐 + 可容忍少量重复 |
| 推荐度 | 不推荐生产使用 | 推荐配合幂等 | 推荐配合兜底同步提交 |

## 一句话总结

**Offset 是消费者在 Partition 中的消费位置——自动提交简单但时机不可控可能重复消费或丢消息，手动提交让业务完成后精确控制提交时机，配合幂等消费即可实现可靠的 At Least Once 语义。**
