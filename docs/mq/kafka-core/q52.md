# Q52 Consumer 消费流程

Consumer poll() 流程经历 7 个步骤：协调器交互（连到 Coordinator 加入 Consumer Group 触发 Rebalance 分配 Partition）、定位消费位置（从 __consumer_offsets 读取上次提交的 offset）、拉取请求（向各 Partition 的 Leader 发送 FetchRequest 拉取消息）、反序列化（字节数组反序列化为消息对象）、拦截器（执行 ConsumerInterceptor.onConsume）、返回（消息列表返回给业务代码处理）、提交 offset（手动或自动提交消费位置）。poll() 是拉模式，max.poll.records 控制单次拉取条数，fetch.min.bytes 控制最小拉取字节数，注意 max.poll.interval.ms 两次 poll 间隔超时会被踢出 Group 触发 Rebalance。

## Consumer 代码实践

### Layer 1 — Consumer 基础配置

```yaml
# application.yml — Consumer 核心参数配置
spring:
  kafka:
    consumer:
      bootstrap-servers: localhost:9092
      group-id: order-consumer-group
      # 反序列化器：与 Producer 的序列化器对应
      key-deserializer: org.apache.kafka.common.serialization.StringDeserializer
      value-deserializer: org.springframework.kafka.support.serializer.JsonDeserializer
      # auto.offset.reset: 无已提交 offset 时的起始位置
      #   earliest — 从最早消息开始（可能重复消费）
      #   latest   — 从最新消息开始（可能丢失消息）
      #   none     — 无 offset 则抛异常
      auto-offset-reset: earliest
      # enable.auto.commit: 是否自动提交 offset
      #   true  — 后台线程定期提交（可能重复消费或丢消息）
      #   false — 手动提交（推荐，精确控制）
      enable-auto-commit: false
      # auto.commit.interval.ms: 自动提交间隔（仅 enable.auto.commit=true 时生效）
      auto-commit-interval: 5000
      # max.poll.records: 单次 poll() 返回的最大消息条数（默认 500）
      # 业务处理慢时建议调小，避免 max.poll.interval.ms 超时
      max-poll-records: 100
      # fetch.min.bytes: 单次拉取的最小字节数（默认 1）
      # 增大可批量拉取提高吞吐，但增加延迟
      fetch-min-size: 1
      # fetch.max.wait.ms: 不满足 fetch.min.bytes 时的最大等待时间（默认 500ms）
      fetch-max-wait: 500ms
      properties:
        # max.poll.interval.ms: 两次 poll() 之间的最大间隔
        # 超过此时间消费者被踢出 Group 触发 Rebalance（默认 300000 = 5分钟）
        max.poll.interval.ms: 300000
        # session.timeout.ms: 心跳超时时间（默认 45000 = 45秒）
        # Broker 在此时间内未收到心跳则判定消费者死亡
        session.timeout.ms: 45000
        # heartbeat.interval.ms: 心跳发送间隔（默认 3000 = 3秒）
        # 建议: session.timeout.ms 的 1/3
        heartbeat.interval.ms: 15000
```

```java
/**
 * Consumer 配置类（Java 方式）
 */
@Configuration
public class KafkaConsumerConfig {

    @Bean
    public ConsumerFactory<String, Object> consumerFactory() {
        Map<String, Object> config = new HashMap<>();
        config.put(ConsumerConfig.BOOTSTRAP_SERVERS_CONFIG, "localhost:9092");
        config.put(ConsumerConfig.GROUP_ID_CONFIG, "order-consumer-group");
        config.put(ConsumerConfig.KEY_DESERIALIZER_CLASS_CONFIG,
                StringDeserializer.class.getName());
        config.put(ConsumerConfig.VALUE_DESERIALIZER_CLASS_CONFIG,
                JsonDeserializer.class.getName());
        config.put(ConsumerConfig.AUTO_OFFSET_RESET_CONFIG, "earliest");
        // 关闭自动提交，使用手动提交
        config.put(ConsumerConfig.ENABLE_AUTO_COMMIT_CONFIG, false);
        // 限制单次 poll 条数，防止业务处理超时
        config.put(ConsumerConfig.MAX_POLL_RECORDS_CONFIG, 100);
        // 两次 poll 最大间隔（5分钟）
        config.put(ConsumerConfig.MAX_POLL_INTERVAL_MS_CONFIG, 300000);
        config.put(ConsumerConfig.SESSION_TIMEOUT_MS_CONFIG, 45000);
        config.put(ConsumerConfig.HEARTBEAT_INTERVAL_MS_CONFIG, 15000);
        config.put(ConsumerConfig.FETCH_MIN_BYTES_CONFIG, 1);
        return new DefaultKafkaConsumerFactory<>(config);
    }

    @Bean
    public ConcurrentKafkaListenerContainerFactory<String, Object>
            kafkaListenerContainerFactory(ConsumerFactory<String, Object> cf) {
        ConcurrentKafkaListenerContainerFactory<String, Object> factory =
                new ConcurrentKafkaListenerContainerFactory<>();
        factory.setConsumerFactory(cf);
        factory.setConcurrency(3); // 3 个消费线程
        // 手动提交模式
        factory.getContainerProperties()
                .setAckMode(ContainerProperties.AckMode.MANUAL_IMMEDIATE);
        return factory;
    }
}
```

### Layer 2 — poll() 消费循环（KafkaListener 内部机制）

```java
/**
 * poll() 消费循环：@KafkaListener 底层就是循环调用 poll()
 *
 * Spring Kafka 的 KafkaListenerContainer 内部执行流程：
 * 1. while(running) { ConsumerRecords records = consumer.poll(timeout); }
 * 2. 对每条记录调用 @KafkaListener 方法
 * 3. 根据 AckMode 决定是否提交 offset
 */
@Component
@Slf4j
public class OrderConsumer {

    /**
     * 方式 1：使用 @KafkaListener 注解（最常用）
     * Spring 自动管理 poll() 循环、Rebalance、Offset 提交
     */
    @KafkaListener(
        topics = "order-events",
        groupId = "order-consumer-group",
        // 可指定 Partition 消费
        // topicPartitions = @TopicPartition(topic = "order-events", partitions = {"0", "1"})
        concurrency = "3" // 3 个消费线程并行
    )
    public void onMessage(ConsumerRecord<String, String> record,
                         Acknowledgment ack) {
        long startTime = System.currentTimeMillis();
        try {
            log.info("收到消息: topic={}, partition={}, offset={}, key={}",
                    record.topic(), record.partition(), record.offset(), record.key());

            // 业务处理（注意：此处的耗时必须 < max.poll.interval.ms）
            processOrder(record.value());

            // 手动提交 Offset（AckMode.MANUAL_IMMEDIATE 模式下每条消息提交）
            ack.acknowledge();

            log.info("处理完成: 耗时={}ms", System.currentTimeMillis() - startTime);

        } catch (Exception e) {
            log.error("消费异常: offset={}, error={}", record.offset(), e.getMessage(), e);
            // 不提交 ack，下次 poll 会重新拉取此消息
            // 可配合死信队列处理毒消息
        }
    }

    /**
     * 方式 2：手动创建 Consumer 执行 poll() 循环
     * 展示 @KafkaListener 底层的 poll() 机制
     */
    public void manualPollLoop(ConsumerFactory<String, String> factory) {
        try (KafkaConsumer<String, String> consumer = factory.createConsumer()) {
            consumer.subscribe(List.of("order-events"));

            while (true) {
                // poll() 内部完成：Rebalance + 定位 offset + FetchRequest + 反序列化 + 拦截器
                ConsumerRecords<String, String> records =
                        consumer.poll(Duration.ofMillis(1000));

                // 返回的消息列表交给业务处理
                for (ConsumerRecord<String, String> record : records) {

                    }
                }

                // 手动同步提交 offset 到 __consumer_offsets
                consumer.commitSync();
            }
        }
    }
```

```java
/**
 * 自定义 Consumer 拦截器：实现 ConsumerInterceptor 接口
 * 在 poll() 返回消息前 (onConsume) 和提交 offset 后 (onCommit) 执行
 */
public class MetricsConsumerInterceptor implements ConsumerInterceptor<String, String> {

     * onConsume：poll() 返回消息前调用（步骤 5）

     */
    @Override
    public ConsumerRecords<String, String> onConsume(

        int count = 0;

        return records;
```

### Layer 4 — Offset 管理策略（手动提交 + Rebalance 安全处理）

```java
/**
 * Offset 管理策略：手动提交 + Rebalance 安全处理
 *
 * 核心问题：Rebalance 发生时，消费者可能正在处理消息但尚未提交 offset
 * 如果不做安全处理，会导致消息丢失或重复消费
 */
@Component
@Slf4j
public class SafeOffsetConsumer {

    // 本地缓存已处理但未提交的 offset
    private final Map<TopicPartition, OffsetAndMetadata> pendingOffsets = new ConcurrentHashMap<>();

    /**
     * 使用 ConsumerRebalanceListener 处理 Rebalance
     */
    public void startSafeConsumer(ConsumerFactory<String, String> factory) {
        try (KafkaConsumer<String, String> consumer = factory.createConsumer()) {

            // 订阅 Topic 并注册 Rebalance 监听器
            consumer.subscribe(List.of("order-events"), new ConsumerRebalanceListener() {

                /**
                 * 分区被撤销时调用（Rebalance 前）
                 * 必须在此提交已处理的 offset，防止重复消费
                 */
                @Override
                public void onPartitionsRevoked(Collection<TopicPartition> partitions) {
                    log.info("分区被撤销: {}", partitions);
                    // 提交本地缓存的 offset（关键！防止 Rebalance 后重复消费）
                    if (!pendingOffsets.isEmpty()) {
                        consumer.commitSync(pendingOffsets);
                        log.info("Rebalance 前已提交 offset: {}", pendingOffsets);
                        pendingOffsets.clear();
                    }
                }

                /**
                 * 新分区分配时调用（Rebalance 后）
                 * 可在此做初始化工作
                 */
                @Override
                public void onPartitionsAssigned(Collection<TopicPartition> partitions) {
                    log.info("新分区已分配: {}", partitions);
                    // 清空本地缓存
                    pendingOffsets.clear();
                }
            });

            // poll() 消费循环
            while (true) {
                ConsumerRecords<String, String> records =
                        consumer.poll(Duration.ofMillis(1000));

                for (ConsumerRecord<String, String> record : records) {
                    try {
                        // 业务处理
                        processOrder(record.value());

                        // 缓存已处理 offset（不立即提交）
                        pendingOffsets.put(
                                new TopicPartition(record.topic(), record.partition()),
                                new OffsetAndMetadata(record.offset() + 1)
                        );

                    } catch (Exception e) {
                        log.error("处理失败，停止消费此分区: offset={}",
                                record.offset(), e);
                        // 可选择 seek 回退到上次成功位置
                        consumer.seek(
                                new TopicPartition(record.topic(), record.partition()),
                                record.offset()
                        );
                        break; // 跳出循环，等待下次 poll 重试
                    }
                }

                // 定期批量提交（减少提交频率提高性能）
                if (!pendingOffsets.isEmpty()) {
                    consumer.commitAsync(pendingOffsets, (offsets, exception) -> {
                        if (exception != null) {
                            log.warn("异步提交失败: {}", exception.getMessage());
                        } else {
                            log.debug("异步提交成功: {}", offsets);
                            // 提交成功后清空缓存
                            pendingOffsets.clear();
                        }
                    });
                }
            }
        }
    }

    /**
     * 批量提交策略（性能优化）
     * 每处理 N 条消息提交一次，而非每条提交
     */
    @Component
    @Slf4j
    public static class BatchAckConsumer {

        private static final int BATCH_SIZE = 50; // 每 50 条提交一次
        private int processedCount = 0;
        private Acknowledgment pendingAck;

        @KafkaListener(topics = "order-events", groupId = "batch-consumer-group")
        public void onMessage(ConsumerRecord<String, String> record,
                              Acknowledgment ack) {
            try {
                processOrder(record.value());
                processedCount++;
                pendingAck = ack;

                // 每 BATCH_SIZE 条提交一次
                if (processedCount >= BATCH_SIZE) {
                    ack.acknowledge();
                    processedCount = 0;
                    pendingAck = null;
                    log.debug("批量提交: {} 条", BATCH_SIZE);
                }
            } catch (Exception e) {
                log.error("处理失败", e);
                // 提交已处理的消息，跳过失败的消息
                if (pendingAck != null) {
                    pendingAck.acknowledge();
                }
                processedCount = 0;
            }
        }
    }

    private static void processOrder(String orderJson) {
        // 业务逻辑
    }
}
```

## Consumer 关键参数

| 参数 | 默认值 | 作用 | 超时风险 |
|------|--------|------|----------|
| max.poll.interval.ms | 300000 (5分钟) | 两次 poll() 之间的最大间隔 | 超时被踢出 Group，触发 Rebalance，消息重复消费 |
| max.poll.records | 500 | 单次 poll() 返回的最大消息条数 | 过大导致处理超时触发 max.poll.interval.ms |
| session.timeout.ms | 45000 (45秒) | 心跳超时，Broker 判定消费者是否存活 | 超时被判定死亡，触发 Rebalance |
| heartbeat.interval.ms | 3000 (3秒) | 心跳发送间隔 | 过大导致 session.timeout.ms 内无心跳 |
| fetch.min.bytes | 1 | 单次拉取最小字节数 | 过大导致消息延迟（等待凑够字节） |
| fetch.max.wait.ms | 500 | 不满足 fetch.min.bytes 时的最大等待 | 增大可提高批量但增加延迟 |
| fetch.max.bytes | 52428800 (50MB) | 单次拉取最大字节数 | 过小限制单次拉取量，降低吞吐 |
| auto.offset.reset | latest | 无已提交 offset 时的起始位置 | earliest 可能重复消费，latest 可能丢消息 |
| enable.auto.commit | true | 是否自动提交 offset | true 可能重复消费或丢消息，建议 false |
| auto.commit.interval.ms | 5000 | 自动提交间隔 | 过大崩溃时丢失更多进度，过小增加写入压力 |
| partition.assignment.strategy | RangeAssignor | 分区分配策略 | 不合理可能导致分配不均衡 |

## 一句话总结

**Consumer poll() 的 7 步流程（Coordinator 交互 → 定位 offset → FetchRequest → 反序列化 → 拦截器 → 返回业务 → 提交 offset）中，max.poll.interval.ms 是最关键的超时参数，业务处理耗时超过此值会导致消费者被踢出 Group 触发 Rebalance 造成重复消费。**
