# Q99 跨机房同步

跨机房 Kafka 同步的核心方案有四种：MirrorMaker 2（开源推荐，Kafka 2.4+ 内置）、Confluent Replicator（商业版 Exactly-Once）、Cluster Linking（Kafka 3.6+ 原生轻量）、自研 Connect Source/Sink Connector，其中 MirrorMaker 2 是企业最常用的方案，配合单写多读架构可以大幅降低复杂度。

MM2 作为 Kafka 原生的跨集群同步方案，通过 Connect 框架运行，可以从源集群消费消息写入目标集群，自动进行 Topic 重命名（按 `source.cluster.alias` 前缀）和 Offset 转换，有效防止双向同步时的无限回环问题。Cluster Linking 则是 Kafka 3.6+ 推出的更轻量方案，无需额外进程直接在 Broker 间建立 Link。

## 跨机房同步代码配置

### Layer 1 — MirrorMaker 2 配置（双向同步 + 防回环）

```properties
# connect-mirror-maker.properties — MirrorMaker 2 核心配置文件
# 集群别名定义
clusters = beijing, shanghai
beijing.bootstrap.servers = beijing-kafka-broker1:9092,beijing-kafka-broker2:9092,beijing-kafka-broker3:9092
shanghai.bootstrap.servers = shanghai-kafka-broker1:9092,shanghai-kafka-broker2:9092,shanghai-kafka-broker3:9092

# 双向同步配置（beijing ↔ shanghai）
beijing->shanghai.enabled = true
shanghai->beijing.enabled = true

# 防止回环 — 关键配置
# replication.policy.class 使用 DefaultReplicationPolicy
# 源集群别名作为前缀：beijing.topic.name → shanghai.beijing.topic.name
# ShangHai 的消费者只消费 shanghai.* 前缀 Topic，不会回到 Beijing
replication.policy.separator = "."

# 同步策略
sync.topic.acls.enabled = true           # 同步 ACL 权限
sync.topic.configs.enabled = true        # 同步 Topic 配置（分区数、副本数）
emit.heartbeats.enabled = true           # 心跳检测同步状态
emit.checkpoints.enabled = true          # Offset 检查点，用于故障恢复

# Offset 转换 — Consumer 可以在 B 集群找到对应 Offset
# Beijing 集群 offset=100 → ShangHai 集群对应 offset 通过 RemoteClusterUtils 转换
offset-syncs.topic.replication.factor = 3
checkpoints.topic.replication.factor = 3
heartbeats.topic.replication.factor = 3

# 性能调优
tasks.max = 16                           # 并行同步 Task 数
offset.flush.interval.ms = 10000         # Offset 刷新间隔
offset.flush.timeout.ms = 5000           # Offset 刷新超时
```

### Layer 2 — Cluster Linking 配置（Kafka 3.6+ 原生方案）

```shell
#!/bin/bash
# kafka-cluster-links.sh — 建立跨集群 Link（Kafka 3.6+）

# Step 1: 在 Shanghai 集群上创建指向 Beijing 的 Link
# 注意: Link 是单向的，从 Beijing（源）→ Shanghai（目标）
kafka-cluster-links.sh \
  --bootstrap-server shanghai-kafka-broker1:9092 \
  --create \
  --link-id beijing-to-shanghai-link \
  --config bootstrap.servers=beijing-kafka-broker1:9092,beijing-kafka-broker2:9092 \
  --config consumer.offset.sync.enable=true \
  --config consumer.offset.sync.ms=30000 \
  --config auto.create.mirror.topics.enable=true \
  --config auto.create.mirror.topics.filters='{"topicFilters": [\
    {"name": "orders", "patternType": "MATCH", "filterType": "INCLUDE"},\
    {"name": "payments", "patternType": "MATCH", "filterType": "INCLUDE"},\
    {"name": "inventory", "patternType": "MATCH", "filterType": "INCLUDE"}\
  ]}'

# Step 2: 查看 Link 状态
kafka-cluster-links.sh \
  --bootstrap-server shanghai-kafka-broker1:9092 \
  --list

# Step 3: 查看 Mirror Topic 同步延迟
kafka-cluster-links.sh \
  --bootstrap-server shanghai-kafka-broker1:9092 \
  --describe --link-id beijing-to-shanghai-link

# Step 4: 暂停 / 恢复 Link（用于维护）
kafka-cluster-links.sh --bootstrap-server shanghai-kafka-broker1:9092 \
  --pause --link-id beijing-to-shanghai-link

kafka-cluster-links.sh --bootstrap-server shanghai-kafka-broker1:9092 \
  --resume --link-id beijing-to-shanghai-link
```

### Layer 3 — 单写多读架构配置（推荐生产实践）

```java
// 单写多读架构 — 生产端只写北京，消费端就近消费
// 生产端配置（所有机房的服务统一写北京集群）
@Configuration
public class ProducerConfig {

    @Bean
    public KafkaTemplate<String, String> kafkaTemplate() {
        Map<String, Object> props = new HashMap<>();
        // 只有北京集群地址 — 单写
        props.put(ProducerConfig.BOOTSTRAP_SERVERS_CONFIG,
            "beijing-kafka-broker1:9092,beijing-kafka-broker2:9092");
        props.put(ProducerConfig.ACKS_CONFIG, "all");
        props.put(ProducerConfig.RETRIES_CONFIG, 3);
        props.put(ProducerConfig.COMPRESSION_TYPE_CONFIG, "lz4");
        return new KafkaTemplate<>(new DefaultKafkaProducerFactory<>(props));
    }
}

// 消费端配置（每个机房消费本地集群 — 就近消费）
@Configuration
public class ShanghaiConsumerConfig {

    @Bean
    public KafkaListenerContainerFactory<?> shanghaiFactory() {
        Map<String, Object> props = new HashMap<>();
        // Shanghai 消费者只连 Shanghai 本地集群
        props.put(ConsumerConfig.BOOTSTRAP_SERVERS_CONFIG,
            "shanghai-kafka-broker1:9092,shanghai-kafka-broker2:9092");
        props.put(ConsumerConfig.GROUP_ID_CONFIG, "shanghai-order-service");
        props.put(ConsumerConfig.AUTO_OFFSET_RESET_CONFIG, "earliest");

        ConcurrentKafkaListenerContainerFactory<String, String> factory =
            new ConcurrentKafkaListenerContainerFactory<>();
        factory.setConsumerFactory(new DefaultKafkaConsumerFactory<>(props));
        return factory;
    }

    // 消费 Mirror 过来的 Topic — 前缀为 beijing.
    @KafkaListener(topics = "beijing.orders", containerFactory = "shanghaiFactory")
    public void consumeFromMirror(String message) {
        // 上海服务就近消费本地 Mirror 数据，延迟低
        processOrder(message);
    }
}
```

### Layer 4 — 同步延迟监控与告警

```shell
#!/bin/bash
# mirror-lag-monitor.sh — 跨机房同步延迟监控脚本

# 获取 MirrorMaker 2 所有 Mirror Topic 的 Lag
# 通过 Kafka Consumer Group 命令查看 MM2 内部 Consumer Group Lag
MM2_GROUP="mirrormaker2-beijing->shanghai"
BOOTSTRAP="shanghai-kafka-broker1:9092"
ALERT_THRESHOLD=50000  # Lag 超过 5 万条触发告警

# 查询 MirrorMaker 2 消费者组的 Lag
kafka-consumer-groups.sh \
  --bootstrap-server $BOOTSTRAP \
  --group $MM2_GROUP \
  --describe 2>/dev/null | while read line; do
    # 解析 Lag 值
    LAG=$(echo "$line" | awk '{print $6}')
    TOPIC=$(echo "$line" | awk '{print $1}')

    if [[ "$LAG" =~ ^[0-9]+$ ]] && [ "$LAG" -gt $ALERT_THRESHOLD ]; then
      echo "[ALERT] Topic=$TOPIC Lag=$LAG exceeds threshold=$ALERT_THRESHOLD"
      # 触发告警 — 飞书 / PagerDuty / Prometheus
      curl -X POST "https://open.feishu.cn/open-apis/bot/v2/hook/xxx" \
        -H "Content-Type: application/json" \
        -d "{\"msg_type\":\"text\",\"content\":{\"text\":\
\"跨机房同步告警: Topic=$TOPIC Lag=$LAG > $ALERT_THRESHOLD\"}}"
    fi
  done

# 网络中断恢复策略
# 1. MM2 本地缓存: 源集群保留足够长的消息（retention.ms=7天）
# 2. 断网时生产端继续写 Beijing 集群
# 3. 恢复后 MM2 自动从 checkpoint offset 继续追赶
# 4. 监控恢复速率: (catchup_lag / time_elapsed) 评估完全 catch up 时间
```
