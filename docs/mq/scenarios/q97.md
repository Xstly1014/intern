# Q97 延迟任务取消订单

"下单 30 分钟未支付自动取消"是高频面试题，业界有五种主流方案：RabbitMQ TTL+DLX（利用死信队列实现延迟）、RabbitMQ 延迟插件（x-delayed-message 原生支持）、Kafka 多级轮询模拟（非原生，复杂）、Redis ZSet（轻量高效，中小规模首选）、时间轮（Netty HashedWheelTimer，内存级超低延迟）。实际选型遵循"已有 RabbitMQ 优先延迟插件，中小规模推荐 Redis ZSet，大规模自研时间轮+持久化"的路径。

## 代码实现：TTL+DLX、延迟插件、Redis ZSet、双轨容灾

### Layer 1 — RabbitMQ TTL + DLX 方案（队头阻塞）

```java
@Configuration
public class TtlDlxOrderCancelConfig {

    // ============ 死信队列（真正消费取消订单） ============
    @Bean
    public Queue orderCancelQueue() {
        return QueueBuilder.durable("queue.order.cancel").build();
    }

    // ============ 延迟队列（TTL 30分钟，过期转 DLX） ============
    @Bean
    public Queue orderDelayQueue() {
        return QueueBuilder.durable("queue.order.delay")
                .withArgument("x-dead-letter-exchange", "dlx.order.exchange")  // 死信交换机
                .withArgument("x-dead-letter-routing-key", "order.cancel")      // 死信路由键
                .withArgument("x-message-ttl", 30 * 60 * 1000)                  // TTL=30分钟
                .build();
    }

    // ============ 死信交换机 ============
    @Bean
    public DirectExchange dlxExchange() {
        return new DirectExchange("dlx.order.exchange");
    }

    @Bean
    public Binding dlxBinding() {
        return BindingBuilder.bind(orderCancelQueue())
                .to(dlxExchange())
                .with("order.cancel");
    }

    // ============ Publisher: 下单时发送延迟消息 ============
    @Service
    @RequiredArgsConstructor
    public class OrderDelayPublisher {
        private final RabbitTemplate rabbitTemplate;

        public void sendDelayCancel(String orderId) {
            // 发送到延迟队列（没有消费者，等待 TTL 过期进 DLX）
            rabbitTemplate.convertAndSend("", "queue.order.delay",
                    new OrderCancelMessage(orderId));
            log.info("订单 {} 延迟取消消息已发送", orderId);
        }
    }

    // ============ Consumer: 取消订单消费者 ============
    @RabbitListener(queues = "queue.order.cancel")
    public void onDelayCancel(OrderCancelMessage msg, Message amqpMsg) {
        String orderId = msg.getOrderId();
        // 检查订单状态
        Order order = orderService.getById(orderId);
        if (order != null && OrderStatus.UNPAID.equals(order.getStatus())) {
            // 未支付 → 取消订单
            orderService.cancel(orderId);
            log.info("订单 {} 超时未支付，已自动取消", orderId);
        }
        // 幂等：已支付/已取消则直接 ACK 忽略
    }
}
```

### Layer 2 — RabbitMQ 延迟插件方案（推荐）

```java
@Configuration
public class DelayedMessageConfig {

    public static final String EXCHANGE_ORDER_DELAY = "exchange.order.delay";
    public static final String QUEUE_ORDER_DELAY = "queue.order.delay.cancel";

    // ============ 声明 x-delayed-message Exchange ============
    @Bean
    public Exchange orderDelayExchange() {
        return ExchangeBuilder
                .directExchange(EXCHANGE_ORDER_DELAY)
                .delayed()   // 标记为延迟 Exchange
                .durable(true)
                .withArgument("x-delayed-type", "direct")  // 底层路由类型
                .build();
    }

    // ============ 延迟队列绑定 ============
    @Bean
    public Queue orderDelayQueue() {
        return QueueBuilder.durable(QUEUE_ORDER_DELAY).build();
    }

    @Bean
    public Binding delayBinding() {
        return BindingBuilder.bind(orderDelayQueue())
                .to(orderDelayExchange())
                .with("order.delay.cancel")
                .noargs();
    }

    // ============ Publisher: 带 x-delay header ============
    @Service
    @RequiredArgsConstructor
    public class OrderDelayedPublisher {
        private final RabbitTemplate rabbitTemplate;

        public void publishOrderDelay(String orderId) {
            OrderCancelMessage msg = new OrderCancelMessage(orderId);

            rabbitTemplate.convertAndSend(
                EXCHANGE_ORDER_DELAY,
                "order.delay.cancel",
                msg,
                message -> {
                    // 关键：设置延迟时间（毫秒）
                    message.getMessageProperties().setHeader("x-delay", 30 * 60 * 1000);
                    return message;
                }
            );
            log.info("订单 {} 延迟取消消息已发送（x-delay=30min）", orderId);
        }
    }

    // ============ Consumer: 到期后直接投递 ============
    @RabbitListener(queues = QUEUE_ORDER_DELAY)
    public void onDelayedCancel(OrderCancelMessage msg) {
        // 30分钟后此方法被触发，无需关注 DLX/死信
        Order order = orderService.getById(msg.getOrderId());
        if (order != null && OrderStatus.UNPAID.equals(order.getStatus())) {
            orderService.cancel(msg.getOrderId());
            log.info("延迟插件触发：订单 {} 已取消", msg.getOrderId());
        }
    }
}
```

### Layer 3 — Redis ZSet 方案（中小规模首选）

```java
@Component
@RequiredArgsConstructor
public class RedisDelayQueueJob {
    private final StringRedisTemplate redisTemplate;
    private final OrderService orderService;
    private final RedissonClient redissonClient;

    private static final String DELAY_KEY = "order:delay:zset";
    private static final String LOCK_KEY  = "lock:order:scan";

    // ============ 下单时写入 ZSet ============
    public void addDelayTask(String orderId, int delayMinutes) {
        long expireTime = System.currentTimeMillis() + delayMinutes * 60 * 1000L;
        redisTemplate.opsForZSet().add(DELAY_KEY, orderId, expireTime);
    }

    // ============ 支付成功时移除 ============
    public void removeDelayTask(String orderId) {
        redisTemplate.opsForZSet().remove(DELAY_KEY, orderId);
    }

    // ============ 定时扫描（每 1 秒） ============
    @Scheduled(fixedDelay = 1000)
    public void scanAndCancel() {
        RLock lock = redissonClient.getLock(LOCK_KEY);
        try {
            // 分布式锁，防止多实例重复扫描
            if (lock.tryLock(0, 2, TimeUnit.SECONDS)) {
                long now = System.currentTimeMillis();
                // 拉取 score <= now 的所有到期 orderId
                Set<String> expiredOrders = redisTemplate.opsForZSet()
                        .rangeByScore(DELAY_KEY, 0, now);

                if (expiredOrders != null && !expiredOrders.isEmpty()) {
                    for (String orderId : expiredOrders) {
                        // Lua 原子操作：ZREM + 查状态 + 取消
                        processWithLua(orderId);
                    }
                }
            }
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        } finally {
            if (lock.isHeldByCurrentThread()) {
                lock.unlock();
            }
        }
    }

    // ============ Lua 脚本原子处理 ============
    private void processWithLua(String orderId) {
        String luaScript =
            "local removed = redis.call('ZREM', KEYS[1], ARGV[1]) " +
            "if removed == 1 then " +
            "    return 1 " +    // 成功移除，允许取消
            "else " +
            "    return 0 " +    // 已被支付回调移除
            "end";

        Long result = redisTemplate.execute(
            new DefaultRedisScript<>(luaScript, Long.class),
            Collections.singletonList(DELAY_KEY),
            orderId
        );

        if (result != null && result == 1) {
            // 原子确认后执行取消
            Order order = orderService.getById(orderId);
            if (order != null && OrderStatus.UNPAID.equals(order.getStatus())) {
                orderService.cancel(orderId);
                log.info("Redis ZSet 触发：订单 {} 已取消", orderId);
            }
        }
    }
}
```

### Layer 4 — 生产环境双轨容灾方案

```java
@Component
@RequiredArgsConstructor
public class OrderCancelOrchestrator {
    private final OrderDelayedPublisher rabbitMqPublisher;  // Layer 2
    private final RedisDelayQueueJob redisDelayJob;          // Layer 3
    private final OrderService orderService;

    /**
     * 下单时双写：主链路 MQ 延迟插件 + 兜底 Redis ZSet
     */
    public void afterOrderCreated(String orderId) {
        // 主链路：RabbitMQ 延迟插件
        rabbitMqPublisher.publishOrderDelay(orderId);

        // 兜底链路：Redis ZSet（MQ 故障时兜底）
        redisDelayJob.addDelayTask(orderId, 30);

        log.info("订单 {} 双轨延迟取消已登记", orderId);
    }

    /**
     * 支付回调时双清
     */
    public void afterPaymentSuccess(String orderId) {
        // Redis ZSet 先移除（支付回调比 MQ 快）
        redisDelayJob.removeDelayTask(orderId);

        // 更新订单状态为 PAID
        orderService.markAsPaid(orderId);

        // MQ 延迟消息到期时通过状态判断跳过（幂等）
        // Order 状态已是 PAID → Consumer 检查后直接 ACK 不取消
    }
}
```

## 五种延迟任务方案全面对比

| 维度 | TTL + DLX | 延迟插件 | Kafka 模拟 | Redis ZSet | 时间轮 |
|---|---|---|---|---|---|
| 实现复杂度 | 中（需声明 DLX+死信队列） | 低（只需声明 delayed Exchange） | 高（多级 Topic 轮询递进） | 低（定时任务+ZRTANGEBYSCORE） | 中（梯度调度 O(1)） |
| 消息可靠性 | 高（消息持久化 ACK） | 高（消息持久化 ACK） | 高（持久化 offset） | 中（Redis 重启数据丢失） | 低（纯内存重启全丢） |
| 精度 | 低（队头阻塞，后面的消息可能延迟） | 中（插件内部排序，毫秒级） | 低（依赖轮询间隔） | 高（定时扫描 + Redis 原子操作） | 极高（微秒级） |
| 吞吐量 | 万级/秒 | 万级/秒（插件性能瓶颈） | 十万级/秒 | 万级/秒（单线程 Redis） | 百万级/秒 |
| 删除任务 | 不支持（消息已入队无法删除） | 不支持（消息已入队无法删除） | 不支持 | 支持（ZREM 即时移除） | 支持（取消 TimerTask） |
| 队头阻塞 | 有（致命缺陷） | 无 | 无 | 无 | 无 |
| 外部依赖 | RabbitMQ | RabbitMQ + 插件 | Kafka | Redis | 无（纯内存） |
| 水平扩展 | 支持（多队列分摊） | 有限（Exchange 单点） | 天然支持 | 支持（分布式锁） | 不支持（单 JVM） |
| 适用场景 | 不推荐（已过时） | 已有 RabbitMQ 首选 | 不推荐用于延迟任务 | 中小规模首选 | 大规模/低延迟场景 |

## 一句话总结

**下单延迟取消订单首选 RabbitMQ 延迟插件（x-delayed-message + x-delay header），中小规模推荐 Redis ZSet（定时扫描 + Lua 脚本原子操作 + ZREM 即时移除），生产环境用"MQ 延迟插件主链路 + Redis ZSet 兜底链路"双轨容灾，支付回调通过 ZREM 即时移除和 Consumer 状态幂等校验防止重复取消。**
