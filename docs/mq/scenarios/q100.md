# Q100 系统设计综合题

设计日活千万级 IM 系统的核心在于"消息不丢、不重、有序、低延迟"四大需求：通过 acks=all + 本地消息表确保不丢，雪花 ID + Redis SETNX 去重确保不重，sessionId hash 到同一 Partition 确保有序，Kafka linger.ms=0 + WebSocket 长连接确保低延迟，存储采用 Redis 热缓存 + MySQL 分库分表 + HBase 冷归档三层架构。

从用户 A 发送消息到用户 B 接收，整个链路经过 7 层处理：Gateway 鉴权限流 → Message Service 生成雪花 ID 并落地本地消息表 → Kafka 按 sessionId hash 分区 → Consumer 手动提交 + 幂等去重 → 三层存储（Redis 热 / MySQL 温 / HBase 冷）→ Push Service 通过 WebSocket 长连接推送到用户 B。四大需求每层都有对应保障。

## IM 系统核心代码实现

### Layer 1 — 消息服务发消息（雪花 ID + 本地消息表 + KafkaTemplate）

```java
// MessageService.java — 消息发送核心服务
@Service
public class MessageService {

    @Autowired private SnowflakeIdGenerator idGenerator; // 雪花算法
    @Autowired private LocalMessageTableMapper msgMapper; // 本地消息表
    @Autowired private KafkaTemplate<String, Message> kafkaTemplate;
    @Autowired private RedisTemplate<String, String> redisTemplate;

    /**
     * 发送消息 — 保证不丢的核心流程
     */
    @Transactional(rollbackFor = Exception.class)
    public SendResult sendMessage(SendRequest req) {
        // Step 1: 雪花算法生成全局唯一 messageId
        long messageId = idGenerator.nextId();

        // Step 2: 写入本地消息表（与业务在同一事务）
        MessageEntity entity = new MessageEntity();
        entity.setMessageId(messageId);
        entity.setSessionId(req.getSessionId());
        entity.setSenderId(req.getSenderId());
        entity.setReceiverId(req.getReceiverId());
        entity.setContent(req.getContent());
        entity.setStatus(MessageStatus.PENDING);  // 待发送
        entity.setCreateTime(System.currentTimeMillis());
        msgMapper.insert(entity);  // INSERT INTO message_local(...)

        // Step 3: 投递到 Kafka（带回调处理失败）
        // 按 sessionId hash 到固定 Partition — 保证有序
        ProducerRecord<String, Message> record = new ProducerRecord<>(
            "im-message-topic",                          // Topic
            req.getSessionId(),                          // Key = sessionId
            buildMessageDTO(entity)                       // Value
        );

        kafkaTemplate.send(record).addCallback(
            success -> {
                // 发送成功 → 更新本地消息表状态
                msgMapper.updateStatus(messageId, MessageStatus.SENT);
                log.info("Message sent to Kafka: messageId={}, offset={}",
                    messageId, success.getRecordMetadata().offset());
            },
            failure -> {
                // 发送失败 → 标记失败，定时任务重试
                msgMapper.updateStatus(messageId, MessageStatus.SEND_FAILED);
                log.error("Failed to send message: messageId={}", messageId, failure);
            }
        );

        return SendResult.builder()
            .messageId(messageId)
            .status(SendStatus.ACCEPTED)
            .build();
    }
}
```

### Layer 2 — 消费者保证不丢不重（手动提交 + Redis SETNX 去重 + 幂等）

```java
// MessageConsumer.java — 消费端可靠性保障
@Component
public class MessageConsumer {

    @Autowired private RedisTemplate<String, String> redisTemplate;
    @Autowired private MessageStoreService storeService;
    @Autowired private PushService pushService;

    /**
     * 消费消息 — 手动提交 Offset + 幂等去重
     * 不丢: 手动提交，只有处理成功才 commit
     * 不重: Redis SETNX 幂等校验，重复消息直接跳过
     */
    @KafkaListener(topics = "im-message-topic", concurrency = "6")
    public void consume(ConsumerRecord<String, Message> record,
                         Acknowledgment ack) {
        Message msg = record.value();
        String dedupKey = "msg:dedup:" + msg.getMessageId();

        try {
            // Step 1: Redis SETNX 幂等去重 — TTL 24小时
            // SETNX 返回 true 表示 key 不存在，首次处理
            // SETNX 返回 false 表示已处理过，跳过（不重）
            Boolean firstTime = redisTemplate.opsForValue()
                .setIfAbsent(dedupKey, "1", Duration.ofHours(24));

            if (Boolean.FALSE.equals(firstTime)) {
                // 重复消息 — 直接确认，不重复处理
                log.warn("Duplicate message ignored: messageId={}", msg.getMessageId());
                ack.acknowledge();  // 仍然 ack，避免重试
                return;
            }

            // Step 2: 幂等写 DB — messageId 作为唯一索引兜底
            boolean stored = storeService.tryInsert(msg);
            if (!stored) {
                // DB 唯一索引冲突，重复消息
                log.warn("DB unique index conflict: messageId={}", msg.getMessageId());
                ack.acknowledge();
                return;
            }

            // Step 3: Push 给接收方
            pushService.pushToUser(msg.getReceiverId(), msg);

            // Step 4: 处理成功后手动提交 Offset
            ack.acknowledge();

        } catch (Exception e) {
            // 异常不 ack — Kafka 会重新投递（At-Least-Once）
            // 下次消费时 SETNX 和 DB 唯一索引保证幂等
            log.error("Consumer error, will retry: messageId={}",
                msg.getMessageId(), e);
            throw e;  // 抛异常，Kafka 重试
        }
    }
}
```

### Layer 3 — 有序性保证（sessionId hash 到 Partition + 单线程消费）

```java
// 有序性设计 — 三层保障

// ===== 第1层: Producer 按 sessionId 路由到固定 Partition =====
// 已在 Layer 1 的 sendMessage 中实现:
// new ProducerRecord<>("im-message-topic", sessionId, message)
// Kafka 默认按 key hash: Math.abs(sessionId.hashCode()) % partitionCount
// 同一 session 的所有消息必然进入同一个 Partition

// ===== 第2层: 消费者单线程处理每个 Partition =====
// Kafka 保证同一 Partition 的消息由 Consumer Group 中同一 Consumer 处理
// concurrency=6 启动 6 个线程，每个线程独立处理分配的 Partition
// 单 Partition 内消息按 offset 顺序消费，天然有序

// ===== 第3层: 消息序列号辅助排序 =====
@Data
public class Message {
    private Long messageId;       // 雪花 ID（全局递增）
    private String sessionId;     // 会话 ID → hash key
    private Long seq;             // 会话内序列号，用于客户端排序
    private String senderId;
    private String receiverId;
    private String content;
    private Long timestamp;

    /**
     * Producer 侧生成递增序列号
     * 使用 Redis INCR 每次发送前递增
     */
    public static Message create(String sessionId, String senderId,
                                  String content, StringRedisTemplate redis) {
        Long seq = redis.opsForValue()
            .increment("seq:" + sessionId);  // 会话内自增序号
        Message msg = new Message();
        msg.setMessageId(new SnowflakeIdGenerator().nextId());
        msg.setSessionId(sessionId);
        msg.setSeq(seq);           // 接收方按 seq 排序展示
        msg.setSenderId(senderId);
        msg.setContent(content);
        msg.setTimestamp(System.currentTimeMillis());
        return msg;
    }
}
```

### Layer 4 — 低延迟推送（WebSocket 长连接 + Redis 缓存）

```java
// PushService.java — 低延迟消息推送
@Service
public class PushService {

    // userId → WebSocketSession 映射
    private final ConcurrentHashMap<String, WebSocketSession> sessionMap
        = new ConcurrentHashMap<>();

    @Autowired private StringRedisTemplate redisTemplate;

    /**
     * 推送消息给接收方 — 低延迟核心
     */
    public void pushToUser(String userId, Message msg) {
        // Step 1: 写入 Redis 热缓存（ZSET — 最近 100 条消息）
        String cacheKey = "msg:recent:" + msg.getSessionId();
        redisTemplate.opsForZSet().add(cacheKey,
            JSON.toJSONString(msg), msg.getTimestamp());
        // 只保留最近 100 条
        redisTemplate.opsForZSet()
            .removeRange(cacheKey, 0, -101);

        // Step 2: WebSocket 实时推送
        WebSocketSession session = sessionMap.get(userId);
        if (session != null && session.isOpen()) {
            try {
                session.sendMessage(new TextMessage(
                    JSON.toJSONString(msg)));
            } catch (IOException e) {
                log.error("WebSocket push failed: userId={}", userId, e);
                sessionMap.remove(userId);  // 移除失效连接
            }
        }
        // 如果用户不在线: 消息已持久化，上线后从 Redis/DB 拉取
    }

    // WebSocket 连接管理
    @OnOpen
    public void onOpen(Session session) {
        String userId = getUserIdFromSession(session);
        sessionMap.put(userId, session);
        log.info("WS connected: userId={}, total={}", userId, sessionMap.size());
    }

    @OnClose
    public void onClose(Session session) {
        String userId = getUserIdFromSession(session);
        sessionMap.remove(userId);
    }
}
```

### Layer 5 — 群聊 Fanout（一条消息写入 N 个用户队列 + 已读回执）

```java
// GroupChatService.java — 群聊消息分发
@Service
public class GroupChatService {

    @Autowired private KafkaTemplate<String, Message> kafkaTemplate;
    @Autowired private GroupMemberService groupMemberService;
    @Autowired private RedisTemplate<String, String> redisTemplate;

    /**
     * 群聊发送 — 一条消息 Fanout 到 N 个用户队列
     */
    @Transactional
    public void sendGroupMessage(GroupMessageRequest req) {
        // Step 1: 获取群成员列表（从 Redis 缓存）
        List<String> memberIds = groupMemberService
            .getGroupMembers(req.getGroupId());

        // Step 2: 雪花 ID
        SnowflakeIdGenerator idGen = new SnowflakeIdGenerator();

        // Step 3: 为每个群成员写入消息到对应的用户队列 Topic
        for (String memberId : memberIds) {
            // 跳过发送者自己
            if (memberId.equals(req.getSenderId())) continue;

            Message msg = Message.builder()
                .messageId(idGen.nextId())
                .groupId(req.getGroupId())
                .senderId(req.getSenderId())
                .receiverId(memberId)           // 每个成员作为接收方
                .sessionId("group:" + req.getGroupId())
                .content(req.getContent())
                .messageType(MessageType.GROUP_CHAT)
                .timestamp(System.currentTimeMillis())
                .build();

            // 每个用户的消息写入各自 session Queue 的 Kafka Topic
            // 有序性: 按 (groupId + memberId) hash → 同一 Partition
            String routingKey = req.getGroupId() + ":" + memberId;
            kafkaTemplate.send(
                "im-message-topic",             // 主消息 Topic
                routingKey,                     // 路由 Key
                msg
            );
        }

        log.info("Group message fanout: groupId={}, members={}",
            req.getGroupId(), memberIds.size() - 1);
    }
}

// ReadReceiptService.java — 已读回执独立处理
@Service
public class ReadReceiptService {

    @Autowired private KafkaTemplate<String, ReadReceipt> kafkaTemplate;

    /**
     * 已读回执 — 独立 Topic，不影响主消息通道
     */
    public void sendReadReceipt(String userId, String sessionId, Long lastReadMsgId) {
        ReadReceipt receipt = ReadReceipt.builder()
            .userId(userId)
            .sessionId(sessionId)
            .lastReadMessageId(lastReadMsgId)
            .readTime(System.currentTimeMillis())
            .build();

        // 投递到独立的 read-receipt Topic
        kafkaTemplate.send("read-receipt-topic", sessionId, receipt);

        // 消费者侧: 更新 Redis ZSET 中消息的 read 状态
        // 发送方查询时: 从 Redis 获取最新已读位置
    }
}
```

| 需求维度 | 实现方案 | 关键配置 |
|---|---|---|
| **不丢失** | acks=all + 本地消息表 + Consumer 手动提交 + retries=3 | `acks=all`, `min.insync.replicas=2`, `enable.auto.commit=false`, `replication.factor=3` |
| **不重复** | 雪花算法 messageId + Redis SETNX 去重 TTL 24h + DB 唯一索引兜底 | `SETNX dedup_key TTL 86400`, `UNIQUE KEY uk_message_id` |
| **有序性** | Producer 按 sessionId hash → 同一 Partition + 单线程消费 + seq 序号 | `ProducerRecord(key=sessionId)`, `concurrency=1 per partition`, `max.in.flight.requests=1` |
| **低延迟** | Kafka linger.ms=0 + acks=1 + WebSocket 长连接 Push + Redis 热缓存 | `linger.ms=0`, `acks=1`, `WebSocket session pool`, `ZSET recent 100` |
| **高可用** | 多 Broker + 3 副本 + Consumer Group Rebalance + 异地多活 | `replication.factor=3`, `group.id`, `session.timeout.ms=30000` |
| **存储分层** | Redis 热层(100条) → MySQL 分表(100库×100表) → HBase 冷归档(90天) | `user_id % 100 → DB`, `TTL 冷数据迁移`, `ZSET 热缓存` |
| **群聊 Fanout** | 1 条群消息 → N 条独立消息写入用户队列 | 异步批量写，防止群聊放大效应 |
| **已读回执** | 独立 Topic + 异步处理 + Redis 状态缓存 | `read-receipt-topic` 独立，不阻塞主通道 |

## 一句话总结

**日活千万 IM 系统的可靠性设计围绕"不丢(acks=all+本地消息表)、不重(雪花ID+SETNX去重)、有序(sessionId hash到同一Partition)、低延迟(linger.ms=0+WebSocket)"四大核心展开，存储采用 Redis 热缓存 + MySQL 分库分表 + HBase 冷归档三层架构，群聊通过 Fanout 模式将一条消息分发到 N 个用户队列，已读回执使用独立 Topic 异步处理，从而在保证消息可靠性的同时做到端到端延迟低于 100ms。**
