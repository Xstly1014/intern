# Q96 广播通知

广播通知的核心是在 MQ 层面实现一条消息被多个服务各自独立消费——RabbitMQ 用 Fanout Exchange 将消息复制到所有绑定队列，Kafka 用多个独立 Consumer Group 各自订阅同一 Topic 实现"逻辑广播"。实际项目中配合 WebSocket/SSE 完成服务间分发后的实时终端推送。

上图全景对比了两大广播方案：左侧 **RabbitMQ Fanout Exchange** 是经典广播模式，Exchange 将消息复制到所有绑定队列，每个消费者获得独立副本；右侧 **Kafka 多 Consumer Group** 利用不同 Group 独立 offset 机制实现"逻辑广播"，每个 Group 都能消费到完整消息。底部给出了实时推送（WebSocket/SSE）的对接方案。

## 代码实现：RabbitMQ Fanout + Kafka 多 Group + WebSocket 实时推送

### Layer 1 — RabbitMQ Fanout Exchange 广播配置

```java
// ============ 配置类 ============
@Configuration
public class FanoutBroadcastConfig {

    public static final String EXCHANGE_NAME = "broadcast.notification.fanout";

    @Bean
    public FanoutExchange broadcastExchange() {
        return ExchangeBuilder.fanoutExchange(EXCHANGE_NAME)
                .durable(true)
                .build();
    }

    // ============ Publisher ============
    @Service
    @RequiredArgsConstructor
    public class AnnouncementPublisher {
        private final RabbitTemplate rabbitTemplate;

        public void publish(String announcementId, String content) {
            // 消息体只包含公告内容，无 routing key
            Message message = MessageBuilder
                    .withBody(content.getBytes(StandardCharsets.UTF_8))
                    .setMessageId(announcementId)
                    .setContentType("application/json")
                    .build();
            // Fanout Exchange routingKey 为空，自动忽略
            rabbitTemplate.convertAndSend(EXCHANGE_NAME, "", message);
            log.info("广播公告 {} 已发布", announcementId);
        }
    }

    // ============ Consumer A — 库存服务 ============
    @Bean
    public Queue queueInventory() {
        return QueueBuilder.nonDurable("temp.inventory.announce")  // 临时队列
                .autoDelete()                                       // 断开自动删除
                .build();
    }

    @Bean
    public Binding bindingInventory(FanoutExchange exchange, Queue queueInventory) {
        return BindingBuilder.bind(queueInventory).to(exchange);
    }

    @RabbitListener(queues = "temp.inventory.announce")
    public void onAnnouncement(Message msg) {
        String content = new String(msg.getBody(), StandardCharsets.UTF_8);
        log.info("库存服务收到公告: {}", content);
        // 1. 更新库存面板提示
        // 2. WebSocket 推送在线用户
    }

    // ============ Consumer B — 积分服务 ============
    @Bean
    public Queue queuePoints() {
        return QueueBuilder.nonDurable("temp.points.announce")
                .autoDelete()
                .build();
    }

    @Bean
    public Binding bindingPoints(FanoutExchange exchange, Queue queuePoints) {
        return BindingBuilder.bind(queuePoints).to(exchange);
    }

    @RabbitListener(queues = "temp.points.announce")
    public void onAnnouncement(Message msg) {
        String content = new String(msg.getBody(), StandardCharsets.UTF_8);
        // 积分服务处理公告逻辑
    }

    // ============ Consumer C — 短信服务 ============
    @Bean
    public Queue queueSms() {
        return QueueBuilder.nonDurable("temp.sms.announce").autoDelete().build();
    }

    @Bean
    public Binding bindingSms(FanoutExchange exchange, Queue queueSms) {
        return BindingBuilder.bind(queueSms).to(exchange);
    }

    @RabbitListener(queues = "temp.sms.announce")
    public void onAnnouncement(Message msg) {
        // 短信推送公告内容
    }
}
```

### Layer 2 — Kafka 多 Consumer Group 广播

```java
// ============ Publisher ============
@Service
@RequiredArgsConstructor
public class KafkaAnnouncementPublisher {
    private final KafkaTemplate<String, String> kafkaTemplate;
```

```java
    public void pushToOnlineUsers(String announcementContent) {

@RestController
@RequestMapping("/sse")
public class SseNotificationController {

    private final CopyOnWriteArrayList<SseEmitter> emitters = new CopyOnWriteArrayList<>();

    @GetMapping("/subscribe")
    public SseEmitter subscribe() {
        SseEmitter emitter = new SseEmitter(0L);  // 永不过期
        emitters.add(emitter);
        emitter.onCompletion(() -> emitters.remove(emitter));
        emitter.onTimeout(() -> emitters.remove(emitter));
        return emitter;
    }

    // MQ 消费后调用
    public void broadcast(String message) {
        List<SseEmitter> dead = new ArrayList<>();
        emitters.forEach(e -> {
            try {
                e.send(SseEmitter.event().name("announcement").data(message));
            } catch (Exception ex) {
                dead.add(e);
            }
        });
        emitters.removeAll(dead);
    }
}
```

## RabbitMQ Fanout vs Kafka Consumer Group 广播对比

| 维度 | RabbitMQ Fanout | Kafka 多 Consumer Group |
|---|---|---|
| 广播方式 | Exchange 主动复制消息到所有队列 | 每个 Group 独立消费，逻辑广播 |
| 队列管理 | 每个消费者声明临时队列，绑定 Exchange | 无需额外管理，Group 自动分配 partition |
| 新服务接入 | 声明队列+绑定 Exchange，已部署服务无感 | 新增 Consumer Group，Topic 无变化 |
| 消息持久化 | 消费后删除（或设置持久队列） | 天然持久化，支持回溯重放 |
| 消息顺序 | 队列内 FIFO | Partition 内有序，跨 partition 无序 |
| 吞吐量 | 万级/秒，适合中小规模 | 十万级+/秒，适合大规模 |
| 路由灵活性 | 强，支持 Topic/Direct/Headers 模式组合 | 弱，只有 Topic，路由靠业务判断 |
| 适用场景 | 通知推送、配置刷新、缓存失效 | 日志采集、数据同步、追踪链路 |

## 一句话总结

**RabbitMQ Fanout 用 Exchange 复制实现"物理广播"，新服务接入只需声明队列绑定 Exchange 且已部署服务完全无感；Kafka 用独立 Consumer Group 实现"逻辑广播"，天然持久化和高吞吐适合大规模场景——二者结合 WebSocket/SSE 即可完成从服务间分发到终端推送的完整广播链路。**
