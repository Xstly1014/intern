# Q94 秒杀削峰

面对 10 万 QPS 秒杀场景，核心策略是"前端限流 + Kafka 缓冲 + 后端按 DB 承受能力慢消费"三级削峰，将瞬时流量从 10 万平滑到 2000 QPS。消息设 TTL 超时丢弃、扩 Partition + 消费者弹性扩容、令牌桶前置限流共同构成纵深防御体系。

秒杀削峰的核心理念是"用时间换空间"——在入口处用令牌桶挡住绝大多数请求，让剩余流量进入 Kafka 排队缓冲，订单服务只按数据库最大承受能力（2000 QPS）匀速消费。前端通过轮询获取最终结果，超时则返回失败，整个系统宁可少卖、绝不被打垮。

## 端到端代码实现

### Layer 1 — API Gateway 限流（Spring Cloud Gateway + Redis 令牌桶）

```java
@Configuration
public class RateLimitConfig {

    @Bean
    public KeyResolver userKeyResolver() {
        return exchange -> Mono.just(
            exchange.getRequest().getHeaders()
                .getFirst("X-User-Id"));
    }
}

@Component
public class SeckillRateLimiter {

    private final StringRedisTemplate redisTemplate;
    // Lua 脚本：原子性获取令牌
    private static final String LUA_SCRIPT =
        "local key = KEYS[1] " +
        "local limit = tonumber(ARGV[1]) " +
        "local current = tonumber(redis.call('get', key) or '0') " +
        "if current < limit then " +
        "    redis.call('incr', key) " +
        "    redis.call('expire', key, 1) " +
        "    return 1 " +
        "else " +
        "    return 0 " +
        "end";

    public boolean tryAcquire(String userId) {
        Long result = redisTemplate.execute(
            new DefaultRedisScript<>(LUA_SCRIPT, Long.class),
            Collections.singletonList("rate:seckill:" + userId),
            "20000"  // 每秒最多 20000 个令牌
        );
        return result != null && result == 1;
    }
}

// Gateway Filter
@Component
public class SeckillGatewayFilter implements GlobalFilter {

    @Autowired
    private SeckillRateLimiter rateLimiter;

    @Override
    public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
        String userId = exchange.getRequest().getHeaders().getFirst("X-User-Id");
        if (!rateLimiter.tryAcquire(userId)) {
            exchange.getResponse().setStatusCode(HttpStatus.TOO_MANY_REQUESTS);
            // 直接返回"抢购失败"，不进入 Kafka
            return exchange.getResponse().setComplete();
        }
        return chain.filter(exchange);
    }
}
```

### Layer 2 — 秒杀请求入 Kafka（Producer 优先低延迟，linger.ms=0, acks=1）

```java
@Service
public class SeckillProducer {

    @Autowired
    private KafkaTemplate<String, String> kafkaTemplate;

    // application.yml 配置:
    // spring.kafka.producer.acks=1           // 只需 Leader 确认
    // spring.kafka.producer.linger-ms=0      // 不等待批量，立即发送
    // spring.kafka.producer.compression-type=lz4

    public void submitSeckill(Long userId, Long productId, String requestId) {
        SeckillRequest req = new SeckillRequest();
        req.setUserId(userId);
        req.setProductId(productId);
        req.setRequestId(requestId);
        req.setSubmitTime(System.currentTimeMillis());

        // 按 userId 哈希路由到固定 Partition，保证同一用户顺序
        kafkaTemplate.send("seckill", String.valueOf(userId),
            JSON.toJSONString(req));
    }
}
```

### Layer 3 — 订单服务按速率消费（限速 throttle + 控制批量大小）

```java
@Component
public class SeckillOrderConsumer {

    // 配置:
    // spring.kafka.consumer.max-poll-records=50   // 每次拉取不超过 50 条
    // spring.kafka.consumer.enable-auto-commit=false

    private final RateLimiter rateLimiter = RateLimiter.create(2000); // 2000 QPS

    @KafkaListener(topics = "seckill", groupId = "order-group")
    public void onMessage(List<ConsumerRecord<String, String>> records,
                          Acknowledgment ack) {
        for (ConsumerRecord<String, String> record : records) {
            SeckillRequest req = JSON.parseObject(
                record.value(), SeckillRequest.class);

            // 1. 消息 TTL 检查：超过 30 秒的消息丢弃
            long elapsed = System.currentTimeMillis() - req.getSubmitTime();
            if (elapsed > 30_000) {
                log.warn("消息已过期, userId={}, elapsed={}ms",
                    req.getUserId(), elapsed);
                continue;
            }

            // 2. Guava RateLimiter 限速：每秒最多 2000 个
            rateLimiter.acquire();

            try {
                // 3. 扣库存 + 创建订单（同一个事务）
                orderService.createSeckillOrder(req.getUserId(), req.getProductId());
                // 4. 写入订单状态缓存，供前端轮询
                redisTemplate.opsForValue().set(
                    "seckill:result:" + req.getRequestId(),
                    "SUCCESS", Duration.ofMinutes(5));
            } catch (InsufficientStockException e) {
                redisTemplate.opsForValue().set(
                    "seckill:result:" + req.getRequestId(),
                    "SOLD_OUT", Duration.ofMinutes(5));
            }
        }
        ack.acknowledge();
    }
}
```

### Layer 4 — 前端轮询结果 + 超时处理

```java
@RestController
@RequestMapping("/seckill")
public class SeckillController {

    @Autowired
    private SeckillProducer producer;

    // 第一步：提交秒杀请求
    @PostMapping("/submit")
    public Result submit(@RequestBody SeckillSubmitRequest request) {
        String requestId = UUID.randomUUID().toString();
        producer.submitSeckill(request.getUserId(),
            request.getProductId(), requestId);
        // 立即返回排队状态和 requestId
        return Result.ok(new SubmitResponse(requestId, "QUEUING"));
    }

    // 第二步：前端轮询结果
    @GetMapping("/result/{requestId}")
    public Result queryResult(@PathVariable String requestId) {
        String status = redisTemplate.opsForValue()
            .get("seckill:result:" + requestId);
        if (status == null) {
            return Result.ok(new QueryResponse("QUEUING")); // 还在排队
        }
        return Result.ok(new QueryResponse(status)); // SUCCESS / SOLD_OUT
    }
}
```

## 秒杀削峰方案对比

| 维度 | 直接挡流 | Redis 队列 | Kafka 削峰 |
|------|---------|-----------|-----------|
| **实现方式** | Nginx limit_req / Gateway 限流后直接拒绝 | Redis List LPUSH + BRPOP 消费 | Kafka Topic 多 Partition 缓冲 |
| **削峰深度** | 单层，拒绝即丢失 | 内存缓冲，受 Redis 内存限制 | 磁盘持久化，几乎无上限 |
| **可靠性** | 无缓冲，超限请求直接丢失 | Redis 宕机则全部丢失 | 磁盘持久化 + 多副本，可恢复 |
| **消费速率控制** | 无 | 需自行实现 Pull 频率控制 | Consumer 原生支持 max.poll.records + pause/resume |
| **消息 TTL** | 无（已经拒绝） | Redis key 设置 EXPIRE | Kafka 消息级 TTL 或 topic retention |
| **弹性扩容** | 扩容 Gateway 节点 | 扩容消费者需自行分配 | 原生支持 Partition 扩容 + Consumer Rebalance |
| **延迟** | 最低（即时拒绝或放行） | 内存操作，延迟低 | 磁盘 I/O，有 ms 级延迟 |
| **运维成本** | 低 | 中（需监控 Redis 内存） | 高（Kafka 集群运维） |
| **适用场景** | 普通限流、API 保护 | 中小流量、内存充足 | 大流量秒杀、需持久化兜底 |

## 一句话总结

**秒杀削峰的核心是将瞬时 10 万 QPS 通过 API Gateway 令牌桶限流 (挡掉 8 万) + Kafka 队列缓冲 (排队 2 万) + 订单服务限速消费 (2 千/秒出队) 三级漏斗逐层削减，宁可让用户排队等待甚至超时失败，也绝不让系统被流量打垮。**
