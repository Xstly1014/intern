# 生产参考架构与检查清单

本页将前述路由、信任、流控、发布、控制面和观测组合成可落地的部署形态。参考架构是按规模和风险逐步演进，不是要求所有项目一开始就自建网关平台。

## 1. 成长型系统参考拓扑

![生产 API 网关参考架构](/architecture/gateway-reference-topology.svg)

该拓扑使用以下边界：

- 边缘层负责 Anti-DDoS、WAF、TLS 和地域入口。
- 区域 L7 LB 负责将流量送到跨可用区的网关数据面。
- 网关数据面无业务数据库，使用本地快照执行路由和策略。
- 限流/JWKS 等外部依赖都有本地快速路径与有界故障策略。
- 上游 BFF/服务只接受来自网关/受信任内部网络的流量。
- 控制面不处理数据面请求，独立鉴权、审计、备份和扩缩容。
- 发布按可用区/Cell 分批，数据面能使用最后有效快照独立运行。

## 2. 小型系统

### 适用

单地域、少量服务、无复杂开放平台，团队尚无独立平台人员。

### 建议形态

![小型系统 API 网关部署拓扑](/architecture/gateway-small-topology.svg)

即使简化，也要具备：

- 至少两个网关实例，跨不同故障域。
- 路由配置进 Git，通过 CI 验证，不直接登录机器改文件。
- JWT 本地验签、Header 清洗、路由级 Body/超时/限流。
- 结构化访问日志、路由 RED 指标和 Trace 传播。
- readiness、优雅摘流、滚动发布和可快速回退制品。

不需要一开始自建 API 商店、复杂控制面、全局配额平台和多供应商网关。优先使用云托管能力或一个团队能完整驾驭的网关产品。

## 3. 成长型系统

当出现多团队、多终端、多租户、Open API、频繁灰度和明确 SLO 后，新增：

- 结构化 API/Route/Upstream/Consumer/Policy 对象模型。
- 带 Schema、冲突检测、影响分析和审批的配置发布管道。
- 按租户/应用的分层配额，本地过载保护与集中长期配额结合。
- 稳定哈希灰度、镜像、分阶段指标门禁和自动回退。
- 公网 API、管理 API、合作方 API 至少按信任域隔离策略和容量。
- 路由所有者、开发者应用、凭证轮换、调用统计与 API 淘汰流程。

## 4. 多地域/大型平台

### 每地域数据面

请求应在用户所在地域的网关处理，再调用本地 BFF/服务，避免每次请求跨洋。每地域有独立容量、连接池、熔断和本地依赖。

### 控制面层次

可使用全局管理面维护 API 产品与标准，地域控制面生成合并了合规、地域上游和容量的快照。全局控制面故障不影响地域数据面，也不应阻断地域紧急操作。

### Cell 隔离

一个地域可进一步分为多个 Cell，用户/租户稳定映射到 Cell。每个 Cell 有独立网关数据面、上游容量和故障边界，某 Cell 过载不应抢占其他 Cell 资源。

### 多供应商/多网关技术

只有在供应商故障、合规或并购技术异构确实需要时引入。需要先统一 API 契约、身份声明、配额语义、错误模型、Trace 和路由 ID，否则多网关只是两套不一致的故障面。

## 5. Spring Cloud Gateway 落地要点

### 线程模型

Spring Cloud Gateway 基于 Reactor Netty 事件循环。禁止在 GlobalFilter/GatewayFilter 的热路径直接：

- JDBC/JPA 查询。
- 使用阻塞客户端调用远程鉴权或配置服务。
- 读写文件、调用外部进程。
- 对大 Body 执行无界聚合与 JSON 转换。
- 高 CPU 密码学/脚本计算且无并发上限。

应优先使用本地缓存和非阻塞 API。无法避免的阻塞操作移入专用有界线程池，对队列、并发、超时和拒绝量建指标，并评估它是否本来就不应放在网关。

### Body 处理

请求 Body 通常是一次性数据流。需要验签、日志或修改 Body 时，会引入缓冲和重放问题。必须先限制 Body 大小，避免用 `DataBuffer` 时内存泄漏，对上传/流式 API 禁用需整体缓冲的 Filter。访问日志不应默认打印 Body。

### 路由和配置

动态路由更新要生成不可变快照并原子切换。不建议让每个网关实例轮询业务数据库拼装 RouteDefinition；应由受控控制面统一验证、发布和审计。

### JVM 与容器

- 设置明确容器 CPU/内存请求与限制，观察 CPU throttling。
- 根据堆外 Direct Memory、连接和 Netty buffer 保留非堆空间，不将容器内存全给 Java Heap。
- 监控 GC 暂停、堆/直接内存、事件循环 pending tasks 与连接池。
- readiness 不依赖所有上游，避免上游故障将全部网关摘掉。
- 使用 `preStop`/优雅停机协调 LB 摘流、在途请求与容器终止宽限。

## 6. 一条“创建订单”路由的完整设计

| 维度 | 参考决策 |
|---|---|
| 匹配 | `POST /api/v1/orders`，只允许 JSON，Body 上限 256 KiB |
| 身份 | JWT 本地验签，`aud=order-api`，scope 包含 `order:create` |
| 信任 | 删除外部身份 Header，传递受信任 subject/tenant/client，内部 mTLS |
| 幂等 | 强制非空、长度有界 `Idempotency-Key`，真正去重由订单服务完成 |
| 流控 | 全局 + tenant + user 令牌桶，为高价值租户保留容量，小并发上限 |
| 超时 | 总预算 800 ms，排队 30 ms，Connect 80 ms，单尝试受剩余 deadline 约束 |
| 重试 | 默认不重试；只在 Body 尚未发送的连接失败且剩余预算充足时一次 |
| 灰度 | tenant/user 稳定哈希，候选与基线对比下单成功率与重复冲突 |
| 错误 | 401/403/409/429/503/504 保持真实语义，返回稳定错误码与 request ID |
| 观测 | route ID、tenant 套餐、灰度桶、上游尝试、各阶段耗时，不记 Token/Body |

用户看到 504 后不能盲目换 Key 重新创建。客户端应使用同一幂等键重试或查询结果，订单服务使用持久化唯一约束返回原结果。网关只负责检查键契约和传递，不把内存缓存当业务幂等事实。

## 7. 故障演练矩阵

| 注入故障 | 预期行为 | 验证指标 |
|---|---|---|
| 上游延迟增加 | 并发/队列有界，超时和熔断，其他路由不受影响 | pending、timeout、circuit、其他 route P99 |
| 上游实例部分失败 | 被动摘除，健康实例接流但不过载 | 实例错误、负载分布、恢复探测 |
| 无健康上游 | 快速 503，无长排队和重试风暴 | no_healthy_upstream、attempt ratio |
| Redis/配额存储不可用 | 按 API 风险进入本地严格限制或 fail-closed | 降级模式、延迟、放行/拒绝量 |
| JWKS/introspection 不可用 | 已缓存凭证按策略运行，未知凭证不放行 | cache age、unknown kid、auth dependency |
| 控制面断开 | 继续使用最后有效快照 | config age、version divergence |
| 发布错误路由 | 预检阻断或波次检测后自动回滚 | NACK、404/5xx、rollback time |
| 日志管道阻塞 | 有界缓冲与采样，数据面不被拖垮 | dropped logs、event loop lag |
| 单实例/可用区丢失 | 剩余容量承接，无连接风暴 | 容量余量、new connections/s、SLO |

## 8. 评审清单

### 边界与所有权

- 每条路由是否有稳定 ID、所有团队、上游和值班联系？
- 网关是否只执行跨业务通用策略，没有业务数据库与长流程编排？
- Ingress、网关、BFF 和 Mesh 中的路由、鉴权、重试责任是否唯一？

### 安全

- 外部身份/Forwarded Header 是否清洗，上游能否被绕过直连？
- JWT、API Key、mTLS 的发行、缓存、轮换、撤销和故障行为是否明确？
- 管理面是否网络隔离、MFA、最小权限、审批与不可篡改审计？
- 日志、Trace、指标和错误响应是否已脱敏？

### 韧性

- 限流是否同时保护公平性、上游容量和网关自身？
- 超时是否分阶段且受总 deadline 限制，写请求是否幂等？
- 重试是否有唯一主要层、尝试上限、总预算和全局重试预算？
- 慢路由、长连接和大 Body 是否有独立并发、连接池和内存边界？

### 变更

- 配置是否经过 Schema、引用、路由冲突、安全与影响分析？
- 是否分波次发布、跟踪 ACK/NACK 并能原子回到上一快照？
- 灰度是否稳定命中，同时使用技术与业务不变量作门禁？
- API 版本是否有消费者清单、兼容契约、弃用日期和淘汰证据？

### 运维

- 是否可区分网关本地错误、上游错误、每次尝试与最终响应？
- 容量测试是否覆盖真实 TLS、协议、Body、连接、鉴权和日志特征？
- 是否已演练上游慢/断开、限流依赖故障、控制面断开和错误配置？
- 单实例、可用区或 Cell 失败后是否仍有足够安全容量？
