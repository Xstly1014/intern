# 生产就绪、上线编排与验收

Production Readiness Review（PRR）不是上线前补文档，而是确认系统在正常、过载、依赖故障、发布失败和人员操作下都具备明确行为。证据应来自自动化测试、压测、演练和真实监控。

## 1. 生产就绪门禁

![从设计冻结到稳定观察的上线门禁](/architecture/practice-production-gates.svg)

门禁依次确认契约与数据、功能与安全、容量与过载、运行与观测、迁移与恢复、灰度与稳定观察。高风险项未完成时要缩小范围、降级能力或延后，不用口头承诺替代证据。

## 2. 发布前基线

- 服务目录、owner、on-call、SLO、依赖和数据分级登记完整。
- 配置、Secret、证书、DNS、配额、Topic、表和索引在目标环境验证。
- Dashboard、告警、日志查询、Trace、业务核对和变更事件可用。
- requests/limits、连接池、超时、重试、限流、HPA 和容量余量经压测校准。
- 数据迁移可重入、有 checkpoint、限速、估时、暂停和校验。
- 回滚/forward fix、Feature kill switch、备份恢复和依赖降级已演练。

## 3. 上线指挥

![上线期间角色、信号与决策回路](/architecture/practice-launch-command.svg)

指定发布负责人、业务确认人、应用/数据/平台/安全值守和最终 go/no-go 决策人。使用统一时间线记录 digest、配置、Schema、流量权重、Flag、指标和动作。变更冻结窗口防止无关发布污染判断。

## 4. 渐进放量

先内部/测试租户，再 1%、5%、25%、50%、100%，阶段窗口覆盖慢查询、异步积压和业务周期。每步比较稳定组与候选组的错误、尾延迟、饱和度、下游失败及业务成功率。遥测缺失默认暂停；不要在指标异常时继续放量“收集更多样本”。

## 5. 回滚与停止条件

预先量化错误率、延迟、数据差异、积压、业务失败和人工工单阈值。触发后先停止放量和副作用，再决定回滚流量、关闭 Flag、恢复配置或 forward fix。数据库 contract、外部支付和已发布事件通常不可自动撤销。

## 6. 上线后验收

稳定观察覆盖完整流量周期，核对账务、订单状态、消息积压、数据差异、成本与容量。清理临时权限、旁路开关和调试日志；完成 Runbook、值班交接和用户支持材料。发布结束标准是风险回到可接受水平，而非流量达到 100%。

## 7. 必做演练

至少验证实例/节点/AZ 故障、下游慢与不可用、DB 主备切换、MQ 积压与重放、证书/Secret 轮换、发布门禁失败、备份恢复和人工误操作。记录实际恢复时间、数据影响、人工步骤和下一项改进。
