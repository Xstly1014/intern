# 架构评审、ADR、风险台账与轻量治理

架构治理的目标是让重要决策可解释、风险可见、标准可复用，而不是制造中央审批。评审关注约束、失败和证据，ADR 保存当时为什么这样选择。

## 1. 评审输入与输出

![架构评审从问题到决策和行动的流程](/architecture/practice-review-flow.svg)

输入至少包括业务旅程、上下文与数据流、质量目标、容量模型、威胁模型、依赖清单、部署恢复方案、成本和替代方案。输出不是“通过/不通过”一句话，而是已接受决策、风险、缓解动作、owner、期限、验证证据和需要升级的争议。

## 2. 六个评审视角

1. **边界与数据**：谁拥有数据和不变量，事务、缓存、搜索、事件怎样派生。
2. **失败语义**：超时、重试、重复、乱序、部分成功、未知结果和修复路径。
3. **安全隐私**：身份、对象授权、租户隔离、Secret、数据分级、审计与供应链。
4. **性能容量**：峰值、扇出、连接、队列、热点、扩容延迟和单故障域余量。
5. **交付运维**：兼容迁移、Canary、回滚边界、SLI/SLO、告警、Runbook 和 DR。
6. **组织成本**：团队 ownership、认知负担、供应商锁定、单位成本和退场路径。

## 3. ADR 的写法

![ADR 生命周期与复审触发器](/architecture/practice-adr-lifecycle.svg)

每份 ADR 记录背景和约束、决策、候选方案、选择理由、后果、风险、状态和复审触发器。状态使用 proposed、accepted、superseded、deprecated；新决策用链接取代旧决策，避免篡改历史。触发器可以是流量阈值、SLO 失败、团队变化、供应商价格或监管要求。

## 4. 风险台账与例外

风险按可能性、影响、可探测性和暴露时间排序。每项必须有缓解/接受理由、owner、截止日期和验证方式。标准例外需要最小范围、补偿控制、审批和自动到期；永久例外会把基线掏空。

## 5. 评审节奏

小变更在 PR 模板和自动策略中完成；跨边界、数据权威、安全、高成本或不可逆变更做同步评审；重大事故、SLO 超支和阶段升级触发复审。预读材料提前异步评论，会议只解决分歧和风险。

## 6. 治理效果

跟踪决策前置时间、重复问题、例外数量与过期率、事故中已知风险命中率、模板采用率和整改完成率。评审文档数量不是成功指标；决策更快、生产风险下降、团队更能自助才是。
