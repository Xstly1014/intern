# API 网关层：统一流量治理入口

API 网关是内部服务之前的统一代理和策略执行点。它负责与业务领域无关、适合全局一致执行的能力：路由、限流、基础认证、灰度、协议治理与访问日志。网关不是“超级业务服务”。

## 1. 控制面与数据面

![API 网关控制面与数据面](/architecture/gateway-control-data-plane.svg)

控制面短暂故障时，数据面应继续使用最后一份有效配置。配置发布要支持校验、版本、灰度和秒级回滚，不能让一个错误路由同时击穿所有入口。

## 2. 请求经过网关的顺序

1. 接受 TLS 请求，限制连接、Header 和 Body 大小。
2. 匹配域名、方法、Path 和 API 版本，拒绝未知路由。
3. 建立或校验 `traceparent`、request ID，清洗不可信转发头。
4. 校验 Token 的签名、签发方、受众和有效期，提取最小身份声明。
5. 按 IP、用户、租户、应用或接口执行配额与限流。
6. 选择版本和实例，设置连接/响应超时，转发请求。
7. 记录状态码、延迟、上下游地址、流量标签和策略命中。
8. 返回统一的技术错误；业务错误保持由业务服务定义。

## 3. 应该做与不应该做

| 适合放网关 | 不适合放网关 |
|---|---|
| Host/Path 路由、重写、版本映射 | 订单价格和库存规则 |
| TLS、CORS、安全 Header、请求大小 | 多服务长流程编排 |
| Token 基础合法性验证 | 资源所有权的最终授权 |
| 全局/接口/主体限流和配额 | 写业务数据库 |
| 金丝雀、蓝绿、A/B 流量分配 | 用脚本承载频繁变化的核心业务 |
| 协议转换、访问日志、Trace 传播 | 无限重试非幂等请求 |

边界判断很简单：规则是否跨业务通用，是否只依赖请求元数据，是否能在不访问业务数据库的情况下决策。否则应由接入层或业务服务负责。

## 4. 限流、熔断、重试与超时

### 限流

令牌桶允许一定突发，漏桶强调平滑输出，滑动窗口适合精确配额。限流维度通常组合为 `route + tenant + user/app`，并为高价值请求保留容量。网关集群使用集中计数时要考虑 Redis 故障；应明确计数失败时放行还是拒绝。

### 超时

网关超时必须小于客户端超时并大于下游整体预算。连接超时和响应超时分开设置，流式下载与普通 API 使用不同策略。超时只停止等待，不一定取消下游工作，因此写操作仍需幂等。

### 重试

只对连接失败、部分 502/503 等短暂错误重试，优先限于 GET/HEAD 或携带幂等键的操作。每次请求限制重试次数和总预算，采用抖动退避，并防止网关、SDK、服务三层叠加重试形成放大风暴。

### 熔断与降级

按路由和下游隔离统计，避免一个服务拖慢网关线程与连接池。熔断后返回明确的可重试语义或静态降级结果；不要把所有异常统一改写成 200。

## 5. 路由、发现与灰度

路由目标可以来自静态地址、Kubernetes Service、注册中心或服务网格。灰度标签可来自 Cookie、用户 ID 哈希、租户、Header 或地域；同一用户应稳定命中同一版本。数据库 Schema、消息格式和缓存 Key 必须先做到前后兼容，流量灰度才有意义。

## 6. 安全设计

- 外部 Header 白名单化，身份 Header 由网关覆盖而非透传。
- 管理 API 与业务数据面隔离，配置变更最小权限并完整审计。
- JWT 验签密钥本地缓存并轮换；不要每个请求同步调用认证中心。
- 对登录、短信、导出、上传等高风险接口使用更严格策略。
- 日志不记录 Token、密码、完整银行卡号或未脱敏请求体。

## 7. Java 技术选型

| 场景 | 选择 | 注意点 |
|---|---|---|
| Java 体系动态路由 | Spring Cloud Gateway | 基于 Reactor，过滤器不能阻塞；控制插件数量 |
| 高性能通用网关 | Apache APISIX、Kong、Envoy | 团队需掌握其配置、插件与控制面 |
| Kubernetes Ingress/Gateway | Envoy Gateway、NGINX、云网关 | 区分集群入口与业务 API 网关职责 |

Spring Cloud Gateway 使用 Netty 事件循环。过滤器中执行 JDBC、阻塞 HTTP 或大对象序列化会阻塞整个事件线程；业务查询必须移出网关。

## 8. 关键指标与故障模式

监控每个 route 的请求率、状态码、上下游耗时、限流/熔断数、连接池等待、活跃连接、事件循环延迟、配置版本和实例负载。网关是高爆炸半径组件，至少多实例跨故障域部署，发布小步灰度，配置有自动回滚，并通过压测验证单实例容量和过载行为。
