# 客户端工程：连接、超时、重试、缓存与弱网

后端架构常把客户端画成一个方框，但请求是否会重复、连接是否复用、Token 是否泄露、弱网下是否形成重试风暴，往往由客户端决定。边缘层的可靠性从用户设备开始。

本篇覆盖浏览器、原生 App、小程序和第三方 SDK 的共同原则。具体平台 API 不同，但失败语义相同。

## 1. 客户端承担什么职责

- 正确构造请求：方法、URL、Header、Body、编码和版本。
- 安全保存与发送凭证，不把 Secret 嵌入可反编译客户端。
- 管理 DNS、连接池、TLS 会话、Cookie 和本地缓存。
- 设置总超时、取消请求、有限重试和退避。
- 在弱网、离线、切网、进后台和进程重启时保持正确性。
- 展示明确状态，避免用户因无反馈反复点击。
- 采集不含敏感数据的端到端性能与错误信息。

客户端不应自行决定商品真实价格、最终权限或订单状态。客户端校验用于体验，服务端校验用于正确性和安全。

## 2. 请求生命周期

![客户端一次网络请求的完整生命周期](/architecture/client-request-lifecycle.svg)

必须区分“没有收到响应”和“服务端没有执行”。写请求在客户端超时前可能已成功提交，重新发送会产生重复副作用。因此订单、支付、创建任务等接口需要客户端生成稳定的幂等键。

## 3. 超时不是一个数字

| 超时 | 含义 | 常见问题 |
|---|---|---|
| DNS 超时 | 域名解析等待上限 | 系统解析器通常不暴露独立控制 |
| Connect Timeout | TCP/QUIC 建连上限 | 过长会卡在不可达地址 |
| TLS Handshake Timeout | 安全握手上限 | 证书链、网络丢包会影响 |
| Write Timeout | 上传请求体上限 | 大上传与普通 JSON 不应相同 |
| Read/Response Timeout | 等待响应数据上限 | 流式接口不能用普通读超时 |
| Call/Total Timeout | 整次调用总预算 | 必须包含重试、排队和所有阶段 |

客户端应优先设置**总预算**，再设置各阶段子预算。三次每次 5 秒的重试不是“5 秒超时”，最坏接近 15 秒加退避。UI 层还要定义多久显示 loading、多久允许取消、何时转为后台任务。

### 示例策略

| 请求类型 | 建议思路 |
|---|---|
| 自动补全 | 数百毫秒预算，新请求取消旧请求，不重试陈旧查询 |
| 普通查询 | 1～5 秒量级，可有限重试网络瞬时失败 |
| 创建订单 | 明确总预算，携带幂等键；超时后查询结果而非盲目创建 |
| 文件上传 | 分片、断点续传、校验摘要，超时按分片处理 |
| 流式聊天/SSE | 建连超时短，读取允许长时间，配置心跳与重连游标 |

具体数字必须来自用户网络分布和 SLO，不应复制表格值直接上线。

## 4. 重试的完整规则

一次可靠重试必须同时回答：

1. 哪些错误可重试？例如连接重置、部分 502/503/504、明确的 429。
2. 哪些方法可重试？GET 通常可重试，POST 只有服务端支持幂等才可以。
3. 最多几次？同时限制次数和总时间预算。
4. 等多久？指数退避加随机抖动，尊重 `Retry-After`。
5. 谁负责重试？客户端、CDN、网关、SDK 不能每层都重试。
6. 原请求是否仍在执行？超时不等于远端取消。

指数退避示意：

```text
delay = random(0, min(cap, base × 2^attempt))
```

抖动避免大量客户端在服务恢复瞬间同时重试。后台同步还应在设备离线时等待网络恢复，而不是高频轮询。

### 绝不应自动重试的情况

- 400、401、403、404 等确定性客户端或权限错误。
- 服务端返回明确业务拒绝，如余额不足、状态不允许。
- 没有幂等保障的支付、转账、发券等写操作。
- 已经超过业务截止时间的请求。

## 5. 幂等键如何生成与保存

幂等键代表一次业务意图，不是每次 HTTP 尝试都生成新值。

```text
用户第一次点击“提交订单”
  → 生成 idempotencyKey = UUID
  → 本地保存 pending(intent, key, payloadHash)
  → 第一次发送失败/超时
  → 使用同一个 key 重试或查询
  → 收到最终结果后标记完成
```

如果用户修改了商品或地址，应创建新的业务意图和新键。服务端应将用户/租户、操作类型、幂等键和请求摘要关联；同一键但载荷不同返回冲突，而不是复用错误结果。

## 6. 连接复用与连接池

每次请求都重新 DNS、TCP 和 TLS 会显著增加延迟、电量与边缘新建连接压力。客户端应复用 HTTP Keep-Alive、HTTP/2 多路复用或 HTTP/3 连接。

连接池关注：

- 每主机最大连接数和空闲连接数。
- 空闲连接存活时间应小于中间 NAT/LB 的空闲回收时间，或具备失效重连。
- 连接建立失败在多个 IP 间怎样回退。
- App 从 Wi-Fi 切到蜂窝网络后旧连接如何失效。
- HTTP/2 单连接故障是否影响全部并发流，是否需要少量多连接。
- 客户端退出后台时是否暂停非关键网络工作。

连接池无限大不会提高吞吐，只会把压力和排队转移到服务端。

## 7. DNS 与 Happy Eyeballs

客户端和操作系统会缓存 DNS，缓存时间未必严格等于权威 TTL。IPv6/IPv4 双栈环境下，客户端可使用 Happy Eyeballs 并行或短间隔尝试地址族，避免某一地址族路由损坏导致长等待。

不要在 App 中长期硬编码源站 IP：它绕过 DNS 故障切换、CDN/WAF，并会因证书、扩容和迁移失效。如果使用 HTTPDNS，应评估 SNI、证书域名、调度、隐私、系统代理和合规问题，而不是只为“防 DNS 劫持”。

## 8. 本地缓存

| 缓存 | 适合内容 | 关键风险 |
|---|---|---|
| HTTP Cache | 静态资源、可验证 GET 响应 | Header 配置错误导致陈旧或泄露 |
| 内存缓存 | 当前会话热点对象 | 进程终止即丢失、内存压力 |
| 磁盘缓存 | 图片、离线资源、较大响应 | 加密、淘汰、版本迁移 |
| 业务数据库 | 草稿、离线队列、同步状态 | 冲突合并和 Schema 升级 |

客户端必须区分“最后一次已知值”和“服务器当前事实”。离线展示应标出数据时间，敏感数据按平台安全能力加密，并在退出登录、租户切换和账号切换时彻底隔离。

## 9. 弱网与离线策略

弱网不是只有“慢”，还包括高抖动、高丢包、短暂断连、网络切换、代理异常和只可访问部分互联网。

- 关键页面优先加载骨架和本地数据，再渐进更新。
- 小请求合并、压缩响应，图片使用合适尺寸和格式。
- 可取消过期请求，例如用户快速切换搜索词。
- 写操作显示“提交中/已受理/结果未知/失败”，不把未知状态展示为失败。
- 离线队列只用于可安全延迟且可幂等的操作。
- 恢复网络后分批、带抖动同步，避免瞬时洪峰。
- 上传采用分片、摘要、断点续传和并发上限。

## 10. Web、App 与第三方 SDK 的差异

### 浏览器

受同源策略、CORS、Cookie、Service Worker 和浏览器缓存约束。不要把长期 Token 放在可被任意脚本读取的位置；防范 XSS 与 CSRF。Service Worker 更新需要版本和回退策略，否则会长期运行旧缓存逻辑。

### 原生 App

可控制更细的连接池、本地数据库和证书校验，但版本升级不可强制瞬时完成。服务端必须维护最低支持版本和兼容窗口。Certificate Pinning 能降低特定中间人风险，也可能在证书轮换时让全量旧版本断网，必须预埋备用公钥并演练。

### 第三方 SDK/Open API 客户端

需要稳定版本、明确超时和重试默认值、幂等支持、错误分类、限流 Header、代理配置和可观测 Hook。SDK 不应隐藏无限重试，也不应打印 Token 和完整响应。

## 11. 凭证和敏感信息

- 客户端包中的任何固定 Secret 都可被提取，不能作为真正机密。
- Access Token 短期有效，Refresh Token 使用平台安全存储并支持旋转。
- 日志、崩溃报告、剪贴板、URL 查询参数和分析埋点不得泄露 Token。
- 退出登录时清理身份、缓存、Cookie、离线任务和推送标识关联。
- WebView 与原生桥接限制可调用方法和来源，防止任意网页获取本地权限。

## 12. 客户端可观测性

Real User Monitoring 至少记录匿名化的：

- DNS、连接、TLS、TTFB、下载和总耗时。
- 网络类型、地域、运营商、App/浏览器版本、操作系统。
- HTTP 状态、稳定错误码、重试次数、请求取消和离线状态。
- 页面首屏、交互延迟、崩溃和关键业务成功率。

采样和字段必须遵守隐私政策。端到端 request ID 可让客服反馈与边缘/服务端日志关联，但不能把用户敏感标识直接作为 Trace ID。

## 13. 上线检查清单

- [ ] 每类 API 有总超时、取消和重试策略。
- [ ] 关键写操作携带稳定幂等键，超时后有状态查询。
- [ ] 重试有指数退避、抖动、次数和总预算。
- [ ] 连接池和并发有上限，支持网络切换和失效重连。
- [ ] 离线/弱网/进后台/杀进程场景经过测试。
- [ ] 本地缓存按账号和租户隔离，可安全清理与升级。
- [ ] Token 不进入 URL、普通日志、埋点和崩溃报告。
- [ ] 旧客户端版本有兼容期、最低版本和升级策略。
- [ ] RUM 能按地域、运营商和版本定位问题。
