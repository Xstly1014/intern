# 可观测性与故障排查：用户为什么访问不了

边缘问题往往具有地域性、运营商相关、协议相关和间歇性。服务端监控全绿，只能说明请求到达服务后表现正常；无法证明 DNS、TLS、CDN、WAF 和公共网络正常。

本篇建立从用户体验到源站的观测模型，并给出一套可复用的排障顺序。

## 1. 三种观察视角

### RUM：真实用户监控

在浏览器/App 采集真实网络和页面体验，能发现特定运营商、版本、设备和网络类型问题。优点是真实，缺点是采样、隐私和用户完全无法连接时可能上报不出来。

### Synthetic：合成探测

从固定地域/运营商持续执行 DNS、TLS、HTTP 和关键交易。适合告警和对比，但探测点不能代表所有用户。

### Server/Edge Telemetry

DNS、CDN、WAF、LB 和 Java 服务产生指标、日志和 Trace。适合定位组件内部，但完全没到达入口的请求没有服务端 Trace。

三者结合：RUM 发现真实影响，Synthetic 主动检测，服务端遥测定位原因。

## 2. 端到端延迟分解

浏览器 Navigation Timing 或 App 网络栈应区分：

| 阶段 | 指标 | 异常可能原因 |
|---|---|---|
| DNS | domainLookupEnd - Start | 递归 DNS、缓存 miss、权威故障 |
| Connect | connectEnd - Start | 路由、丢包、端口不可达 |
| TLS | connectEnd - secureStart | 证书链、握手 CPU、协议兼容 |
| Request Send | requestStart 到发送完成 | 弱网、大 Body、慢速上传 |
| TTFB | responseStart - requestStart | 边缘排队、回源、应用处理 |
| Download | responseEnd - responseStart | 带宽、丢包、响应过大 |
| Total/User | 动作到可交互 | 客户端渲染、重试、业务流程 |

机房内 APM 只覆盖 TTFB 中的一部分。

## 3. 统一关联标识

入口接受合法 W3C `traceparent` 或生成新 Trace，同时生成稳定 request ID。边缘、LB、网关和服务日志记录：

- request_id / trace_id。
- 时间、Host、Path 模板、Method、状态码。
- 客户端匿名网络维度：区域、ASN/运营商、协议。
- edge PoP、cache status、WAF/Bot action。
- upstream、target、连接/响应时间和重试次数。
- 配置/规则/部署版本。

原始 Path 的 ID 和 Query 可能含隐私或高基数，指标使用路由模板，详细值只在受控日志按需保存。不要记录 Token、Cookie、签名 URL 和完整敏感 Body。

## 4. 分层黄金指标

### DNS

查询成功率、解析时延、SERVFAIL/NXDOMAIN、答案与 TTL、权威可用性、DNSSEC、GSLB 地域选择和切换事件。

### CDN

请求/字节命中率、MISS/STALE/BYPASS、回源请求和带宽、PoP TTFB、Purge 延迟、边缘/源站错误区分。

### 安全

清洗 bps/pps、WAF 规则命中/阻断、Challenge、Bot 分类、限流、误报、源站绕过和安全配置变更。

### LB/代理

活跃/新建连接、TLS 握手、请求率、排队、健康目标、前后端 reset/timeout、目标响应时间、跨区流量。

### 用户体验

成功率、DNS/TLS/TTFB/总耗时、页面性能、网络类型、地域、运营商、客户端版本和重试次数。

## 5. 状态码要知道由谁生成

同一个 502 可能来自 CDN、LB、网关或应用。日志和响应诊断 Header 应能识别生成层，但对外不泄露内部拓扑。

| 状态 | 常见边缘含义 |
|---|---|
| 400 | 协议、Host、Header、Body 或 WAF 正向校验失败 |
| 403 | WAF/Bot/访问控制阻断，或应用授权拒绝 |
| 408 | 读取客户端请求超时 |
| 413 | 某一层请求体过大 |
| 421 | 请求被送到不适合的连接/主机 |
| 429 | CDN/WAF/网关/业务配额限流 |
| 499（部分代理） | 客户端在响应前断开 |
| 502 | 后端连接/协议错误或无效响应 |
| 503 | 无健康后端、过载、维护或熔断 |
| 504 | 代理等待上游超时 |

错误响应可携带对用户无敏感信息的 request ID 和稳定错误码。安全阻断携带事件 ID，便于客服和安全团队查询。

## 7. 现场信息收集

在不收集敏感数据的前提下，获取：

- 发生时间和时区、目标域名/路径模板。
- 用户大致地域、运营商、网络类型。
- App/浏览器/OS 版本。
- HTTP 状态、稳定错误码、request/event ID。
- 是否所有用户、某地域、某账号或某版本。
- 首次发生时间、持续或间歇、重试是否恢复。
- 最近发布、配置、证书、DNS、WAF 和供应商事件。

不要让用户发送密码、Token、Cookie、银行卡或完整个人数据。HAR/抓包可能含敏感 Header，必须脱敏并受控传输。

## 8. DNS 排障

1. 查询用户所用递归 DNS 的答案和 TTL。
2. 比较不同公共解析器与权威 DNS 直接答案。
3. 检查 A/AAAA/CNAME 链、循环、过长链和负缓存。
4. 检查 DNSSEC、NS 委派、域名到期和权威状态。
5. 按地域/运营商看 RUM 与合成探测。
6. 若刚切流，确认旧 TTL 缓存用户和旧地址仍如何响应。

## 9. TLS 排障

1. 用正确 SNI 获取线上实际证书链。
2. 检查 SAN、有效期、完整中间链和客户端时间。
3. 对比失败客户端支持的 TLS/密码套件/ALPN。
4. 判断是某 PoP、某证书绑定还是全局。
5. 检查证书部署/续期变更和 OCSP/CT 情况。
6. 如果只有旧 App 失败，检查 Pinning 和备用公钥。

## 10. CDN 排障

1. 查看 Age、Cache-Status、PoP 和 request ID。
2. 判断 HIT/MISS/STALE/BYPASS/ERROR。
3. 对比不同 PoP，识别单节点问题。
4. 检查缓存键、Query、Cookie、Vary 和响应缓存头。
5. 检查 Shield/源站连接、回源 Host/SNI 和源站健康。
6. 检查刚执行的 Purge、规则和发布。
7. 修复用版本化 URL 或精确失效，不直接全站 purge。

## 11. WAF/Bot 排障

1. 用事件 ID 查命中的规则、动作和规则版本。
2. 确认阻断来自边缘安全还是业务 403。
3. 比较正常与异常请求的 Path、Method、Content-Type、字段结构。
4. 查看影响比例、客户端版本、地域和业务转化。
5. 紧急止损优先把具体规则切 Count 或缩小范围。
6. 不建立无到期的全站白名单；保留原规则命中观测。

## 12. 502/503/504 排障

### 502

查看后端连接拒绝/reset、TLS/协议不匹配、无效 Header、后端提前关闭和失效连接复用。如果 Java 无请求日志，问题多在到达应用之前。

### 503

查看健康目标是否为零、容量/并发限制、维护模式、熔断和服务发现。确认健康检查误摘还是实例真的不可用。

### 504

分解代理等待时间和 Java Trace。若后端最终成功但代理超时，检查超时层级和写请求幂等；若后端连接池排队，扩应用未必解决数据库瓶颈。

## 13. 网络抓包和工具边界

常用工具：`dig/nslookup`、`curl -v`、`openssl s_client`、`mtr/traceroute`、浏览器 DevTools、云厂商流日志和受控 `tcpdump`。抓包涉及生产数据时需审批、最短采集、过滤和安全存储。

`ping` 失败不能证明 HTTPS 失败，很多入口禁 ICMP；traceroute 中间跳不响应也不代表链路断。使用端到端 TCP/TLS/HTTP 探测验证真实协议。

## 14. 告警设计

- 以用户成功率和多窗口 SLO Burn Rate 作为分页告警。
- DNS/TLS/边缘 5xx 按地域和运营商告警。
- 缓存命中下降结合回源/源站容量告警。
- WAF 阻断激增结合正常转化下降判断误杀。
- 健康目标减少结合剩余容量，避免每次滚动发布报警。
- 证书、域名、容量和配额用提前量告警。

每条告警包含仪表盘、影响判断、负责人、Runbook、最近变更和安全的回滚操作。

## 15. 复盘需要回答

1. 用户从何时开始受影响，哪些地域/版本受影响？
2. 首个可用信号是什么，为什么告警早/晚？
3. 故障在哪个边界产生，为什么传播到更多层？
4. 缓存、限流、冗余、回滚等防线为何没有阻止？
5. 处置中哪些步骤有效，哪些增加风险？
6. 如何减少再次发生概率、缩小爆炸半径和缩短恢复？
