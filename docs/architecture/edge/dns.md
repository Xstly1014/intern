# DNS 与 GSLB：域名如何找到正确的入口

DNS 是多数请求的第一跳控制面。它把稳定域名映射到不断变化的边缘节点、负载均衡器或源站地址，并可依据地域、运营商、健康状态和权重进行全局调度。

DNS 故障的典型表现是“服务和网关都健康，但用户根本到不了入口”。

## 1. 一次解析的完整过程

```text
应用
 ↓ 查询 api.example.com
操作系统 Stub Resolver / 本机缓存
 ↓
递归 DNS（运营商 / 公共 DNS / 企业 DNS）
 ↓ 先问根域
Root → .com TLD → example.com 权威 DNS
                        ↓
               返回 A / AAAA / CNAME
                        ↓
递归 DNS 缓存结果 → 客户端缓存 → 连接目标 IP
```

客户端通常不直接查询权威 DNS，而是向递归解析器询问。递归解析器代表大量用户缓存答案，因此权威记录改了，不代表所有用户立刻看到新结果。

## 2. 常见记录类型

| 记录 | 用途 | 注意点 |
|---|---|---|
| A | 域名映射 IPv4 | 可返回多个地址，不代表客户端均匀使用 |
| AAAA | 域名映射 IPv6 | 必须验证真实 IPv6 端到端质量 |
| CNAME | 一个域名别名指向另一个域名 | 根域通常受限制；增加解析链与依赖 |
| ALIAS/ANAME | DNS 厂商在根域模拟 CNAME | 非标准通用记录，行为看供应商 |
| TXT | 域名验证、SPF 等文本声明 | 不用于业务流量地址 |
| CAA | 限制可为域名签发证书的 CA | 降低错误签发风险 |
| NS | 指定权威 DNS 服务器 | 多供应商时要管理一致性 |
| SOA | 区域序列号、主服务器和负缓存参数 | 影响同步和 NXDOMAIN 缓存 |

API 常通过 CNAME 指向 CDN/GSLB 提供的域名，由供应商动态返回边缘地址。不要把供应商当前解析出的 IP 复制成长期 A 记录。

## 3. TTL 到底控制什么

TTL 表示递归/客户端可以缓存答案的最长建议时间，不是全球切流 SLA。

低 TTL：

- 优点：计划变更和部分故障切流更快生效。
- 代价：权威查询量增加，更依赖 DNS 可用性；客户端也未必严格遵守。

高 TTL：

- 优点：缓存命中高，即使权威 DNS 暂时故障，已有答案仍可用。
- 代价：错误地址和计划迁移需要更久收敛。

生产常在迁移前至少一个旧 TTL 周期逐步降低 TTL，切换稳定后再恢复。事故发生后才把 TTL 从一小时改成一分钟，已有缓存仍会保留到原 TTL 到期。

## 4. 正缓存与负缓存

不存在的域名（NXDOMAIN）也会被缓存，时长受 SOA 参数影响。如果客户端在记录创建前访问过新域名，后续即使创建记录也可能继续失败。灰度新域名前先发布 DNS，再发布引用该域名的客户端或页面。

DNS 供应商的健康检查失败、权限错误或自动化误删也可能返回空答案。监控不仅要查“记录内容”，还要查多个地域递归解析的最终答案。

## 5. GSLB 的调度依据

GSLB（Global Server Load Balancing）通常通过权威 DNS 或 Anycast 把用户导向某个地域/边缘集群。

| 调度维度 | 示例 | 风险 |
|---|---|---|
| 地理位置 | 美国用户到美东，亚洲用户到新加坡 | 递归 DNS 位置不等于用户位置 |
| 运营商 | 电信走电信优化线路 | 规则多，维护复杂 |
| 延迟 | 选择探测 RTT 较低地域 | 探测点不代表每个真实用户 |
| 权重 | 10% 新地域、90% 旧地域 | DNS 缓存让精确比例失真 |
| 健康 | 故障地域从答案移除 | 探测误判会错误切流 |
| 容量 | 满载地域降低权重 | 需要及时、稳定的容量反馈 |

DNS 调度粒度较粗，适合地域级流量，不适合单请求级精细金丝雀。精细灰度通常在网关/LB 完成。

## 6. 健康检查怎样设计

健康检查从外部模拟真实访问，而不是只 ping IP。至少区分：

- DNS 是否返回预期记录。
- TCP 端口是否可连接。
- TLS 证书和 SNI 是否正确。
- HTTP 路径是否返回预期状态和内容。
- 地域是否具备服务关键请求的能力。

探测点要分布在不同地域和运营商，采用连续多次失败才摘除、连续多次成功才恢复的迟滞机制，避免网络抖动造成来回切换。健康检查自身要多副本，并明确超时和故障时默认行为。

### 健康不等于可以切流

备用地域可能 HTTP 200，却没有完整数据、缓存未预热、第三方白名单未配置或容量不足。因此切流条件还应包含数据库角色、复制延迟、依赖连通性、容量水位和业务合成测试。

## 7. DNS 故障切换时序

```text
T0   主地域发生故障
T+15s 多个探测点连续失败
T+30s GSLB 停止返回主地域地址
T+30s 新查询开始获得备用地域
T+30s～TTL 已缓存用户仍访问旧地址
T+?   客户端连接失败后重新解析并尝试新地址
```

因此仅靠 DNS 无法实现瞬时无损切换。可配合 Anycast、全局代理、短连接失败重解析、多地址返回和客户端退避重试。老地址也不应立即关闭，应尽可能返回重定向或保持排空。

## 8. 多 DNS 供应商

多权威 DNS 能降低单供应商故障，但不是简单配置两套 NS：

- 记录来源必须统一，避免两家答案不一致。
- 健康检查和 GSLB 策略需要等价实现。
- DNSSEC 密钥和 DS 记录要正确协调。
- API 自动化、权限、审计和变更顺序需要演练。
- CNAME 到单一 CDN 仍可能保留单点依赖。

如果团队无法持续验证一致性，多供应商会把显式单点变成隐蔽配置风险。

## 9. DNSSEC、DoH 与 HTTPDNS

### DNSSEC

DNSSEC 为 DNS 数据提供来源认证和完整性校验，防止响应被篡改，但不加密查询，也不隐藏用户访问的域名。密钥轮换或 DS 配置错误会让支持验证的解析器认为整个域名无效，必须自动监控签名有效期。

### DoH/DoT

DNS over HTTPS/TLS 加密客户端到解析器之间的查询。它改善局部隐私和篡改风险，但解析器仍能看到查询，也可能绕过企业网络策略。浏览器、操作系统和 App 行为可能不同。

### HTTPDNS

App 通过 HTTPS API 获取地址，常用于复杂移动网络。但它需要正确处理：

- TLS SNI 与 HTTP Host 仍使用原域名。
- IP 变化、TTL、本地缓存和备用解析器。
- 系统代理、VPN、IPv6、网络切换和合规。
- 不能绕开 CDN 按域名调度和 WAF 信任链。

## 10. 域名与环境规划

建议按信任和生命周期分离，而非无限使用 Path：

```text
www.example.com       用户 Web
api.example.com       公网 API
static.example.com    CDN 静态资源
upload.example.com    上传入口
admin.example.com     运营管理端（更严格访问控制）
openapi.example.com   第三方开放平台
internal.example.net  内部服务，不公开解析
```

生产、预发、测试域名和证书分离。管理端、开放平台和用户 API 有不同攻击面、限流与审计需求，不应只靠一个 `/admin` 路由区分。

## 11. 常见事故

| 事故 | 根因 | 预防 |
|---|---|---|
| 域名全量解析失败 | NS/续费/Registrar 权限问题 | 注册商锁、MFA、到期告警、分权 |
| 切流不生效 | 原 TTL 很长或客户端缓存 | 提前降 TTL、保留旧入口、多地探测 |
| 部分运营商失败 | 路由或递归解析差异 | 按运营商 RUM 与合成监控 |
| IPv6 用户失败 | AAAA 已发布但链路未完整验证 | 双栈压测、Happy Eyeballs、分阶段发布 |
| 新域名上线后仍 NXDOMAIN | 负缓存 | 先发记录，等待负 TTL 后再引用 |
| 自动健康检查反复切流 | 阈值过敏或探测单点 | 多探测点、迟滞、最小驻留时间 |

## 12. 监控与排查命令

监控权威查询成功率/延迟、SERVFAIL/NXDOMAIN、各地域答案、TTL、DNSSEC、域名与注册商到期时间、GSLB 权重和切换事件。

```bash
# 查询系统默认解析结果
nslookup api.example.com

# 指定公共递归 DNS，并查看记录链
dig @1.1.1.1 api.example.com A
dig @8.8.8.8 api.example.com AAAA

# 追踪从根到权威的委派链
dig +trace api.example.com

# 查看权威服务器
dig example.com NS
```

排障要比较：用户使用的递归 DNS、不同公共解析器、权威 DNS 直接查询和本地缓存。单台办公电脑解析正常不能证明全球正常。

## 13. 上线检查清单

- [ ] 域名注册、DNS 和云账号启用 MFA、最小权限与审计。
- [ ] 域名、证书、CAA、DNSSEC（若启用）有到期/有效性监控。
- [ ] A/AAAA/CNAME、TTL 和负缓存经过评审。
- [ ] 多地域、多运营商进行递归和端到端探测。
- [ ] 健康检查包含 TLS/HTTP/业务合成，不只 ICMP。
- [ ] 切流阈值有迟滞，备用地域容量和数据状态可用。
- [ ] 完成计划迁移和非计划故障切流演练。
- [ ] 客户端能在旧地址失败后重新解析，不永久缓存 IP。
