# DDoS、WAF 与 Bot 防护：分层阻断恶意流量

入口安全不是一个 WAF 开关。攻击可能耗尽网络带宽、连接表、TLS CPU、HTTP 线程、短信预算或业务库存。不同攻击必须在不同层处理，原则是**越廉价、越确定的恶意流量，越靠外阻断；越依赖业务上下文的判断，越靠近业务执行。**

## 1. 攻击面分层

![从网络攻击到业务滥用的分层防护体系](/architecture/edge-security-layers.svg)

WAF 不能吸收超过入口带宽的 DDoS，也不能理解全部业务欺诈；Anti-DDoS 不能发现用户每秒请求 100 次验证码的业务滥用。

## 2. DDoS 防护

### 常见类型

| 类型 | 目标 | 典型指标 |
|---|---|---|
| 容量型 | 打满网络带宽 | bps、pps、地域流量突增 |
| 协议型 | 耗尽连接/状态表 | SYN rate、半连接、连接失败 |
| 应用型 L7 | 用合法外观请求耗尽计算 | RPS、TLS handshakes、慢请求、缓存 miss |
| 反射放大 | 借 DNS/NTP/CLDAP 等放大流量 | 大量伪造源 UDP 流量 |

### Anycast 与清洗

Anycast 让同一 IP 在多个 PoP 宣告，攻击流量被分散到全球网络；清洗中心识别并丢弃恶意流量，把干净流量转发源站。关键是源站 IP 隐藏，否则攻击者可绕过清洗直接攻击。

### 源站保护

- 源站安全组仅允许边缘/清洗回源地址或专线。
- 历史 DNS、邮件 Header、证书透明日志和错误页可能泄露源站，需要持续扫描。
- 回源链路使用 mTLS或签名 Header，签名有时间戳和轮换。
- 源站有自身限流和连接上限，不能完全信任边缘永不失效。

### 防护阈值和应急

区分自动防护阈值、弹性带宽上限和黑洞阈值。黑洞意味着运营商/云平台直接丢弃目标 IP 流量，需知道触发条件、持续时间和切换方案。攻击应急预案包含供应商联系人、临时降级静态页、非核心接口关闭、跨域切流和证据保留。

## 3. WAF 负责什么

WAF 解析 HTTP 请求，在应用之前执行通用安全规则：

- 请求协议合法性、方法、Host、路径、Header、Body 大小。
- OWASP 常见攻击特征：SQL 注入、XSS、路径穿越、命令注入。
- 已知 CVE/框架漏洞的虚拟补丁。
- IP/地域/ASN/威胁情报和访问频率规则。
- 文件上传类型、扩展名和部分内容特征。
- API Schema 正向校验：只允许已知路径、字段和类型。

WAF 是补充防线，不替代参数化 SQL、输出编码、对象级授权和依赖升级。依赖 WAF 长期掩盖代码漏洞会积累不可见风险。

## 4. 规则生命周期

![WAF 安全规则从需求到到期复审的生命周期](/architecture/waf-rule-lifecycle.svg)

每条自定义规则应有 ID、描述、负责人、适用域名/路径、动作、创建原因、到期时间和回滚方法。紧急规则也要在事故后补充评审，避免永久白名单。

### 动作等级

- Log/Count：只观察，不影响请求。
- Challenge：JS Challenge、验证码或设备验证。
- Rate Limit/Throttle：限制速率或延迟。
- Block：明确拒绝。
- Allow/Bypass：跳过部分规则，风险最高，必须限定路径、来源和期限。

## 5. 正向安全模型

负向规则寻找“看起来像攻击”的字符，永远可能绕过。API 更适合加入正向校验：

- 只允许已发布的 Host、Path 和 HTTP 方法。
- Content-Type 必须匹配，JSON 深度、字段数和总大小有限。
- Query/Header/Body 字段符合 OpenAPI Schema。
- 枚举、长度和格式严格，未知字段按契约处理。
- 上传只允许特定 MIME、大小和文件签名。

正向模型上线前先观察真实流量，处理旧客户端和第三方差异，避免一次性阻断。

## 6. Bot 与业务滥用

Bot 不一定是攻击：搜索引擎、可访问性工具、合作伙伴和监控也是自动化流量。需要分类，而不是“不是浏览器就封”。

### 识别信号

- IP/ASN、代理/Tor、数据中心出口和信誉。
- TLS/HTTP 指纹、Header 一致性、浏览器能力。
- Cookie、设备标识、挑战通过情况。
- 请求间隔、路径序列、鼠标/页面行为（需隐私评估）。
- 账号失败率、设备关联、地理跳变和业务结果。

单个信号容易误判，应组合评分。设备指纹不是强身份，也可能涉及隐私和监管要求。

### 典型业务防护

| 场景 | 限制维度 | 额外措施 |
|---|---|---|
| 登录撞库 | IP + 账号 + 设备 + ASN | MFA、泄露密码检测、风险登录 |
| 短信轰炸 | 手机号 + IP + 设备 + 租户 | 图形验证、日配额、成本告警 |
| 抢券/秒杀 | 用户 + 设备 + 活动 | 排队令牌、库存预留、业务幂等 |
| 爬虫 | IP + 指纹 + 路径 + 速率 | robots、合作 API、内容水印 |
| API Key 滥用 | Key + 租户 + 路由 | 配额、签名、撤销、账单异常 |

限流不能只按 IP：NAT 后可能有成千真实用户，攻击者也可轮换代理。

## 7. 限流算法和部署位置

| 算法 | 特点 | 适用 |
|---|---|---|
| 固定窗口 | 简单，但窗口边界可瞬时翻倍 | 低风险配额 |
| 滑动日志/窗口 | 更准确，状态成本高 | 精确审计型限制 |
| 令牌桶 | 平均速率 + 允许突发 | 通用 API 限流 |
| 漏桶 | 平滑输出 | 保护稳定速率下游 |
| 并发限制 | 限制正在处理数量 | 慢接口、昂贵操作 |

边缘做粗粒度全局保护，网关按路由/租户配额，业务服务按资源和业务规则限制。多层限制要返回一致错误语义，避免总量不透明。

## 8. TLS 与应用层攻击细节

TLS 握手比转发已有连接更昂贵。启用会话复用、合理握手速率限制和边缘终止；但不能为了性能支持弱密码套件。慢速攻击通过极慢发送 Header/Body 占用连接，应设置 Header 完成、Body 读取、最小速率和空闲超时。

请求走私（Request Smuggling）利用前后代理对 Content-Length/Transfer-Encoding 解析不一致。边缘和源站使用严格、统一的 HTTP 解析，拒绝歧义请求，及时升级代理组件。HTTP/2 Rapid Reset 等协议级攻击也依赖供应商和实现升级，而不只靠普通 WAF 规则。

## 9. 文件上传防护

推荐流程：

![用户文件从隔离上传到安全发布的流程](/architecture/secure-upload-flow.svg)

不要只检查扩展名或客户端 Content-Type。文件名不直接作为对象 Key，不在应用服务器可执行目录落盘。下载响应设置正确 Content-Type、`Content-Disposition` 和 `X-Content-Type-Options: nosniff`。

## 10. 真实 IP 与 Header 信任

公网客户端可自行发送 `X-Forwarded-For`。第一层受信边缘必须删除外部同名 Header，再按约定写入：

![真实客户端 IP 与转发 Header 的可信传递链](/architecture/trusted-forwarded-headers.svg)

应用根据受信代理跳数解析，而不是取列表第一个或最后一个。内部身份 Header 同样必须覆盖，并用 mTLS/网络策略保护代理到网关链路。

## 11. Fail-open 还是 Fail-closed

防护组件故障时的默认行为必须逐能力定义：

| 能力 | 常见倾向 | 原因 |
|---|---|---|
| 支付/管理端认证 | Fail-closed | 放行风险不可接受 |
| WAF 通用规则引擎 | 依风险决定 | 全站拒绝也可能造成事故 |
| Bot 评分服务 | 降级到基础限流 | 避免外部评分故障拖垮入口 |
| 威胁情报更新 | 使用最后有效版本 | 短时陈旧优于无规则 |
| 日志导出 | Fail-open + 有界丢弃 | 不能阻塞业务数据面 |

Fail-open 不是“完全不防护”，而是退化到本地缓存策略、静态规则和更严格速率限制。

## 12. 误报、申诉与调试

被 WAF 阻断应返回无敏感信息的事件 ID。支持人员可用事件 ID 查询规则、请求摘要、来源、时间和动作。不要让用户反复提供完整 Token 或请求体。

误报处理优先缩小规则范围或修正规则，而不是给整个 IP/账号永久 Allow。例外包括负责人、原因、最小 Path/方法、到期时间，并持续记录本来会命中的规则。

## 13. 指标和告警

- 攻击流量 bps/pps、清洗流量、黑洞状态。
- TLS 新建连接、握手失败和协议分布。
- WAF 每规则命中、阻断、Challenge 通过率和误报反馈。
- Bot 分类、登录失败、验证码发送、活动请求与成功转化。
- 按来源/ASN/地域/路径的请求率与状态码。
- 源站绕过探测、回源鉴权失败和非法 Host。
- 防护规则/策略/白名单变更事件。

告警必须关联业务影响。攻击被成功吸收且用户无影响可只记录；源站 5xx、延迟或成本同时异常才升级响应。

## 14. 上线检查清单

- [ ] DDoS、协议、HTTP、应用漏洞和业务滥用分别有防线。
- [ ] 源站 IP 隐藏，只接受可信回源并定期扫描暴露。
- [ ] WAF 规则先 Count/灰度，具备事件 ID、误报和回滚流程。
- [ ] API 正向 Schema、Body/Header/方法限制已配置。
- [ ] 限流组合 IP、主体、租户、设备和业务资源，不只按 IP。
- [ ] 登录、短信、上传、导出、秒杀等高风险路径单独建模。
- [ ] 上传隔离、扫描、重编码和安全分发流程完整。
- [ ] 转发 Header 清洗、可信代理和真实 IP 解析经过测试。
- [ ] 每个组件 Fail-open/closed 与降级行为明确。
- [ ] 完成 DDoS、WAF 误杀、Bot 服务故障和源站绕过演练。
