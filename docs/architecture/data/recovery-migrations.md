# 备份恢复、灾难恢复与 Schema 演进

高可用副本不能替代备份：误删、逻辑损坏和勒索会复制到所有副本。备份也不能替代恢复演练：只有在目标时间内恢复出可启动、完整且安全的数据，备份才有价值。

## 1. RPO、RTO 与恢复链

![RPO、RTO 与时间点恢复链](/architecture/data-rpo-rto.svg)

- **RPO**：恢复点距事故时刻最多允许丢多少数据。
- **RTO**：从事故开始到业务恢复可接受多久。
- **PITR**：基础全量/快照 + 连续 WAL/binlog 重放到目标时间。

不同数据等级有不同目标。订单账本可能分钟级 RPO，搜索索引可从权威库重建。目标决定备份频率、跨区复制、成本和演练方式。

## 2. 备份设计

- 全量/增量/日志形成可验证链，备份目录与保留策略版本化。
- 至少一份跨账户/跨地域且不可变/防删除，降低凭证失陷爆炸半径。
- 备份加密，密钥与数据分权；密钥备份/恢复同样演练。
- 定期校验校验和、可读性、连续日志缺口和所需软件版本。
- 备份账户只写目标，应用运行账户不能删除备份。
- 保留同时满足业务、法规、删除和存储成本。

## 3. 恢复演练

![从备份到应用恢复验证的演练流程](/architecture/data-restore-drill.svg)

在隔离环境恢复基础备份、重放日志到目标点、运行一致性校验、启动兼容版本应用、验证关键旅程和权限，再测量实际 RPO/RTO。恢复旧备份后要重新应用账户封禁、密钥撤销和依法删除记录，避免安全状态倒退。

演练覆盖单表误删、整库故障、区域不可用、加密密钥问题和逻辑污染；每次输出耗时分解和行动项。

## 4. 在线 Schema 变更

![Expand Migrate Contract 数据库演进](/architecture/data-expand-contract.svg)

1. **Expand**：新增 nullable/兼容列、表或索引；旧应用继续运行。
2. **Dual compatible**：新应用兼容新旧读写，必要时由单一写路径同步。
3. **Backfill**：小批、限速、可暂停、可重入，记录 checkpoint 与校验。
4. **Switch**：灰度切读，比较结果和业务指标。
5. **Contract**：确认所有消费者和回滚窗口结束后删除旧结构。

不要在同一发布中改名/删列并要求所有实例瞬时升级。DDL 在大表上可能锁表、产生 IO/复制延迟和日志爆量，需预演并设置锁等待/执行上限。

## 5. 索引与约束上线

在线创建索引仍会消耗 IO/CPU、扩大复制延迟。先检查重复索引和空间，低峰限速，监控进度并有取消策略。新增 NOT NULL/UNIQUE 先清洗和验证历史数据，再逐步启用约束；验证失败不能卡死整个发布。

## 6. 数据回填

按稳定主键范围分批，不用深 offset；每批独立事务，幂等更新，只修改仍需迁移的行。与在线写竞争时用版本/条件或新写路径同时填充新字段。记录扫描、更新、跳过、冲突、速率和预计完成时间。

回填程序也按生产服务管理：版本、审计、暂停、恢复、容量和回滚，而不是临时 SQL 一次跑到底。

## 7. 删除与归档

大批删除分段，注意 MVCC 膨胀、复制和磁盘回收。可按时间分区直接归档/删除分区，但分区键必须匹配保留策略。归档数据仍需权限、加密、可读性和删除合规。

## 8. 上线检查

- RPO/RTO 是否按数据等级定义并由恢复演练证明？
- 是否有跨账户/地域、不可变、加密且不可被应用删除的备份？
- PITR 日志链、密钥和目标应用版本是否一起验证？
- Schema 是否 expand-migrate-contract，允许新旧实例同时运行？
- DDL/索引/回填是否限速、可暂停、可重入、有进度和回滚？
- 恢复旧备份后撤销、删除和安全策略是否不会倒退？
