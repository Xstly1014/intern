# Java 数据访问与存储生产参考架构

参考架构以 OLTP 为权威事实源：Java 业务服务通过受限 Repository/Query Port 访问主库和允许陈旧的副本；Outbox/CDC 构建缓存、搜索、对象元数据和分析投影；备份与恢复形成独立保护域。

## 1. 生产参考拓扑

![Java 数据访问与存储生产参考拓扑](/architecture/data-reference-topology.svg)

- 写用例只进入权威主库，本地事务同时保存业务、幂等和 Outbox。
- 读路由按一致性要求选主/副本，不按 HTTP GET 或方法名盲目判断。
- Cache/Search/Analytics 是派生副本，携带 source version/watermark，可删除重建。
- 对象存储保存大文件，关系库保存所有者、状态、校验和和对象 Key。
- 备份跨账户/地域隔离，恢复环境定期验证，而非生产只做快照。

## 2. Java 数据访问组合

| 场景 | 适合工具 | 注意 |
|---|---|---|
| 聚合 CRUD/领域对象 | JPA/Hibernate | OSIV、懒加载、N+1、批量 DML |
| 明确 SQL/Projection | JdbcClient/MyBatis/jOOQ | 参数化、映射、方言和测试 |
| 响应式数据库 | R2DBC | 驱动/事务生态、全链路非阻塞 |
| 数据库迁移 | Flyway/Liquibase | 兼容发布、DDL 成本、权限分离 |
| 缓存 | Spring Cache/Redis Client | Key 变体、TTL、序列化、雪崩 |

不要因项目同时使用 JPA 和 SQL 就认为架构失败：命令聚合与复杂查询的访问模型本就不同，关键是边界和事务清晰。

## 3. 连接与实例容量

连接预算从数据库可承载并发反推，再分给在线实例、任务、迁移和运维。自动扩容必须同时约束每实例池，避免 Pod 翻倍让潜在连接翻倍。数据库代理能减少建连/复用成本，但不能创造查询吞吐或消除事务会话状态。

容量模型包含数据/索引增长、写放大、WAL/binlog、临时空间、MVCC 膨胀、备份窗口、复制带宽、缓存副本和故障冗余。磁盘 80% 才告警通常太晚，扩容和重建都需要临时空间。

## 4. 可观测模型

![从连接池到存储引擎的数据观测链](/architecture/data-observability.svg)

### 应用侧

连接 acquire/usage、事务时长、查询指纹耗时、受影响/返回行、timeout、乐观冲突、缓存回源和序列化字节。

### 数据库侧

QPS/TPS、CPU、IOPS/延迟、buffer/cache 命中、活跃连接、锁等待/死锁、慢查询总成本、临时表、复制位点和最老事务。

### 派生与恢复

缓存命中/淘汰/热 Key、搜索/CDC watermark 和失败、对象孤儿/扫描积压、备份成功/年龄、最近恢复演练的实际 RPO/RTO。

SQL 标签使用归一化 query ID/use case，不把用户输入和完整 SQL 参数放指标。

## 5. 故障场景

| 故障 | 期望行为 |
|---|---|
| 缓存全失效 | singleflight + 有界回源 + 限流，数据库不雪崩 |
| 副本严重延迟 | 一致性查询切主/拒绝，非关键查询标陈旧 |
| 主库切换 | 旧主 fenced，连接退避重建，幂等处理未知写结果 |
| 磁盘/IO 饱和 | 降低批任务/回填，保护交易写入，容量扩展 |
| 错误 DDL | 达到锁等待/时间上限自动停止，回滚兼容应用 |
| CDC/搜索中断 | 权威写入继续，积压可见，恢复后按版本追赶 |
| 误删/逻辑污染 | 停写/隔离，PITR 到事故前并回放合法增量 |

## 6. 数据发布流程

Schema 变更、应用变更、回填和清理是多个独立可观察阶段。每阶段有前置条件、指标、暂停/回滚和所有者。数据库迁移账号与应用账号分离；发布失败不能让应用自动拥有 DDL 超级权限“自修复”。

读写双轨时定义单一事实来源，影子读比较但不影响用户；校验覆盖数量、checksum、业务不变量和抽样语义，不只比较总行数。

## 7. 测试与演练

- Repository 集成测试使用真实数据库版本，覆盖约束、排序、null、时区和方言。
- 并发测试覆盖唯一竞争、乐观冲突、死锁和写偏差。
- 查询性能测试使用生产量级分布与倾斜，保存计划基线。
- 缓存/搜索测试覆盖失效失败、重复乱序、全量重建和权限变化。
- 故障演练覆盖主库切换、副本延迟、连接耗尽、缓存雪崩、磁盘逼近和 CDC 中断。
- 恢复演练从空环境开始，不使用已经人工修好的测试库。

## 8. 完整评审清单

### 所有权与访问

- 每个事实是否有唯一写主，跨服务是否不直接更新数据库？
- Repository/Query 是否强制 tenant、授权、结果上限和参数化？
- ORM 懒加载、N+1、批量和事务生命周期是否明确？

### 正确性与性能

- 约束、隔离、版本/锁是否覆盖并发不变量？
- 核心查询是否有真实计划、稳定分页和容量假设？
- 连接、事务、查询和重试预算是否在数据库承载范围内？

### 派生与扩展

- 缓存、搜索、对象、分析是否有版本、删除、新鲜度和重建？
- 复制陈旧、故障转移和写后读是否有业务契约？
- 分片是否有路由、热点、迁移、全局约束和 fan-out 控制？

### 恢复与演进

- 备份是否隔离、加密、不可变并经过恢复验证？
- RPO/RTO 是否实测，PITR、密钥和应用兼容是否完整？
- Schema/回填是否兼容、限速、可暂停、可重入和可回滚？
