# 授权模型、策略决策与资源级执行

认证只证明“你是谁”，授权要回答“你现在能否对这个具体资源执行这个动作”。真实系统的越权通常不是没有登录，而是只检查角色/Scope，没有校验对象归属、租户、关系、状态和敏感字段。

## 1. 授权决策输入

![授权 PDP PEP 与资源事实协作](/architecture/security-authorization-decision.svg)

一个完整决策至少包含：主体与 actor、动作、资源类型和 ID、租户、角色/Scope、资源关系和状态、认证强度、时间/地域/设备风险，以及策略版本。

网关掌握 API 与粗 Scope，资源服务掌握 owner、订单状态、组织关系等最终事实，所以最终对象级授权必须在资源所有者执行。

## 2. 授权模型组合

| 模型 | 擅长 | 风险 |
|---|---|---|
| RBAC | 岗位、后台菜单、稳定职责 | 角色爆炸，难表达对象关系 |
| ABAC | 部门、地域、时间、风险等条件 | 策略复杂、属性新鲜度与解释成本 |
| ReBAC | 所有者、成员、分享、组织层级 | 关系一致性、图查询性能 |
| ACL | 单资源明确授权列表 | 大规模维护、继承和撤销成本 |
| Capability | 受限链接/委托能力 | 泄露即授权，必须限制范围和时效 |

生产系统通常组合：RBAC 给出职位能力，ReBAC/ACL 判断对象关系，ABAC 加风险和环境条件。

## 3. PEP、PDP、PIP 与策略管理

- **PEP**（Policy Enforcement Point）在 Controller、应用用例、查询和数据出口执行允许/拒绝。
- **PDP**（Policy Decision Point）根据策略和上下文给出决策及义务。
- **PIP** 提供部门、关系、资源状态等属性，需定义来源和新鲜度。
- **PAP** 管理策略编写、评审、版本、测试、灰度和回滚。

集中 PDP 便于治理，但会引入延迟和可用性依赖；本地策略库低延迟，却需可靠分发与版本一致。无论何种形态，未知、超时和属性缺失默认拒绝，并记录决策版本与原因。

## 4. 检查时机

读操作把授权过滤下推到查询，避免先读全量再删除。写操作在用例内读取最新资源后同时检查权限与状态，避免检查和使用之间（TOCTOU）发生变化。批量接口逐项给出允许结果或在契约中定义整体原子性，不能只检查“有批量权限”。

隐藏按钮、BFF 字段裁剪和前端路由守卫都只是体验控制，不能代替服务端授权。

## 5. 多层决策和义务

PDP 除 allow/deny 还可返回义务：遮蔽字段、限制数量、要求水印、触发 Step-up、记录强审计。执行点必须认识这些义务；未知义务不能静默忽略。

错误响应要避免泄露敏感资源是否存在。某些场景将无权限映射为 404，但内部审计仍区分 not-found 与 denied。

## 6. 缓存和一致性

授权缓存 Key 包含主体、actor、租户、动作、资源/关系版本和策略版本。高风险拒绝/允许缓存时间应短，角色撤销、离职、租户切换和关系变更触发失效。不能只按 user ID 缓存“管理员=true”。

## 7. 策略工程

- 策略代码化、版本化，变更需双人评审和语义 diff。
- 表驱动测试覆盖 allow、deny、缺属性、跨租户、代理、边界时间和冲突规则。
- 新策略先 shadow evaluation，对比旧决策但不影响流量，分析差异后灰度。
- Break-glass 权限短期、审批、强 MFA、最小范围并实时告警，不能是永久超级账号。

## 8. Spring/Java 落地

URL 规则适合“该 API 是否需要登录”；`@PreAuthorize` 可做用例入口的粗粒度能力检查；复杂对象决策放在应用/领域授权服务，并将过滤条件传给 Repository。不要在 SpEL 中塞入大量数据库查询和业务流程。

方法安全必须覆盖非 HTTP 入口，如消息消费者、定时任务和内部调用。测试要直接调用用例验证授权，不能只测 Controller Filter。

## 9. 上线检查

- 每个敏感动作是否定义 subject、action、resource、tenant 和策略所有者？
- 最终对象级授权是否在资源服务，而不是只在网关/BFF？
- 列表、搜索、导出、批量和消息入口是否执行同等授权？
- 策略失败、属性缺失和超时是否默认拒绝且可解释？
- 缓存是否能在离职、角色/关系变更后及时失效？
- 策略发布是否有测试、影子评估、灰度和回滚？
