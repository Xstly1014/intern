# 审计、威胁检测与安全事件响应

预防控制一定会有遗漏。安全运营要把认证、授权、数据访问、配置、密钥和业务高风险动作关联起来，在攻击扩大前检测，并保留足够证据完成隔离、恢复和复盘。

## 1. 三类记录不要混为一谈

| 类型 | 目的 | 示例 |
|---|---|---|
| 访问日志 | 性能与请求排障 | route、状态、耗时、trace ID |
| 安全事件 | 检测可疑行为 | Token 重放、跨租户拒绝、异常出站 |
| 业务审计 | 证明谁改变了业务事实 | 权限变更、退款、导出、密钥操作 |

业务审计在事务成功语义处产生，不能由网关看到“请求返回 200”就代替。访问日志可采样，关键审计通常不能采样。

## 2. 审计事件模型

事件包含：event ID、时间、actor、subject、workload、tenant、动作、资源类型/ID、结果、拒绝原因、策略版本、认证强度、来源、trace/request ID、变更前后摘要和代理原因。

不记录 Token、密码、完整请求 Body 和不必要个人数据。事件 Schema 版本化；时间来自可信同步源；写入追加型、受限存储，并检测删除、停流和延迟。

## 3. 从信号到处置

![安全信号检测与事件响应闭环](/architecture/security-detection-response.svg)

1. 身份、应用、数据、云平台、WAF 和终端产生结构化信号。
2. 规范化主体、IP、设备、资源和时间，关联同一攻击链。
3. 规则、基线和威胁情报产生告警；高基数原始事实保留在日志仓库。
4. 告警富化资产价值、暴露面、用户风险和最近变更后分级。
5. Playbook 执行撤销会话、禁用身份、隔离 workload、封锁出站或暂停导出。
6. 取证、恢复、通知、复盘将新控制反馈到设计和检测。

## 4. 值得检测的行为

- 同一 Refresh Token 家族重放、异常国家/设备快速切换、MFA 疲劳攻击。
- 授权拒绝突然增加、连续枚举 ID、跨租户探测和大量不存在资源查询。
- 非常规时间/主体的大批量搜索、导出、解密和对象下载。
- 服务身份调用从未使用的 API、访问新地域或云元数据地址。
- Secret/策略/角色/安全组变更后紧接异常访问。
- 审计源停流、事件延迟、时间漂移或日志量异常下降。

检测需基于受控窗口和实体基线，避免把 user ID 放指标标签造成基数爆炸。规则有负责人、测试数据、版本、误报率和退役日期。

## 5. 事件分级与 Playbook

分级综合数据敏感度、权限级别、影响租户、攻击是否持续、证据可信度和可恢复性。每级明确响应时限、指挥者、技术/法务/业务沟通和升级路径。

Playbook 不能只有文档：API 凭证失窃、管理员账户接管、跨租户泄露、恶意依赖、勒索/破坏、审计中断分别演练。自动隔离要可审计、最小化影响且有人工升级与回滚。

## 6. 取证和证据保护

保留相关日志、镜像 digest、配置版本、策略版本、部署记录、云审计和时间线；使用受控快照和哈希证明完整性。不要为取证贸然登录被入侵主机改写现场。访问证据本身需审批和审计。

恢复时不仅重建服务，还要轮换受影响凭证、修复持久化入口、验证制品与数据完整性，并监控攻击者是否回归。

## 7. 指标与 SLO

- MTTD、MTTA、MTTC（控制/隔离）和恢复时间。
- 按严重度的未处置告警、误报率、重复事件与超 SLA。
- 审计覆盖率、摄取延迟、丢弃/停流、时钟偏差。
- Token/证书/Secret 轮换成功率与剩余期限。
- 高危漏洞暴露时间、例外数量与逾期率。
- 演练发现项关闭率和同类事件复发率。

## 8. 上线检查

- 高风险业务动作是否在事务成功点产生不可采样审计？
- actor、subject、workload、tenant、资源与策略版本是否可关联？
- 审计管道中断、延迟和篡改是否自身可检测？
- 每条高严重度告警是否有负责人、上下文和可执行 Playbook？
- 隔离操作是否能撤销会话、身份、证书和网络访问，而非只能告警？
- 恢复是否验证数据/制品完整性并轮换所有受影响凭证？
