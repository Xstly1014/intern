# 应用、API、文件与软件供应链安全

应用安全的关键是把不可信输入限制在明确语法和权限内，把危险能力隔离，并保证从源码、依赖、构建到运行制品都可追溯。WAF 是缓冲层，不能替代代码中的安全边界。

## 1. 攻击面与控制位置

![主要应用攻击面与纵深控制](/architecture/security-application-controls.svg)

| 风险 | 首要工程控制 | 额外防线 |
|---|---|---|
| SQL/命令/模板注入 | 参数化 API、禁止拼接解释器输入 | 最小运行权限、WAF |
| XSS | 按输出上下文编码、安全模板 | CSP、Trusted Types |
| CSRF | CSRF Token、Origin、SameSite | 高风险重认证 |
| SSRF | 目标 allowlist、解析后 IP 校验 | 出站代理/网络策略 |
| IDOR/越权 | 每次对象级授权、租户过滤 | 不可猜 ID 仅降低枚举 |
| 反序列化 | 受限 Schema/类型白名单 | 禁用危险多态和 gadget 依赖 |
| 路径穿越 | 服务端对象 ID、规范化后根目录校验 | 隔离存储权限 |
| 重放 | 短时签名、nonce、幂等与状态核验 | 风险检测 |

## 2. 输入不是只做 Bean Validation

限制请求字节、JSON 深度、字段数、集合大小、字符串长度、数字范围、压缩比和解析时间。对 URL、正则、压缩包、XML、图片等复杂格式使用成熟解析器并设资源上限，防止算法复杂度和解压炸弹。

格式校验不能承担业务授权。`@Valid orderId` 只说明格式正确，不说明当前用户有权访问该订单。

## 3. SSRF 与出站安全

不要直接请求用户提供的任意 URL。使用逻辑资源 ID 映射服务端 allowlist；若必须支持 URL，限制 scheme/port/domain，解析 DNS 后拒绝 loopback、link-local、私网和云元数据地址，每次重定向重新验证，并防 DNS rebinding。出站网络策略作为第二层。

Webhook 回调目标也可能 SSRF。注册时验证不够，实际投递时仍要验证最终地址。

## 4. 文件上传和下载

文件名、扩展名和浏览器 Content-Type 都不可信。限制大小与数量，检测 magic bytes/真实格式，随机对象名，隔离区异步恶意扫描；在扫描通过前不可公开下载。图片/文档转码进沙箱，禁止上传文件作为服务端模板或可执行代码。

下载使用服务端授权后的短时签名 URL，Content-Disposition 和 Content-Type 安全设置，避免对象存储 Bucket 公开。压缩包展开校验路径、总大小、文件数和嵌套层数。

## 5. Java 特有风险

- 禁止对不可信数据启用任意类型 Java 原生序列化；JSON 多态类型使用显式白名单。
- XML 解析关闭外部实体和 DTD，防 XXE。
- 表达式、脚本、模板和 SpEL 不接受用户原文。
- URLConnection/HTTP 客户端设置连接、读取、总 deadline、重定向和最大响应。
- 正则避免灾难性回溯，对不可信模式使用安全引擎或限制。
- Actuator、JMX、Heap dump、调试端口和 Swagger 管理面不暴露公网。

## 6. 供应链可信路径

![从源码到运行制品的软件供应链](/architecture/security-supply-chain.svg)

依赖锁定并通过可信仓库代理；生成 SBOM，扫描直接/传递依赖、基础镜像和许可证。漏洞门禁按可达性、利用条件、资产暴露与 SLA 分级，不能只看 CVSS，也不能长期忽略。

CI 使用短期身份，不把云密钥写在变量和构建日志。构建环境隔离，制品生成 provenance 并签名；部署只允许受信任流水线签名的不可变 digest，不能以可变 `latest` 为依据。

## 7. 安全开发生命周期

1. 设计阶段做数据流和滥用场景评审。
2. 合并前做代码评审、Secret 扫描、SAST 和依赖检查。
3. 集成环境做授权、跨租户、模糊输入和 DAST。
4. 发布前核对配置、权限、SBOM、签名、回滚和风险接受。
5. 运行中监测新漏洞、异常出站、制品漂移和利用迹象。

工具结果要有所有者、去重、基线和修复时限；“扫描通过”不等于设计安全。

## 8. 上线检查

- 每类不可信输入是否同时有语法、大小、时间和资源上限？
- SSRF 是否在 DNS 解析和每次重定向后验证目标，并限制出站网络？
- 上传是否隔离扫描，下载是否重新授权且对象存储不公开？
- Java 反序列化、XML、表达式和管理端口是否使用安全配置？
- 每个运行制品是否可追溯到源码、依赖、构建身份、SBOM 和签名？
- 高危漏洞是否有可达性判断、SLA、例外到期和紧急发布路径？
