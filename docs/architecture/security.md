# 身份与安全层：贯穿全链路的信任体系

安全不是入口处的一次 Token 校验，而是贯穿身份、权限、数据、代码、供应链和运维全过程的横切能力。核心问题依次是：**谁在访问、代表谁访问、允许操作什么资源、风险是否可接受、事后能否追溯。**

## 1. 认证、授权与审计

```text
用户 → 身份提供方登录 → Access Token
                       ↓
网关：验证签名/过期/受众 → 服务：验证权限与资源关系 → 审计日志
```

- **认证 Authentication**：确认主体身份，主体可能是用户、设备、服务或自动任务。
- **授权 Authorization**：判断主体能否对某资源执行某动作。
- **审计 Audit**：记录谁在何时以何种结果做了什么，且记录不能被普通业务人员篡改。

## 2. 用户身份体系

Web/App 推荐使用 OAuth 2.x 与 OpenID Connect。Access Token 短时有效，只携带必要声明；Refresh Token 旋转并支持撤销；授权码流程使用 PKCE；高风险操作触发 MFA 或重新认证。Token 的 `iss`、`aud`、`exp`、`nbf`、签名算法与 key ID 都要校验，不能只解码 payload。

JWT 适合离线验签和跨服务传播，但权限变更不会立即生效；不透明 Token 便于即时撤销，却依赖在线 introspection。可采用短期 JWT + 本地公钥缓存 + 风险名单的折中方案。Cookie 模式需设置 `HttpOnly`、`Secure`、`SameSite` 并防 CSRF。

## 3. 服务身份体系

服务间不能因为在“内网”就默认可信。每个工作负载使用独立服务身份，通过 mTLS、短期凭证或云 IAM 认证；禁止共享永久 Access Key。服务 A 代表用户调用 B 时，同时传递服务身份与受约束的用户委托信息，B 仍做最终授权。

## 4. 授权模型

| 模型 | 适用场景 | 局限 |
|---|---|---|
| RBAC | 管理后台、岗位权限 | 角色爆炸，难表达资源关系 |
| ABAC | 按部门、地域、时间、风险动态判断 | 策略调试和解释较复杂 |
| ReBAC | 文档共享、组织关系、资源所有权 | 需要关系图与高效查询 |
| ACL | 单资源明确列出主体权限 | 大规模维护成本高 |

网关可做粗粒度 Scope 校验，业务服务必须做资源级授权，例如“该订单属于当前用户/租户”。授权默认拒绝，策略变更版本化、可测试、可解释。管理员代操作需要明确的 impersonation 标记和审计。

## 5. 多租户隔离

租户 ID 只能来自可信身份上下文，不能接受客户端任意指定。常见隔离从弱到强为共享库共享表（每表含 tenant_id）、共享实例独立 Schema、独立数据库、独立集群。无论哪种模式，都要确保：

- 唯一索引和查询条件包含租户维度。
- 缓存 Key、MQ Topic/Header、搜索索引、对象存储路径包含租户边界。
- 后台任务与数据导出传播租户上下文。
- 超级管理员跨租户访问有审批、限时和完整审计。

## 6. 数据安全

对数据分级：公开、内部、敏感、受监管。传输中 TLS，加密存储由 KMS 管理密钥，高敏字段可应用层信封加密或 Tokenization。密码使用 Argon2id/bcrypt/scrypt 等慢哈希并独立加盐；日志、Trace、异常、测试数据和备份同样需要脱敏与访问控制。

密钥不得写入 Git、镜像或普通配置中心。通过 Secret Manager 注入短期凭证，定期轮换并监控使用；应用日志不得打印环境变量全集。

## 7. 常见攻击面及控制

| 风险 | 主要控制 |
|---|---|
| 注入 | 参数化查询、严格解析、最小数据库权限 |
| XSS | 输出编码、CSP、避免信任富文本 |
| CSRF | SameSite、CSRF Token、校验 Origin |
| SSRF | 出站域名/IP 白名单、禁止访问元数据地址、重定向复检 |
| 越权/IDOR | 每次资源访问做对象级授权 |
| 重放 | nonce/时间戳/幂等键、短有效期签名 |
| 文件上传 | 类型与内容检测、大小限制、隔离扫描、随机对象名 |
| 供应链 | 锁定版本、SBOM、依赖/镜像扫描、签名制品 |

## 8. 审计与事件响应

登录失败、权限变更、敏感查询、导出、退款、配置和密钥操作都应形成结构化审计事件，包含主体、委托者、动作、资源、前后状态摘要、时间、来源、Trace 和结果。审计存储限制修改与删除，并设置合规保留期。异常登录和批量访问进入风险检测与告警流程。

## 9. Java 落地

Spring Security 负责过滤链和方法授权；Resource Server 验证 OAuth/OIDC Token；`@PreAuthorize` 适合粗粒度入口，复杂资源规则封装为领域授权服务。使用参数化 ORM/SQL，配置安全反序列化，升级 JDK 和依赖，关闭 Actuator 敏感端点公网访问。安全测试覆盖未认证、越权、跨租户、重放和敏感字段泄露，而不只测试成功路径。

## 10. 关键指标

监控认证成功率与延迟、MFA 失败、Token 刷新/撤销、授权拒绝、跨租户拦截、WAF 高风险命中、Secret/证书剩余时间、依赖漏洞修复时长和异常数据导出。安全告警必须有负责人、分级、处置剧本和复盘。
