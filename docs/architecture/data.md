# 数据访问与存储层：保存权威事实，提供可预测的访问能力

数据层不等于“MySQL 那一层”。它包含应用访问边界、事务数据库、缓存、搜索、对象存储、读模型、复制、分片、备份与恢复。核心原则是：**每个业务事实只有一个权威写入来源，其他数据形态都是有来源、有版本、有新鲜度并且可重建的副本。**

## 1. 系统中的数据版图

![权威事实与派生存储的数据版图](/architecture/data-storage-landscape.svg)

| 数据形态 | 主要责任 | 不能承担 |
|---|---|---|
| OLTP 数据库 | 事务、约束、权威业务事实 | 海量全文检索、无限分析扫描 |
| Redis/本地缓存 | 热点副本、短期加速、协调 | 无恢复设计的唯一业务事实 |
| 搜索引擎 | 全文、筛选、聚合、相关性 | 订单强一致写入和最终授权事实 |
| 对象存储 | 图片、附件、归档、大对象 | 高频行级随机更新 |
| 数仓/ClickHouse | 历史分析、报表、宽表扫描 | 在线交易决策和点写事务 |
| 只读投影 | 跨上下文页面/查询模型 | 绕过写入所有者修改事实 |

派生副本要回答：权威来源是谁、通过什么事件/CDC 同步、最大允许多旧、如何检测落后、怎样全量重建、删除/权限变更如何传播。

## 2. 数据请求链

![从业务用例到存储引擎的数据访问链](/architecture/data-access-runtime.svg)

1. 业务用例以领域语言调用 Repository/Query Port，不传任意表名或 SQL 片段。
2. 数据适配器选择读写数据源、构造参数化查询、执行 tenant/权限条件。
3. 连接池在明确预算内借出连接；事务边界仍由业务用例决定。
4. 数据库解析 SQL、选择执行计划、访问索引/数据页并处理锁与 WAL/binlog。
5. 结果映射为领域聚合或只读 Projection，不把 Persistence Entity 泄露到 API。
6. 指标记录池等待、查询耗时、扫描行、锁、错误和副本延迟。

一次“SQL 只用了 20 ms”不代表数据访问只耗时 20 ms：连接池排队、网络、结果传输、ORM 映射和事务等待都属于用户延迟。

## 3. 数据所有权

- 业务服务拥有自己的 Schema、迁移、写账户和数据质量。
- 其他服务通过 API、事件、CDC 投影或数据平台读取，禁止直接更新其表。
- 共享物理集群时也按服务分账户/Schema，最小授权，避免跨域 Join 成为永久契约。
- 管理脚本、修复工具和迁移任务走受审计身份，不复用应用超级账号。
- 删除、导出和保留策略覆盖全部派生副本和备份生命周期。

数据库是业务层实现事实的工具，不应反过来让“已有几张表”决定服务边界。

## 4. 存储选型方法

![从访问模式到存储选型的决策过程](/architecture/data-storage-selection.svg)

选型前写清：读写 Key、范围/排序/全文需求、QPS 与峰值、单条和总量、事务/约束、一致性、新鲜度、保留期、增长、RPO/RTO、数据驻留与团队运维能力。

先用能正确承载权威事实的最少技术。引入一种新存储意味着新增容量、备份、升级、权限、监控、故障和数据同步责任。Polyglot Persistence 是有证据地匹配访问模式，不是数据库品种越多越先进。

## 5. 正确性优先级

1. 业务不变量由领域行为和数据库约束共同保护。
2. 本地事务保证必须原子提交的最小事实。
3. 并发通过唯一约束、版本、条件更新或锁得到明确胜负。
4. 派生副本允许的陈旧度由业务契约定义，关键决策回权威来源。
5. 备份恢复、对账和重建能力处理长尾故障。

缓存命中率、查询 P99 和存储成本很重要，但不能以丢失事实、跨租户或静默不一致为代价。

## 6. 数据安全基线

- tenant 从可信上下文进入每个查询、唯一约束、缓存 Key 和对象路径。
- 应用账户不拥有 DDL、跨 Schema 和任意导出权限。
- TLS 保护传输，存储/备份由 KMS 加密，高敏字段按需信封加密。
- 参数化查询、防注入、输出字段白名单和查询资源上限同时存在。
- 日志、慢查询样本、Trace 和数据库审计不记录密码、Token 和不必要个人数据。
- 生产数据不直接复制到开发测试环境。

## 8. 最小上线基线

- 每个事实有唯一写入者，所有派生数据有同步、延迟和重建方案。
- 每条核心查询有数据量假设、索引/执行计划和结果上限。
- 事务边界短小，并发规则由数据库原子机制最终保证。
- 连接池总预算按数据库能力反推，应用扩容不会耗尽数据库。
- 缓存/副本失败能受控回源，不造成雪崩、串租户或关键陈旧决策。
- 备份经过隔离恢复验证，RPO/RTO 有测量结果而不是口号。
- Schema 变化支持新旧应用共存、回填、验证、回滚和最终清理。
