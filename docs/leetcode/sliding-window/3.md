# 3. 无重复字符的最长子串

> LC 3 · Longest Substring Without Repeating Characters · 滑动窗口 + HashMap

## 题目

给定一个字符串 `s`，请你找出其中不含有重复字符的 **最长子串** 的长度。

**示例 1：**
```
输入: s = "abcabcbb"
输出: 3
解释: 因为无重复字符的最长子串是 "abc"，所以其长度为 3。
```

**示例 2：**
```
输入: s = "bbbbb"
输出: 1
解释: 因为无重复字符的最长子串是 "b"，所以其长度为 1。
```

**示例 3：**
```
输入: s = "pwwkew"
输出: 3
解释: 因为无重复字符的最长子串是 "wke"，所以其长度为 3。
     请注意，"pwke" 是一个子序列，不是子串。
```

**约束：** `0 <= s.length <= 5 * 10^4`，`s` 由英文字母、数字、符号和空格组成。

核心规则：**HashMap 记录每个字符最近出现的位置。右指针 `right` 逐个探测，当 `map.containsKey(c)` 且 `map.get(c) >= left` 时，将左指针跳到 `map.get(c) + 1`，实现窗口收缩。** 无论字符集多大（Unicode 也能用），HashMap 都能正确处理。

---

## 解题思路 — 为什么用 HashMap 而不是 int[128]

拿到这道题，"子串 + 不重复" → 滑动窗口。关键问题是：**如何快速判断右指针指向的字符是否已经在窗口内？**

第一个反应是用 `int[128]` 数组——利用 ASCII 码做索引，存取 O(1)，很快。但仔细想想，题目约束说字符包括"符号和空格"，实际的 ASCII 范围是 0-127，128 长度的数组确实够用。**但在面试中，面试官会追问"如果不是 ASCII 呢？如果是 Unicode 呢？如果是中日韩文字呢？"**

`int[128]` 面对 Unicode 完全不够用。而 `HashMap<Character, Integer>` 天然支持所有字符类型，存取也是平均 O(1)。这是更通用、更"面试正确"的解法。

**为什么不是 int[128]？**
- 局限性：只能处理 ASCII（0-127），Unicode 字符会数组越界
- 面试风险：面试官有极大可能追问"如果字符集不止 ASCII 怎么办？"

**为什么用 HashMap？**
- 通用性：支持任何字符（字母、数字、符号、空格、Unicode、中文、emoji 等）
- 复杂度相同：HashMap 的 get/put 平均 O(1)，和数组一样
- 可扩展：面试官不会追问"如果字符集更大怎么办"

暴力法 O(n³) → 滑动窗口 + HashMap O(n)。

## 代码推演 — ACM 模式，逐步构建

### 第一步：搭框架

读入一行字符串。ACM 模式下输入就一行 `s`。

```java
import java.util.*;

public class Main {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        String s = sc.nextLine();
        sc.close();
    }
}
```

### 第二步：空方法签名

方法接收 `String s`，返回 `int`（最长长度）。

```java
    public static int lengthOfLongestSubstring(String s) {
        // TODO
    }
```

### 第三步：初始化 HashMap + 指针

```java
        Map<Character, Integer> map = new HashMap<>();
        int left = 0;
        int maxLen = 0;
```

这里最关键的一点：**left 始终指向窗口左边界（包含），right 是循环变量指向窗口右边界（包含）。窗口范围是 `[left, right]`。**

### 第四步：遍历 + HashMap 查冲突

```java
        for (int right = 0; right < s.length(); right++) {
            char c = s.charAt(right);
```

现在判断 `c` 是否已经在当前窗口中。怎么判断？看 `map` 里有没有这个 key：

- 如果有：看它的 value（上次出现的位置）是否 `>= left`——如果是，说明这次出现就在窗口内，**冲突了！**
- 冲突时：L 直接跳到 `map.get(c) + 1`（重复字符的下一个位置）

不对，等等——如果 `map.get(c) < left` 呢？比如 `"tmmzuxt"`，当处理到最后一个 `'t'` 时，`map.get('t') = 0`，而 `left` 已经在处理中间的重复 `'m'` 时移动到了 2。此时 `0 < 2`，说明上次出现的 `'t'` 已经在窗口外面了，不算冲突！

所以判断逻辑是：`if (map.containsKey(c) && map.get(c) >= left)` 才触发收缩。

不，还可以更简洁。就算不删掉旧 key，HashMap 会保留历史位置。只要判断 `map.get(c) >= left` 就行。但需要先确保 map 里有这个 key——否则 `map.get(c)` 可能返回 null。

```java
            if (map.containsKey(c) && map.get(c) >= left) {
                left = map.get(c) + 1;  // 跳到冲突字符的下一个位置
            }
```

然后更新当前位置到 map，计算窗口长度：

```java
            map.put(c, right);
            maxLen = Math.max(maxLen, right - left + 1);
        }
        return maxLen;
```

这里的 `map.put(c, right)` 有一个关键作用：如果字符 `c` 之前出现过，put 会覆盖掉旧位置。这样一来，下次再遇到 `c` 时，map 拿到的是最新的位置，判断冲突更精确。

### 完整代码

```java
import java.util.*;

public class Main {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        String s = sc.nextLine();
        sc.close();

        int result = lengthOfLongestSubstring(s);
        System.out.println(result);
    }

    public static int lengthOfLongestSubstring(String s) {
        Map<Character, Integer> map = new HashMap<>();
        int left = 0;
        int maxLen = 0;

        for (int right = 0; right < s.length(); right++) {
            char c = s.charAt(right);

            // 如果 c 在 map 中，且其位置在窗口内 → 冲突
            if (map.containsKey(c) && map.get(c) >= left) {
                left = map.get(c) + 1;  // L 跳到冲突字符的下一个位置
            }

            map.put(c, right);                        // 更新位置（覆盖旧值）
            maxLen = Math.max(maxLen, right - left + 1);
        }

        return maxLen;
    }
}
```

---

### 边界验证

- **空串 `""`**：for 不执行，返回 0。正确。
- **单字符 `"a"`**：map 无冲突，maxLen=1。返回 1。正确。
- **全重复 `"bbbbb"`**：每次 map.containsKey('b') 且 index≥0，left 逐跳到 1,2,3,4，maxLen 始终 1。正确。
- **无重复 `"abcdef"`**：map 无冲突，窗口持续扩大，maxLen=6。正确。
- **Unicode 字符**：如 `"你好世界你好"`，HashMap 对字符类型无限制，'你' 和 '好' 各自作为 key 存储位置，逻辑完全有效。

## 一句话总结

**滑动窗口 + HashMap 记录位置：右指针遍历，遇到重复且位置在窗口内则左指针跳到 `map.get(c) + 1`，无论字符集多大都能正确判断冲突。**
